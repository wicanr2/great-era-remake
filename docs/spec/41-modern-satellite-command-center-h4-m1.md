# SPEC-41：Modern 軍事衛星作戰室 H4／M1

> **2026-08-12 勘誤：** 使用者後續以 A2 原型確認明亮土黃／朱紅的民國風主視覺，深藍黑
> 衛星作戰室已由 `SPEC-43` 取代。本文保留歷史決策、1280×720 幾何與既有 action 證據，
> 不再作為目前 Modern 色彩、字級、按鈕裝飾或司令官肖像的驗收基準。

> **狀態：READY（1280×720 Modern 主地圖、共用外殼與人物檔案的視覺／幾何切片；不含新規則）**  
> 日期：2026-08-12  
> 決定依據：使用者已確認「全域指揮室」根架構，並在可丟棄原型後選定「軍事衛星作戰室」視覺語言。

## 1. 目標與非目標

本規格把高解析 Modern 從 H3 的淺色儀表板，改為深色、低飽和的軍事衛星作戰室。它必須讓地圖、
選定省份的軍情檢視、可執行指令與新聞／史事入口有明確層級，但不得新增任務、地圖資料、規則、
成本、存檔欄位、假按鈕或未證實的軍事情資。

它是 remake 的呈現差異，不是原版還原斷言。`retro` 640×350、原版字模、規則與 `.DT1`／`.DT2`
寫回都不在本切片改動。

M1 只接既有的 `screenMap` 正常玩家路徑，以及所有高解析頁可共用的衛星外殼與人物檔案色彩。
戰鬥 HUD、政略流程與設定頁使用相同主題色和導覽軌，但其個別資訊架構後續各自驗收；不得以 M1
主地圖截圖宣稱所有 Modern 畫面已完成。

## 2. 已確認資料與輸入邊界

| 類別 | 證據等級 | 約束 |
|---|---|---|
| 1280×720、16:9、橫向 Modern 設計畫布 | confirmed-user-decision | 由 `layout.ModernDesignSurface` 維持；Android 仍以同一設計座標反算觸控 |
| 現有 `OpenCommands`／`OpenNarrative` | confirmed-code | 只能重排兩者的命中矩形；不可創造新的 `Action` |
| 14×14 六角格與 3/2 顯示比例 | confirmed-code | `MapCellRect` 的 48×36 格及奇數欄 +18 px 位移不變 |
| `PanelData`、`PeopleDB`、`PortraitCatalog` | confirmed-code | 只讀；不把照片、來源或 UI 狀態寫回遊戲資料 |
| 衛星掃描格線、訊號條、幾何符號 | remake-visual | 純 Go 繪製，僅提供閱讀節奏；不是原版資料或可操作功能 |

所有玩家可見文字必須由既有 wording／資料呼叫端提供。導覽軌在 M1 只放幾何狀態符號；實際可點的
「指令」與「新聞／史事」仍同時保留有文字的底部操作列，避免以未語系化的圖示取代語意。

## 3. H4 主地圖幾何

安全區仍是四側 24 px。以下座標為設計座標，renderer 與 pointer 必須共用同一個 `ModernMapLayout`：

| 區塊 | 矩形 | 作用 |
|---|---:|---|
| 導覽／狀態軌 | `(24,24,72,672)` | 常駐背景、目前地圖標記，以及兩個既有入口的輔助命中區 |
| 工作區頂列 | `(112,24,1144,58)` | 選定省份、狀態、日期；不得塞入新快捷規則 |
| 衛星地圖窗 | `(112,98,704,598)` | 地圖框與掃描底紋；14×14 地圖固定置中為 `(128,136,672,522)` |
| 省份軍情檢視器 | `(832,98,424,360)` | 司令、省長、六項既有摘要與後勤讀值 |
| 操作／事件列 | `(832,474,424,222)` | 唯一的文字化 `OpenCommands`／`OpenNarrative` 按鈕與非互動訊號條 |

`CommandRailButton` 與 `NarrativeRailButton` 是各自底部按鈕的第二個命中入口，派送完全相同的
既有 action；新聞不存在時不得登錄或繪製可點的新聞入口。地圖目前沒有已證實的選省 action，
所以衛星地圖窗不得偷偷設成可點選省份。

## 4. 視覺契約

1. `Paper` 是深藍黑基底，`Panel` 是藍灰控制面，`Ink` 是冷白資訊文字；青藍表示可讀取的
   資訊／連線，琥珀表示焦點，橘紅只表示既有主要指令或危險強調。
2. 地圖圖塊、鐵路、部隊 token 與 HUD 圖示仍由完整 `theme.Modern` provider 一次建立；切換時
   原子交換整組，不得出現新外殼配舊調色盤的半載入狀態。
3. 掃描格線、角標、訊號列與導覽符號只能使用純 Go 幾何和現有 palette，不引入原版 `.TPC`、
   第三方衛星照片、AI 生成地圖或未清權背景圖。
4. 人物檔案沿用 `SPEC-40` 的實圖／中性檔案卡失敗即關閉規則；外殼改為衛星作戰室色系，但照片
   欄位、短署名、頁數與 `PeopleDB` 不因有無圖片重新排版。
5. 除既有兩個 action 的輔助入口外，導覽軌和訊號條皆不可點；不以「看似可以操作」的元件誤導玩家。

## 5. 實作步驟

1. 擴充 `ModernMapLayout`、`ModernPageLayout` 與 `ModernBattleLayout`，明確提供導覽軌與 M1
   操作矩形；所有矩形在 layout 測試驗證不重疊、最小 48×48 命中區與六角格不變。
2. 將 `theme.Modern.Style` 和程式化 palette 換成衛星作戰室的完整色組，保留 `ModeModern`、
   資產索引數量、透明索引與 unit 方向索引。
3. 將主地圖 renderer 改為衛星地圖窗＋軍情檢視器＋操作／事件列；只從現有 `ModernMapSurfaceData`
   取資料。pointer 為兩個已存在 action 加入導覽軌與底部按鈕的同義目標。
4. 共用頁框、戰鬥 HUD 與人物檔案使用同一深色外殼；不改任何 screen transition 或輸入 action。
5. 以 `cmd/screenshot` 的正常資料路徑產生暫存截圖，人工確認不是 H3 放大版；僅在接受最終設計後
   才更新 `docs/images/` 或重錄推廣片。

## 6. 驗收與停止條件

1. `NewModernMapLayout` 驗證軌、頂列、地圖窗、檢視器、操作列與兩組同義 action 命中區均不重疊；
   地圖仍為 672×522，格仍為 48×36、奇數欄仍下移 18。
2. renderer 在 1280×720 有非透明的深色背景、可畫主題圖塊、沒有要求原版字型；錯誤畫布／retro
   style 仍失敗即關閉。
3. 滑鼠／觸控的導覽軌與底部按鈕各自派送相同既有 action；沒有新增 `Action`、沒有命中地圖即改狀態。
4. 人物有照片、無照片與 hash／載入失敗仍走 `SPEC-40` 的固定欄與後備畫面。
5. 針對受影響 package 的 Docker＋Xvfb 測試、`tools/check_no_cgo.sh`、資產拒絕掃描和
   `git diff --check` 通過；全量遊戲長跑不是此 M1 的前置條件。

未完成項目：H4 的各流程頁細節、Android 真機觸控密度、日文長文人工排版、Modern Ogg、真實遊玩
推廣片、桌面／Android 發行包。這些都不可因 M1 視覺接線完成而宣稱完成。

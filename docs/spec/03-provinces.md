# SPEC-03 省份資料表 — `TOWN(N).DAT` 與 `SAVE(N).DT1` 前段

狀態：**READY**
輸入檔：`TOWN(1).DAT` / `TOWN(2).DAT` / `TOWN(3).DAT`（各 1,443 B）、
`SAVE(1).DT1` / `SAVE(2).DT1`（各 14,683 B）
驗證方式：DOSBox 實機截圖（`docs/playtest/02`）逐欄比對 + 全 39 省歷史交叉驗證
日期：2026-08-01

---

## 1. 結構

39 筆記錄，每筆 **37 bytes**，順序就是省編號（1-based，與 `3.15` 的省名表同序）。

兩個檔案裝的是同一個結構，只差起點：

| 檔案 | 陣列起點 | 內容 |
|---|---:|---|
| `TOWN(N).DAT` | 0 | 第 N 期的**初始**省份狀態，整檔 = 39 × 37 = 1,443 B |
| `SAVE(N).DT1` | **4** | 存檔當下的省份狀態，佔 offset 4..1446 |

`.DT1` 的前 4 bytes 是檔頭：

```
+0  u16  年（民國）      SAVE(1)/(2) 都是 15
+2  u8   月              都是 7
+3  u8   未解            都是 1（疑似期別或玩家勢力，未驗）
```

實機載入 `SAVE(1)` 後畫面顯示「民國 15 年 8 月」，存檔存的是 **7 月**——
載入時會推進一個月，或存檔點在月結算之前。未追。

### [雷] 相位差 4 bytes

`.DT1` 的省份記錄比 `TOWN` 晚 4 bytes。直接用 `k × 37` 切 `.DT1` 會拿到
**橫跨兩筆記錄的碎片**，而且看起來還很像一筆記錄（因為每筆尾端固定是
`19 19 19 19`，切錯了照樣對齊得漂亮）。判斷切點對不對的方法是拿實機數值驗，
不是看 hex 排得整不整齊。

## 2. 記錄佈局（37 B）

偏移是相對於記錄起點。

| 偏移 | 型別 | 欄位 | 依據 |
|---:|---|---|---|
| +0 | u16 | 黃金 | 實機湖北 4200 |
| +2 | u16 | 糧食 | 實機湖北 18050 |
| +4 | u16 | 彈藥 | 實機湖北 8787 |
| +6 | u16 | **煤礦** | 實機湖北 13000 |
| +8 | u16 | **燃料** | 實機湖北 12048 |
| +10 | u16 | 鐵礦 | 實機湖北 14031 |
| +12 | u32 | 人口（人）| 湖北 18,250,000 → 畫面「1825 萬」|
| +16 | u8 | 城市數 | 實機湖北 5 |
| +17 | u8 | 地價 | 實機湖北 22 |
| +18 | u8 | 兵工廠數 | 實機湖北 3 |
| +19 | u8 | 人民忠誠度（0–100）| 實機湖北 79 |
| +20 | u16 | **司令**（將領 ID，1-based；0 = 無主）| 湖北 58 = 吳佩孚 |
| +22 | 8×u8 | 鄰省列表 | 與 `WARPOS.DAT` 幾何鄰接 28/39 完全一致 |
| +30 | u16 | **省長**（將領 ID）| 實機湖北顯示「省長 吳佩孚」|
| +32 | u8 | **位元旗標** | 見 §2b |
| +33 | 4×u8 | 未解，恆為 `25 25 25 25` | 三份檔案全 39 省都一樣 |

### [雷] 資料順序 ≠ 畫面順序

畫面依序印「燃料、煤礦」，資料是「煤礦、燃料」。UI 照畫面排，解碼照資料讀。

### 2b. `+32` 是位元旗標

初始檔（`TOWN(N).DAT`）全 39 省都是 0，存檔裡才會設。

| 位元 | 觀察 | 等級 |
|---|---|---|
| bit 2 (`0x04`) | `SAVE(1)` 25 省、`SAVE(2)` 4 省，**無主的省一律沒設** | **假說：本月已徵過稅** |
| bit 6 (`0x40`) | 兩份存檔都沒出現 | **confirmed：這個省正在打仗** |
| 其他位元 | 沒觀察到 | |

#### bit 2 = 已徵過稅（假說）

`4.15` 的詞條 42 是「**已徵過稅**」，而徵稅每月限一次正好需要一個旗標。
25 vs 4 的差距符合「回合中後段 vs 初期」，無主的省不會徵稅所以一律沒設。

⚠️ **沒有實機驗證。** 要確認就實機徵稅一次、存檔、比對這個 bit。

#### bit 6 = 正在打仗

兩處證據合起來：

- `sub_15925` 收集候選鄰省時**跳過**設了它的省——不能挑正在打的當目標
- `sub_54DAC`（戰後結算）用 `&= 0xBF` **清除**它

所以它是戰鬥期間的暫時旗標，打完就清掉。這也解釋了為什麼兩份存檔裡
都沒有出現——存檔時不在戰鬥中。詳見 `docs/mechanics/30-combat.md` §3f。

### 兵力與將領數不在這裡

實機畫面上的「兵力 97500」與「將領數 15」**不是這張表的欄位**。
兵力是該省將領的兵力加總（`docs/spec/02-generals.md`，實機零誤差驗過），
將領數同理是數出來的。這張表只存省份本身的狀態。

## 3. 將領 ID：1-based，指向 `MAN{期}15` 的名表

`司令` / `省長` 存的是將領編號，**1-based**，0 表示無主。
`MAN115` 是第一期（北伐）的 274 人名表，`MAN215` / `MAN315` 各 106 人。

`TOWN(1).DAT` 的司令欄位解出來就是 1926 年的割據圖：

| ID | 將領 | 轄省 |
|---:|---|---|
| 166 | 張作霖 | 東北九省 + 河北 + 山東 |
| 98 | 孫傳芳 | 江蘇、安徽、浙江、福建、江西 |
| 58 | 吳佩孚 | 湖北、河南 |
| 1 | 蔣中正 | 廣東、廣西 |
| 157 | 劉湘 | 四川 |
| 156 | 唐繼堯 | 雲南 |
| 146 | 袁祖銘 | 貴州 |
| 141 | 趙恆惕 | 湖南 |
| 4 | 閰錫山 | 山西 |
| 3 | 馮玉祥 | 陝西 |

孫傳芳那五個省一個不多一個不少，正是史上的「五省聯軍」；兩廣歸蔣中正，
正是北伐的出發地。**這比任何內部一致性檢查都硬**——如果欄位解錯，
不可能剛好排出一張對的歷史地圖。

存檔裡兩個欄位會分化：司令仍是勢力領袖，省長換成實際駐守的人。
`SAVE(1).DT1` 解出遼寧省長張學良、山東省長張宗昌、江西省長盧香亭、
河北省長李景林（`SAVE(2)`），全部符合史實職務。湖南已易主為
司令蔣中正／省長何應欽——民國 15 年 8 月正是北伐軍攻下長沙的時間點。

## 4. 鄰省列表（+22，8 bytes）

存 1-based 省編號，`0` 是填充，**`255` 表示海洋或境外邊界**。
帶 255 的省是遼寧、安東、河北、山東、江蘇、浙江、福建、廣東、臺灣、緬甸
——全部沿海或臨國境。最大鄰省數是 7，欄位有 8 格。

與 `WARPOS.DAT` 的幾何鄰接（`docs/spec/01`）比對，兩邊各自濾掉哨兵值
（這裡的 255、`WARPOS` 的 40）之後：**36/39 完全一致**。

剩下的 3 筆差異是同一類：福建缺臺灣、廣東缺海南島、雲南缺緬甸——
**全是隔海／隔境的那一段**，而反向（臺灣→福建、緬甸→雲南）卻列著。

### 程式自己會跳過 0 與 255 — **confirmed**

四支函式在遍歷鄰省表時，對每一格都做兩個檢查：

```asm
cmp     byte ptr [di-6220h], 0      ; 填充
cmp     byte ptr [di-6220h], 0FFh   ; 海洋／境外
```

（`sub_1398D`、`sub_13F4E`、`sub_14860`、`sub_150FC`，各自屬於不同的
指令處理鏈。）基址算出來正好落在記錄的 `+22` 起，配合索引掃完 8 格。

**`0xFF` 是程式明確處理的哨兵值，不是資料雜訊。**

⚠️ 兩個哨兵值不能互相代換。255 出現在 10 個沿海／境外省，`WARPOS` 的 40
只出現在其中 5 個。兩者都表示「非省份區域」是合理的推測，**但沒有驗證過**。

第二類看起來像「不可直接進兵」的單向限制，但**這是假說**——沒有實測驗過
從福建能不能打臺灣。在驗證之前不要拿這張表當進兵合法性的判準；
`+22` 的用途也可能只是「顯示相鄰省份」而非「可攻擊目標」。

## 5. 三份 `TOWN` 檔的關係

`TOWN(1)` / `TOWN(2)` / `TOWN(3)` 對應遊戲的三個時期（北伐、抗戰前期、抗日後期）。
三份的多數省份資源完全相同——河南 `6633/14055/12037/14029`、
湖北 `8787/13000/12048/14031` 三份一模一樣，只有嫩江省不同
（`TOWN(1)` 黃金 2616，`TOWN(2)/(3)` 是 30000）。

**這代表三份不是各自獨立編的初始資料，而是從同一份改出來的。**
差異在哪還沒逐欄位比完，別假設「第二期＝抗戰的資源配置」。

## 6. 寫回

依 `CLAUDE.md` §9：從原始 bytes 出發，只蓋已解欄位。
`+32` 與 `+33..36` 未解，寫回時原封不動。驗收是 byte-for-byte round-trip。

## 7. 未解

- `+32` 的 bit 2 是不是「已徵過稅」（假說待實機驗證）
- `+33..36` 恆為 `25 25 25 25`——三份檔案 39 省全同，可能是常數或未使用
- `.DT1` 檔頭 `+3` 的 `1`
- `.DT1` offset 1447 之後（`17 1a 17 14` + 大片 0，兩份存檔差異大）
- 鄰省表的 255 與 `WARPOS` 的 40 是不是同一個意思
- 三份 `TOWN` 的完整差異

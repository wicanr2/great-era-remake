# SPEC-21：戰鬥立即撤退輸入外殼 M1

狀態：**READY**（2026-08-10）

本規格只接上已由正常 DOSBox 玩家路徑閉合的「立即撤退」輸入，不替尚未解出的
候選省份規則、戰後結算或 `.DT2` 寫回補猜。鍵盤、桌面滑鼠與 Android 單指觸控
一律先轉成 `internal/ui/actions.Action`，再走同一個 `cmd/dsds` 狀態機。

## 1. 證據邊界

| 觀察 | 證據等級 | 出處 |
|---|---|---|
| 戰鬥主選單 `3` 進入撤退分支 `sub_4D3F6 → sub_4C2EA` | confirmed | `docs/mechanics/30-combat.md` §3 |
| 陝西省（18）←河南省（19）樣本列出 `19,26,14,17` | confirmed | `docs/re/05-mem-war-record.md` §5、`docs/playtest/16-dt2-live-battle-snapshot.md` §4b |
| 輸入 `19` + Return 回到政略地圖 | confirmed | 同上 DOSBox 正常玩家時間線 |
| 立即撤退前後 `SAVE(1).DT2`、`SAVE(2).DT2`、`MEM_WAR.DAT` 雜湊不變 | confirmed | 同上 |
| 其他交戰組合的候選來源、排序與撤退後戰場狀態 | unknown | 尚無第二份正常撤退樣本 |

因此實作只注入上述一組已證實清單；其他交戰組合按下撤退時保持在主選單，
並不把鄰接、勢力或來源省假說升格成規則。

## 2. 輸入契約

1. 在已證實樣本按 `3` 後，右側顯示撤退候選與 3×4 數字鍵盤。
2. `1..9`、`0` 追加省份編號；`Backspace`／刪除鍵刪掉最後一位；`Enter`／送出鍵提交。
3. 輸入上限為 39；溢位或大於 39 的追加失敗即保持原值。
4. 只有 `19`、`26`、`14`、`17` 會提交；其他值留在撤退輸入層，不改世界狀態。
5. 合法提交只把目前政略畫面切到目標省並清除戰鬥副本；不呼叫戰後 `.DT2`／
   `MEM_WAR.DAT` 寫回入口，符合「尚未攻擊或結算」的原版樣本。
6. ESC 從撤退輸入層回到戰鬥主選單，不離開遊戲。

## 3. 裝置無關版面

- `internal/ui/layout.BattleRetreatKeypadButton` 是 renderer 與指標命中唯一的座標來源。
- 12 個按鍵各為 56×48 邏輯像素，索引依序為 `1..9、0、刪除、送出`；符合既有
  觸控命中尺寸契約。
- 面板保留原版省名與戰場，右欄覆蓋 remake 選單／控制鍵；候選號碼使用原版
  `2.15`「撤退／何省」字模與既有數字繪製器。
- 點擊只產生 `actions.Digit*`、`actions.DeleteDigit` 或 `actions.Submit`，不另造
  一套滑鼠規則。拖曳／畫面切換取消仍由共用 pointer tracker 處理。

## 4. 不在本規格

- 由地圖、勢力或鄰接自動推導所有撤退候選。
- 移動、攻擊六方式、駐軍、查閱、戰鬥勝負與補給結算。
- 有傷亡／打滿回合後的 `sub_3964E` 寫回、`.DT2`／`MEM_WAR.DAT` 同步。
- Android 封裝、旋轉／背景恢復與實機觸控驗證。

## 5. 驗收

- `cmd/dsds` 測試覆蓋輸入上限、已證實清單、未知交戰失敗即關閉與 pointer action 映射。
- `internal/ui/layout` 測試護欄 3×4 幾何、48 像素命中區與不重疊。
- `internal/ui/render` 測試確認候選與 12 個按鍵確實繪製；既有戰鬥面板逐像素標籤
  測試保持通過。

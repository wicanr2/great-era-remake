# 規格 12：外交玩家介面 M1（外援／償還外債）

狀態：**READY（M1 窄切片）**  
日期：2026-08-10

本規格把指令 9 已有規則與帳本接到正常玩家路徑的兩個窄切片：

1. `請求外援`：從外交選單直接執行一次援助判定。
2. `償還外債`：輸入金額、扣省份黃金、更新信用度與 `.DT1` 外債帳本。

它不是外交全流程完成宣告；Android 實機封裝仍保留在缺口清單。
信用度零貸款 gate、貸款拒絕成本與外援結果成本分別由 SPEC-15、SPEC-16、
SPEC-17 管理。

## 1. 已有證據與邊界

規則來源是 `docs/mechanics/50-diplomacy.md` 與 `internal/game/diplomacy.go`：

- 外援先擲 `Random(10)`；一般情況 `roll <= 6` 走拒絕文字，`roll >= 7` 才進入
  核准分支；司令 166 在民國 17 年 2–6 月另有特殊核准覆寫。
- 核准後四項資源各自使用 `Random(60000 - 目前值) ÷ divisor`；黃金額外夾到
  `6000`，糧食／彈藥／燃料不以 6000 夾值。
- 民國 17 年 2–6 月、司令 166（張作霖）是已證實的特殊核准覆寫；歷史動機未定名。
- 償還金額不可為零、不可超過該外交槽位外債，且省份黃金必須足夠；每 500 黃金
  回補 1 點信用度，上限 100，同步扣除 32-bit 外債。
- `.DT1` 只由 `WriteDiplomacyLedger` 寫入已證實的區塊 8／9，其他 bytes 原樣保留。

第一期呼叫端現在已接上 `AidDonorCode`：它保留原版 `.DT1` 區塊 7 的 1-based
勢力代碼與 `Random(10)` 同一顆骰；第二／三期仍在原版分支中覆成代碼 99。
代碼與國家名稱的對應仍是未閉合假說，規則層只傳遞數值，不把 99／100／142 命名成
國家。若新局沒有 `.DT1` 區塊 7，UI 傳 0 走原版 default 分支。

## 2. 輸入與畫面契約

- `外交 → 請求外援` 不另造數字頁；選取後立即執行一次判定，核准／拒絕結果以現有
  訊息佇列顯示，完成後回到政略畫面。
- `外交 → 償還外債` 進入 `screenRepayAmount`。數字鍵、滑鼠與觸控共用既有數字鍵盤
  命中區；送出 0、超過外債或黃金不足時不改任何狀態，保留在輸入頁讓玩家修正。
- 償還成功才呼叫 `CommandBudget.Spend`；外援只要進入第一次援助亂數，核准、隨機拒絕
  與特殊核准都消耗指令數。`AidResult.CommandCompleted` 與接線契約詳見 SPEC-17。
- 所有玩家可見用語放在 `translations/zh-Hant/wording.json` 的外交鍵；原典／現代白話
  只切換文字，不切換規則、亂數或存檔格式。

## 3. 驗收契約

規則層：

- 固定亂數種子下，外援結果與 `AIWorld.RequestAid` 相同，包含特殊核准、黃金夾值及四項
  資源入帳。
- 償還成功後，省份黃金、`DiplomacyLedger.Credit`、`Debt` 三者一次提交；失敗時
  三者 byte／數值均不變。

介面層：

- `screenDiplomacy` 三列仍是 1／2／3；第 1 列貸款 M0 不改行為。
- `screenRepayAmount` 公告 12 個共用數字鍵盤目標；ESC 回到外交選單。
- 外援／償還成功後回到 `screenCommand`，不需要額外裝置分支。

驗證使用 Docker 中的既有 Go image，執行外交規則、`cmd/dsds` pointer／session、
renderer 與 i18n 測試；不宣稱完整原版流程或完整三平台實機驗收。

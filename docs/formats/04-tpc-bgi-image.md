# `.TPC` / `.RGB` / `NEWSDATA.DAT` — BGI 16 色圖像

> 狀態：**confirmed**（`.TPC` + `.RGB` 逐像素 round-trip 通過原版實機畫面，93,615 像素零差異）
> 工具：`tools/bgi.py`
> 日期：2026-08-01

---

## 1. `.TPC` = BGI `getimage` 緩衝區

```
+0  u16  width  - 1
+2  u16  height - 1
+4  像素資料（4 個 bit-plane）
[+20 bytes 選配：'palt' + 16 色 EGA 調色盤暫存器值]
```

大小公式 `4 + ceil(w/8) × h × 4`，CLAUDE.md §3.3 已用它驗過。

### [雷] plane 是逐列交錯，不是四個完整 plane 依序

```
列0: plane0 plane1 plane2 plane3     每段 rowBytes = ceil(w/8)
列1: plane0 plane1 plane2 plane3
```

**兩種佈局算出來的檔案大小完全一樣**，所以「大小公式驗算過了」不代表佈局對。
猜成「四個完整 plane 依序」解出來是雜訊——實測 `CHOOSE2.TPC` 會變成 15 色
且分布平均；正確解法是 5 色、最大宗佔 79%，與 DOSBox 截圖量到的色數一致。

### [雷] plane 0 是最高位元

```
像素值 = plane0<<3 | plane1<<2 | plane2<<1 | plane3
```

用一般的 `plane3<<3|…|plane0`，**圖形完全正確、色數也對**，只有顏色索引被
4-bit 反轉（2↔4、3↔12、7↔14），肉眼是「圖對但配色錯」。
這個錯只有拿實機畫面對照才抓得到。

### `+20` 差額 = 內嵌調色盤

CLAUDE.md §3.3 記的「差額固定 +20 的那批」已解：尾端是 ASCII `palt` + 16 bytes
EGA 調色盤暫存器值。全 44 個 `.TPC` 掃過，差額 20 的**全部**以 `palt` 開頭，零例外。

`palt` 的內容實測都是 EGA 預設 `00 01 02 03 04 05 14 07 38 39 3a 3b 3c 3d 3e 3f`，
**不是**指向 `.RGB` 行號的映射表。

### 差額巨大的是圖集

| 檔案 | 大小 | 首張 | 差額 |
|---|---:|---|---:|
| `AC.TPC` | 94,248 | 178×60 | 88,724 |
| `NEWTERR.TPC` | 8,976 | 32×24 | 8,588 |
| `RAIL.TPC` | 8,064 | 1×1 | 8,056 |
| `NEWICON.TPC` | 5,328 | 32×17 | 5,052 |

多張圖串接，解析方式是從 offset 0 讀 header、跳過該張、再讀下一張。
**分割規則尚未逐張驗證。**

## 2. `.RGB` 調色盤

純文字，16 行，每行一組 RGB。八個檔全部是 16 行、最大值 100。

### [雷] 是百分比（0-100），不是 6-bit DAC

轉 8-bit 的鏈**一定要經過 6-bit DAC**：

```
百分比 → DAC = round(pct × 63 / 100) → 8-bit = (dac<<2) | (dac>>4)

70% → 44 → 178     97% → 61 → 247     60% → 38 → 154     17% → 11 → 44
```

直接 `pct × 255 / 100` 會差 1–2（60% 算出 153，正確是 154），逐像素比對就過不了。
這與 `.GLB` 調色盤的 6→8 bit 規則是同一套（見 `02-glb-image-library.md`）。

檔名與用途對應：`CHOOSE.RGB` ↔ `CHOOSE*.TPC`、`HEAD1.RGB` ↔ `HEAD1.TPC`。

## 3. 驗證：逐像素 round-trip

用 `CHOOSE1.TPC`（395×237，載入畫面的圖框）對 DOSBox 實機畫面驗證。

**定位不依賴調色盤**：窮舉所有位置，檢查「同一個索引值的所有像素在截圖裡是否
都是同一種顏色，且不同索引不同色」。全畫面**只有 (90, 20) 通過**。

**逐像素比對**：`CHOOSE1.TPC` + `CHOOSE.RGB` @ (90,20) vs 實機
→ **相異 0 / 93,615**。

驗證鏈：plane 佈局 → 位元順序 → `.RGB` 百分比 → 6-bit DAC → 8-bit
→ 與原版實機畫面完全相同。

## 4. `NEWSDATA.DAT` = 17 條新聞橫幅

不是文字檔，是**17 個等長區塊**，每塊 1,752 bytes（29,784 / 1,752 = 17 整除）：

```
+0     BGI 圖像 215×16，1,732 bytes
+1732  'palt'
+1736  16 bytes EGA 調色盤
       共 1,752
```

內容是**預繪成點陣圖的新聞句子**：#0「調動軍隊至」、#9「爆發大規模示威遊行」。

這解答了「敘事文本在哪裡」——**遊戲的敘事文本是畫成圖的，不是字模序列**。
`CLAUDE.md` §5 的還原鏈對這批不適用；remake 要處理的是「把圖轉回文字」。

`#0`「調動軍隊至」後面接省名，推測是新聞模板 + 執行期填字，但**填字機制未驗證**。

### 未解：字型不是倚天 16×15

拿倚天字庫反查這 17 張圖，**17 張全部落空**（已排除索引 11 的裝飾點干擾、
試過所有合理的 x/y 對齊）。字形比倚天明體粗，字高 14。

可能是遊戲自製的標題字、加粗過的倚天字、或 24 點字縮小。**待查**，
在解決之前這 17 條新聞只能人工判讀。

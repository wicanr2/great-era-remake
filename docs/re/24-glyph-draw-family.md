## 1. 四支繪字函式，差別只在一次畫幾個字

四支對外的 `far` 函式都是薄包裝，各自往下轉兩層才到真正的像素迴圈：

| 對外 | 中層 | 像素迴圈 | 一次畫 | 堆疊緩衝 | 對應詞表槽寬 |
|---|---|---|---:|---:|---:|
| `sub_5D670` | `sub_5D837` | `sub_5D739` | 1 字 | `1Eh` = 30 | `1.15` |
| `sub_5D695` | `sub_5D9DA` | `sub_5D895` | 2 字 | `3Ch` = 60 | `2.15` |
| `sub_5D6BE` | `sub_5DB7D` | `sub_5DA38` | 3 字 | `5Ah` = 90 | `3.15`、`MAN*15` |
| `sub_5D710` | `sub_5DEEF` | `sub_5DD85` | 5 字 | `96h` = 150 | `FAN(N).15`、`JAPAN*.15`、`TN15.N` |

緩衝區大小 = 字數 × 30，正好是 `docs/formats/01` 量到的槽寬乘每字 30 byte。
**「一次畫幾個字」與「詞表的槽寬」是同一件事**——`CLAUDE.md` §3.5 推出來的
「每 `w` 個字模為一個詞條」在這裡拿到了程式碼側的印證。

像素迴圈三層（以 `sub_5DA38` 為例）：

```
外層 var_60 = 0 .. (字數-1)      逐字
中層 var_5C = 1 .. 0Fh           15 列
內層 var_5E = 0 .. 7             一列 8 bit
```

取樣：`[bp + 1Eh*字 + 2*(列-1) + 1]` 是左半 8 px，`+ 2*列` 是右半。
`and al, [di+2]` 的 `[di+2]` 是 `ds:2` 起的 8 格位元遮罩表（`80h`…`01h`）。

## 2. 每個像素畫兩次——是加粗，不是加寬

```
ax = x + bit + spacing*字            PUTPIXEL(ax,   y, color)
                                      PUTPIXEL(ax+1, y, color)
```

`x` 與 `x+1` 都畫，而相鄰的 bit 只差 1 px，所以筆畫互相重疊——
**這是水平加粗（bold），字的總寬仍是 17 px 而非 32 px。**
右半 8 bit 走 `+ 8` 的分支，兩半合起來 16 bit。

⚠️ 這一條容易讀反。若當成「2 倍寬」，remake 畫出來的字會是原版的兩倍，
而且逐像素 round-trip 一定過不了。

## 3. 參數

四支都是 `retf 0Ah` = 5 個 word 參數，Pascal 慣例（左至右壓棧）：

```pascal
procedure DrawWordN(font: pointer; x, y, index: word);
```

`font` 佔兩個 word（seg:ofs）。呼叫端長這樣：

```
push    word_6B994          ; font 的 segment
push    word_6B992          ; font 的 offset
mov     ax, 0CDh            ; x = 205
push    ax
mov     ax, 116h            ; y = 278
push    ax
mov     ax, 0A6h            ; index = 166
push    ax
call    sub_5D6BE
```

另有兩個全域參數不走堆疊：

| 全域 | 用途 |
|---|---|
| `word_6BC42` | 顏色。呼叫前設、呼叫後歸零，是常見的「臨時改色」用法 |
| `word_6BC44` | 字距（spacing）。1 字版 `sub_5D670` 不用它 |

## 4. 索引是 1-based `[confirmed]`

用年度結算 `sub_30003` 裡民國 17 年那一串驗的（細節見 `docs/re/25`）。
連續五個呼叫，x 座標遞增、y 固定 278：

| x | 函式 | 字數 | index | 0-based 解出 | **1-based 解出** |
|---:|---|---:|---:|---|---|
| 205 | `sub_5D6BE` | 3 | 166 | 〈亂碼〉 | **張作霖**（`MAN115`）|
| 265 | `sub_5D695` | 2 | 49 | 墾地 | **更改**（`2.15`）|
| 305 | `sub_5D695` | 2 | 77 | 士兵 | **番號**（`2.15`）|
| 345 | `sub_5D670` | 1 | 49 | ％ | **為**（`1.15`）|
| 365 | `sub_5D710` | 5 | 3 | 〈不通〉 | **安　國　軍**（`FAN(1).15`）|

1-based 讀出來是「**張作霖更改番號為安國軍**」。0-based 是「墾地士兵％」。
不是勉強通順的差別，是通與不通的差別。

x 座標同時驗到**字距 = 20**：`205 +3×20= 265 +2×20= 305 +2×20= 345 +1×20= 365`，
四段全中。字寬 17 + 間隔 3。

### 3 字與 5 字要人工挑檔

槽寬 3 有四個候選（`3.15`、`MAN115/215/315`）、槽寬 5 有五個。
工具全部列出來，靠語意判斷：

```
sub_3964E  3字 #56  3.15:持續到  MAN115:孫長勝  MAN215:王東原  MAN315:孫連仲
```

這一句上下文是「戰事」，所以取 `3.15:持續到`。**要挑檔這件事是真實的歧義，
不是工具的缺陷**——同一個索引在不同字模檔就是不同的字，得看呼叫端傳哪個 buffer。
把 `word_6B992` 這類 buffer 指標追回載入點可以自動化，列為未解。

## 6. 這對里程碑的意義

`CLAUDE.md` §5 的還原鏈四步：

1. 字模反查 Big5 —— 已完成（`docs/formats/01`，6,174 字模）
2. **索引來源 —— 本文件解決**（編譯進 `WAR.EXE` 的立即數）
3. 逐像素 round-trip —— 未做
4. 例外記帳 —— 進行中（95 個動態索引、3/5 字檔的歧義）

第 2 步原本假設索引在 `.DAT` 或 `.GLB` 裡（§5 的圖就是這樣畫的），**實際不在**。
UI 與事件文本的索引是常數，直接編在程式碼裡；資料檔裡的索引（將領姓名、省名）
才是跑起來才決定的那 95 個。

⚠️ **這不代表敘事文本全解了。** `NEWSDATA.DAT`（29,784 B）仍未解，
新聞事件那條線與這裡是不同機制，別把本文件的結論外推過去（`CLAUDE.md` §7 第 9 條）。

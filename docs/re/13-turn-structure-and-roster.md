# 電腦的一個回合：命令數、將領清單、遷都

輸入檔：`WAR.EXE`（375,568 B，未打包）
位址：IDA linear address
日期：2026-08-01

`docs/re/12` 結束在「電腦怎麼發動戰爭，未解」。往上追 `sub_15F3C`
的呼叫者，解出了電腦回合的整體結構，順帶收掉三個懸案。

## 1. 將領清單的順序：攻擊力降序 — confirmed

`docs/re/10` §7 把這一條列為「宣稱調動行為對齊原版之前必須驗」的頭一項。
填清單的是 `sub_13B44`：

```
清單[0] = 0
for id = 1 .. 將領總數（word_6BC4A）:
    if 將領[id].+4  != 當前省:      continue
    if 將領[id].+16 != 1:           continue     ; ← 是 == 1 不是 & 1
    if 將領[id].+14 != 我方勢力:     continue
    清單[0]++
    清單[清單[0]] = id

清空 清單[清單[0]+1 .. 將領總數]

for i = 1 .. 清單[0]-1:                          ; 排序
    for j = i+1 .. 清單[0]:
        if sub_5A0B9(清單[j]) > sub_5A0B9(清單[i]):  swap
```

`sub_5A0B9` 是攻擊力公式（`docs/re/08` §4）。交換條件是
「後面的比前面的大就換」→ **降序**。

### 這讓八個模式的語意浮現

| 模式 | 掃描範圍 | 實際挑到誰 |
|---|---|---|
| 0 | `1..count-1` | 除了**最弱的**全部調走 |
| 6 | 只有第一個 | 派出**最強的** |
| 2／3 | 尾端往前 | 從**最弱的**開始挑 |
| 4 | 後半段 | **較弱的那一半** |

**強的先派出去、弱的留守。** 這與電腦「分散不集中」的整體傾向
（`70-ai.md` §6j）是同一個設計取向。

⚠️ 篩選條件是 `+16 == 1` 而不是 `+16 & 1`。目前觀察到的 `+16`
只有 `{0, 1, 32}` 三個值，兩種寫法結果相同（`32 & 1 == 0`），
但出現別的值就會分歧。規則層照 `& 1` 寫，這裡記一筆。

## 2. 剩餘命令數確實存在——在 `-232h` — confirmed

`docs/re/10` §1 推翻過「`狀態[-22Eh]` 是剩餘命令數」。當時的結語是
「社群那條說法回到未證實」。**現在它證實了，只是格子找錯了。**

`sub_13D23`（一個省的回合初始化）：

```asm
mov     ax, ss:[di-22Eh]        ; 將領清單長度
cwd
mov     cx, 8
idiv    cx
inc     ax                      ; 將領數 ÷ 8 + 1
mov     ss:[di-232h], ax
```

而 `-232h` **會遞減**——這正是當初找不到、因而不敢下結論的那件事：

| 函式 | 做什麼 |
|---|---|
| `sub_1398D` | 遷都（§3），成功就 `dec` |
| `sub_174C9` | `sub_17ADA` 底下的決策（627 行）。⛔ **「只是遞減命令數」是嚴重不完整的描述**——它還扣四種資源、改省份司令，見 `docs/re/28` §3 |

`sub_1ACCC` 的主迴圈跑到它歸零才換下一個省：

```
loc_1AD5D:
    ...決策與執行...
    if 命令數 == 0 或 司令 == 0:  收尾並離開
    ...
    if 命令數 > 0 且 司令 != 0:  goto loc_1AD5D
```

> `CLAUDE.md` §1.5 的社群說法「**每個省份有命令數上限，用完換下一個
> 省份**」——**成立**，而且公式是算出來的：將領越多，能下的命令越多。
> 39 省最忙的一個在 SAVE(1) 有 4 個命令。

## 3. `-236h` = 該省兵力總和 — confirmed

同樣在 `sub_13D23`：

```asm
mov     al, ss:[di+0Ah]         ; 當前省
push    ax
call    sub_306CF               ; 該省可用將領的兵力總和（32-bit）
mov     ss:[di-236h], ax
mov     ss:[di-234h], dx
```

這解掉 `70-ai.md` §6h 那道門檻的最後一半：

```
狀態[-236h] ÷ 狀態[-22Eh] ≥ 10000
= 該省兵力總和 ÷ 將領數 ≥ 10,000
= **平均每個將領兵力 ≥ 半個滿員步兵師**
```

分子分母現在都是 confirmed。

## 4. `sub_1398D`：勢力領袖遷都 — confirmed

```
if 將領[我方領袖].+4 != 當前省:      return    ; 領袖不在這裡
if sub_5B7DC(當前省) == 0:           return    ; 這裡不是前線 → 不用搬
for k = 1..7:
    鄰 = 鄰省[k]，跳過 0／0FFh、已找到就跳
    if 省份[鄰].+20 != 我方勢力:      continue
    if 省份[鄰].+32 & 40h:            continue  ; 交戰中
    if sub_5B7DC(鄰) != 0:            continue  ; 目標必須是後方
    找到 = 鄰
if !找到:  return

if 清單長度 == 1:  狀態[-5] = 1
將領[我方領袖].+4 = 找到                        ; 領袖搬過去
省份[找到].+30 = 我方勢力
省份[找到].+20 = 我方勢力
狀態[-232h]--                                   ; 消耗一個命令
```

**領袖所在的省變成前線就往後方搬。** 這是「大本營」的概念，
而且它是**第一個被確認會消耗命令數**的行為。

`-6217h` = 省份記錄 base（`-6235h`）+ 0x1E = **`+30`**，
與 `+20`（司令）一起被寫成同一個值——`docs/spec/03` 標 `+30` 為省長，
所以遷都同時把省長也換成領袖本人。

## 6. 電腦的回合結構 `sub_1ACCC` — confirmed（骨架）

```
sub_13D23(狀態)                      ; 建清單、算命令數、算兵力總和
if 清單長度 == 0:  return
if !sub_5C7FE(司令):  sub_13DDC()

loc_1AD5D:                           ; ← 主迴圈
    ...內政（依 byte_6FE7E 分支：1／3／6／7／8／0Bh／0Ch）...
                                     ; ← **byte_6FE7E 是月份**，整段是
                                     ;   季節性內政，見 docs/re/32
    sub_19B89()
    sub_1398D()                      ; 遷都
    if 司令 == 0 或 命令數 == 0:  sub_13786(); return

    if 命令數 > 0 且 狀態[-6] == 0 且 !sub_197A9():
        sub_17ADA()                  ; ← 決策鏈 A（已解，見 docs/re/28）
    if 命令數 > 0 且 狀態[-6] == 0 且 !sub_197A9():
        sub_15F3C()                  ; ← 決策鏈 B（docs/re/12 解的那條）
    ...
    sub_1AC01()
    if 命令數 > 0 且 司令 != 0:  goto loc_1AD5D
    sub_13786()
```

### 兩個關鍵發現

1. **`sub_15F3C` 不是唯一的決策鏈。** `sub_17ADA` 排在它**前面**，
   而且 627 行的 `sub_174C9`（會消耗命令數）掛在它底下。
   **電腦的攻打最可能在這裡。**
2. `狀態[-6]` = `sub_5C7FE(司令)`（是否為十大勢力之一，`docs/re/06`）。
   兩條決策鏈都要求它 **== 0**——十大勢力的省不走這兩條鏈。
   ⚠️ 這讀起來很怪（主要軍閥反而不做決策？），**`sub_5C7FE` 的語意
   可能需要重新驗**，或者十大勢力另有決策路徑。記為未解。

## 2. `sub_149C8`：候選是「我方的、前線的、快撐不住的」省 — confirmed

**掃全部 39 省，不是只看鄰省。**

```
我方勢力 = 省份[當前省].+20
for p = 1 .. word_7001E:                       ; 省份總數
    if 省份[p].+20 != 我方勢力:      continue   ; 只看自己的
    if sub_5B7DC(p, 我方) == 0:      continue   ; ← 必須是**前線**
    if sub_5B983(p) >= 2000（7D0h）: continue   ; ← 戰力總和 < 2,000
    if 省份[p].+32 & 40h:            continue   ; 交戰中的不救
    sub_14860(狀態, p)                          ; 算兩個排序指標
    候選 += p
```

`2000` 是很具體的一道門檻。`sub_5B983` 是該省可用將領的**攻擊力總和**
（`docs/mechanics/70-ai.md` §6h），所以這條讀作
**「戰力掉到 2,000 以下的前線省」**——快撐不住了。

> 掃全國而不是掃鄰省，是這一支與其他五支調動最大的差別。
> 也因此後面才需要尋路：目標可能離得很遠。

## 3. `sub_14860(狀態, 省)`：算兩個威脅指標 — confirmed（結構）

```
最大關係值 = 0
敵省數 = 0
for k = 1..7:
    鄰 = 省份[省].鄰省[k]
    跳過 0／0FFh
    if 省份[鄰].+20 == 我方勢力:  continue     ; 自己人不算
    if 省份[鄰].+20 == 0:         continue     ; 無主省不算
    敵省數++
    a = [我方領袖   - 0x5319]                  ; 將領 → 勢力索引
    b = [鄰省的司令 - 0x5319]
    值 = [a × 3Bh + b - 0x5237]                ; ← 59 × 59 的矩陣
    if 值 > 最大關係值:  最大關係值 = 值
狀態[-52h + 2×省]     = 最大關係值
狀態[-52h + 2×省 + 1] = 敵省數
```

### ⚠️ 兩張新的資料結構

| 位址 | 形狀 | 讀法 |
|---|---|---|
| `-0x5319` | byte 陣列，索引是**將領 ID** | 將領 → 勢力索引 |
| `-0x5237` | **59 × 59** byte 矩陣（`3Bh` = 59）| 勢力對勢力的關係值 |

`59` 這個維度在別處沒出現過（省是 39、將領是 274、勢力上限是 10）。
**它是什麼還沒解**——可能是勢力表的容量，也可能是別的實體。
內容要從 `.DAT`／存檔對出來才算數，這裡只記結構。

## 4. 兩輪排序：先看敵省數，再看關係值 — confirmed

```
sub_14B0D:  依 狀態[-51h + 2×候選]（敵省數）    降序
sub_14BEE:  依 狀態[-52h + 2×候選]（最大關係值）降序
```

兩支都是氣泡排序，交換條件都是 `cmp al, dl / jnb 不換`
——`al < dl` 才換，所以前面的要大，**降序**。

第二輪跑在第一輪之後，所以**最終主鍵是關係值**，敵省數只在關係值
相同時才有影響。

讀起來是：**優先救「被關係最惡劣的勢力包圍」的省**。

## 5. `sub_14CCF`：挑的不是目的地，是**通往它的第一步** — confirmed

```
for 候選 in 排序後的清單:
    sub_5BF74(狀態[+6], 我方勢力, arg_4, 候選, 當前省)
    ; 輸出：byte_70013 = 路徑長度、[-41C5h + i] = 路徑節點

    if byte_70013 == 1 且 !sub_5B76E(節點[1], 節點[2]):  continue
    if 節點[byte_70013] == 當前省:                       continue
    if !sub_5B76E(當前省, 節點[byte_70013]):             continue
    → 選中，回傳 節點[byte_70013]
```

回傳的是**路徑上與當前省相鄰的那一格**，不是候選省本身。
調動只能往鄰省走，所以遠處的救援目標要一步一步接力過去。

### 這讓 `sub_5BF74` 從強證據升為 confirmed

`docs/mechanics/70-ai.md` 先前標它為「省份層的路徑搜尋 — 強證據」，
依據是 `GetMem(5F1h)` = 1,521 = 39 × 39。現在有了輸出的用法：

- `byte_70013` = **路徑長度**
- `[-41C5h + i]` = **路徑節點陣列**（byte，省編號）

`sub_5B76E`（鄰接檢查）拿來驗路徑的連續性，語意完全自洽。
⚠️ 兩支權重函式（`sub_5BA56`／`sub_5BD7B`）仍**未讀**，
所以「路徑怎麼算出來的」還是未知——只知道它是路徑。

## 6. `byte_6FFCA` bit 0 解了 — confirmed（用途）／假說（語意）

`sub_15018` 開頭有一段只在 `byte_6FE88 == 1` 且 `byte_6FFCA & 4` 時才跑：

```
n = 0
for i = 1 .. 18h（24）:
    if 表[i] != 0 且 將領[表[i]].+16 & 1:  n++     ; 表在 [-534Ah]，24 格 word
```

然後決定調動模式：

```
if n == 2:  模式 = (byte_6FFCA & 1) ? 7 : 5
else:       模式 = 1
```

**bit 0 只做這一件事**：當那張 24 格表裡剛好剩 **2** 個可用將領時，
調動用模式 7 而不是模式 5。

兩者都是「只調滿員的」，差別是模式 5 掃完整份清單、模式 7 掃到
`count-1`（`docs/re/10` §3b）。**差一個人。**

這是 `byte_6FFCA` 八個位元裡最後一個未知的（bit 1、3、7 仍未見使用）。
⚠️ 那張 24 格表 `[-534Ah]` 是什麼、`byte_6FE88` 是什麼，都還沒解。

## 2. 難度決定用哪一支湊兵 — **confirmed**

```asm
loc_174E0:
mov     al, byte_6FFCA
and     al, 1
cmp     al, 1
jnz     short loc_1751F
;   高難度：
call    sub_1655C              ; 138 行，**多收一個「模式」參數**
jmp     short loc_1754F
loc_1751F:
;   低難度：
call    sub_16A9E              ; 83 行，**不收模式參數**
```

這是 `byte_6FFCA` bit 0 的**第五個用途**（前四個見 `70-ai.md` §3w）。

兩支的參數列差一個：`sub_1655C` 收模式，`sub_16A9E` 不收。
所以**低難度的電腦不分模式 2／3，一視同仁**——
模式差異只在高難度下生效。

### `sub_1655C` 的參數（Pascal 慣例，由左至右壓棧）

```
sub_1655C(X, &狀態[-5], &狀態[-0EEh], 10, &狀態[-12h], 目標省, 模式)
          ↑  ↑          ↑             ↑   ↑            ↑       ↑
      bp+4  bp+6     bp+10        bp+14 bp+16       bp+20   bp+22
```

`X = ss:[bp_17ADA+4]` 是外層狀態，`目標省 = ss:[bp_17ADA-2]`
（步驟 4／5 挑出來存在 `var_2` 的那個省）。

> ⚠️ IDA 的 `arg_C = dword ptr 10h` 這種標法**名字與偏移不一致**
> （`arg_C` 在 `bp+16` 不是 `bp+12`）。照偏移讀，別照名字。

## 4. 湊兵迴圈 — **confirmed（結構）**

```asm
loc_165F6:
inc     [bp+var_A]             ; 計數
push    bp
call    sub_1629E              ; ← 試著把第 idx 個將領收進名單（§4b）
push    bp
call    sub_163BE              ; ← 夠了沒？177 行
or      al, al
jz      short loc_165F6        ; 回 0 → 繼續湊
```

**`sub_163BE` 回非 0 就停**。它裡面依模式分兩套停止條件，
兩套都用 Turbo Pascal 的 48-bit Real 常數：

| 模式 | 暫存器 | 常數 | 條件 |
|---:|---|---:|---|
| 1 | `CX=82h SI=0 DI=4000h` | **3** | `Round([-14h] × 2 ÷ 3) ≥ [-18h]` → 停 |
| 2／3 | `CX=82h SI=0 DI=2000h` | **2.5** | `Round([-1Ch] × 2.5) ≤ [-10h]` → 停 |

Real 解碼照 `docs/re/10` 的規則（`byte0` 是 exponent、`bytes1-5` 是
mantissa 低位在前、最高位隱含 1）：

```
exp 82h → 2^(82h-81h) = 2
40h → 補隱含位 C0h → C0h/80h = 1.5   → 1.5 × 2 = 3
20h → 補隱含位 A0h → A0h/80h = 1.25  → 1.25 × 2 = 2.5
```

`sub_1629E` 讀完之後這條**已定案**（見 §4b）：
`[-10h]` 在進迴圈前被歸零，迴圈中累加每個收進來的將領的攻擊力，
所以它就是**已派出的戰力總和**。

> **模式 2／3 湊到目標省戰力的 2.5 倍就收手。**

`[-18h]` 則是每收一個就**減掉**，所以是**留守戰力**（本省 − 已派出）。

⚠️ 模式 1 那條（除以 3）用的 `[-14h]` **`sub_1629E` 從來不寫**，
所以它在這條路徑上恆為 0。模式 1 也不從 `sub_174C9` 進來
（開頭就跳走了），要 `sub_18509` 那個呼叫端才走得到——**仍是假說**。

## 4b. `sub_1629E`：挑人的兩道篩選 — **confirmed**

```
idx = 父[-0Ah]                          ; 掃到第幾個
gen = X[-22Eh + idx×2]                  ; 當前省的將領清單[idx]

if 將領[gen].+21（兵種）== 4:
    父[-0Bh]++                          ; ← **計數先加**
if 將領[gen].+21 == 4 且 父[-0Bh] ≥ 1:
    return                              ; 不收

if sub_5A0B9(gen) < 10:  return         ; 單兵戰力下限

父[-0Ch]++                              ; 已收人數
父[-10h] += sub_5A0B9(gen)              ; 已派出戰力
父[-18h] -= sub_5A0B9(gen)              ; 留守戰力
出兵名單[父[-0Ch]] = gen
```

### ⚠️ 兵種 4 一個都收不到 — 疑似原版 bug

`inc` 排在比較之前，所以碰到**第一個**兵種 4 時計數已經是 1，
`1 < 1` 不成立 → 當場攔下。看起來本意是「最多帶一個」，
實際效果是「**一個都不帶**」。

兵種 4 的人力權重是 4、滿員 5,000。照抄這個行為
（`CLAUDE.md` §9：原版行為就是規格，不在 remake 補上「本意」）。

### `ss:[X-22Eh]` 是清單的**長度**，後面接著清單本身

`70-ai.md` §6m 記過「`狀態[-22Eh]` = 當前省的將領清單長度」。
補上一句：**它後面接的就是清單**，`[-22Eh + i×2]`（`i` 從 1 起）
是第 `i` 個將領的 ID。兩者不衝突，只是原本只記了 `[0]`。

## 4c. `sub_163BE`：四個停止條件 — **confirmed**

```
上限 = ?                                ; 見下
if 父[-0Ah] == 清單長度:      停         ; 掃完了
if 模式 == 2 或 3:
    if Round(父[-1Ch] × 2.5) ≤ 父[-10h]: 停    ; **湊夠了**
    if 父[-0Ch] == 上限:                 停
    if 父[-0Ch] == 10:                   停    ; 硬上限
if sub_13710(當前省) 且 父[-0Ch] + 5 ≥ 清單長度 且 byte_6FE88 != 1: 停
```

**上限**由開頭那段算出來，四個分支：

| 條件 | 上限 |
|---|---|
| `ss:[X+0Eh] == 10` | 清單長度 **− 1** |
| `ss:[X+0Eh] < 清單長度` | `ss:[X+0Eh]` |
| 目標省的司令 == 我方勢力 | 清單長度 |
| 其他 | 清單長度 − 1 |

⚠️ `sub_1655C` 的呼叫端把 `ss:[X+0Eh]` **寫死成 10**（`mov al, 0Ah; push ax`），
所以**第一個分支恆成立**，上限永遠是「清單長度 − 1」：

> **至少留一個守家。**

另外三個分支要 `sub_18509` 那個呼叫端傳別的值才走得到，**未驗**。

實作在 `internal/game/aisortie.go`。

**模式 2 要求湊到的兵力 × 2 > 最強敵對鄰省的戰力**，模式 3 不要求。

「最強敵對鄰省」怎麼來的：`sub_5A907` 收集敵對鄰省 →
`sub_16047(mode 2)` 降序排 → 取第一個（`70-ai.md` §3r）。
若第一個正好就是要打的目標省而且候選不只一個，改取**第二強**的
——也就是**不把要打的那個算進威脅評估**，只看背後還有誰。

這是很細緻的判斷：**打之前先看側翼**。

## 5c. `sub_16A9E`：低難度版用「人數」當標準 — **confirmed（結構）**

### ⚠️ 一處疑似無效的比較

`sub_1655C` 的 `loc_165DA` 比「本省戰力」與「最強敵省戰力」：

```asm
cmp     dx, [bp+var_12]
jl      short loc_165EC        ; 高位小於 → 結束，不出兵
jg      short loc_165EE        ; 高位大於 → 出兵
cmp     ax, [bp+var_14]
ja      short loc_165EE        ; 出兵
;   fallthrough → loc_165EE    ; ← **也是出兵**
```

低位比較的兩條路徑**都到 `loc_165EE`**，所以那次 `cmp ax, [bp+var_14]`
沒有任何作用。實務上戰力值遠小於 65,536，高位恆為 0 恆相等，
**這道檢查等於永遠放行**。

與 `sub_306CF` 開頭那段「交戰中就歸零」（`70-ai.md` §3u）一樣，
是寫了但不生效的碼。照抄行為即可，不要在 remake 補上「本意」——
**原版的行為才是規格**。

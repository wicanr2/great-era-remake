## 1. 三層結構

```
sub_39B6E          戰鬥主函式
  └ sub_3F698      ← **戰鬥 AI 的主入口**（189 行）
      ├ sub_3AB99  ← **決策鏈**：決定要做什麼，寫進 byte_6AA85 / byte_6AA84
      └ switch     ← **分派器**：依那個值呼叫對應的行動函式
```

`sub_39B6E` 在 `+299` 與 `+4C7` 兩處呼叫 `sub_3F698`，各傳一個 `arg_0`。

⚠️ `arg_0` 的語意是**假說**：它決定走哪一條決策鏈，而兩條鏈各自用一個
相鄰的變數（`byte_6AA84`／`byte_6AA85`），形狀像「兩方各一套」。
與 `byte_64901`（攻方 1／守方 2，`30-combat.md` §3i）的對應**未驗**。

## 2. `sub_3AB99`：決策鏈 — **confirmed（結構）**

與政略決策鏈**完全同構**：優先序 + 一個「已決定」旗標（`var_1`），
第一個做出決定的就是答案。

```
sub_55FBE(&格清單, &數量)                    ; 先掃全場（見 §5）

if arg_0 == 0:                               ; 分支 A，五步
    byte_6AA85 = 0
    sub_3A817                                ; 11 / 12 / 16 / 17
    if !決定: sub_3A885                      ; 12
    if !決定: sub_3A8C8                      ; 19
    if !決定 且 byte_6FFCA & 4: sub_3A8F7    ; 14 / 15 / 18
    if !決定 且 byte_6FFCA & 4: sub_3A94E    ; 16 / 17
    if !決定: byte_6AA85 = 13                ; ← **預設行動**
    sub_3A988                                ; 不設值，收尾
    sub_3A9C9                                ; 不設值，收尾
else:                                        ; 分支 B，三步
    byte_6AA84 &= 0C0h                       ; 只留 bit 6/7
    sub_3A9F4                                ; 2
    if !決定: sub_3AA51                      ; 1 / 3
    if !決定 且 byte_6FFCA & 4: sub_3AABA    ; 4
    if !決定: byte_6AA84 |= 3                ; ← **預設行動**
    sub_3AAF4                                ; 不設值，收尾
```

**`byte_6FFCA & 4` 又出現了**——與政略決策鏈的「啟用最後三步」
（`70-ai.md` §6d）是同一個位元、同一個手法。這是 bit 2 的**第四個用途**。

⚠️ `byte_6AA84` 開頭那三段位元操作（`and 80h / or 80h`、`and 40h / or 40h`）
是**恆等變換**——`x & 80h` 非零時再 `or 80h` 不改變任何東西。
淨效果就是最後那一行 `and 0C0h`。與 `sub_306CF` 的死碼（`70-ai.md` §3u）
同型：寫了但不生效。

## 4. `sub_3A320`：戰力比門檻 — **confirmed**

決策鏈用它做判斷，與政略的 `sub_16F89`（優勢比，`70-ai.md` §3w）同型：

```
if mode != 0:  mine = Σ sub_5A0B9(word[0x750 + i×2])   i = 1..10
               other = Σ sub_5A0B9(word[0x764 + i×2])
else:          mine 與 other 對調
回 (mine × Real 常數) ≤ other
```

`0x750`／`0x764` 是兩方各 10 個單位的清單（`docs/re/05` §已記），
`sub_5A0B9` 是單一將領的攻擊力。**AI 的評估函式又是攻擊力公式**
——這是第六個獨立的例子。

### 常數 0.67

`sub_3A8F7` 傳的是 `AX=5280h BX=1EB8h DX=2B85h`，
解碼（`tools/tp_real.py`）得 **0.67**。

```
80 52 b8 1e 85 2b  →  0.67
```

讀作：**「我方戰力 × 0.67 ≤ 對方戰力」**，也就是**對方至少有我方的 2/3**
——勢均力敵或更差時才走那一步。

⚠️ `tools/tp_real.py` 內建 `--self-test`，用五個在別處驗過的常數
（10／0.8／1.5／2.5／3）當正對照，全過才輸出。

## 5. ⭐ 整條鏈圍繞的是**城市** — **confirmed**

決策鏈開頭先跑 `sub_55FBE`：

```
n = 0
for 格 = 0 .. 0C3h (195):
    if sub_50151(格) == 5:
        清單[++n] = 格
for i = n+1 .. 10:
    清單[i] = 0FFh              ; 補哨兵
```

**`sub_50151(格) == 5` 就是「這格是城市」**（`docs/spec/04` §2 的地物編號表，
5 = 城市，全圖 91 格、39/39 省驗證過）。

所以這一支是**掃全場找出所有城市格**，最多 10 個，不足補 `0FFh`。

> **戰鬥 AI 的每一個決策都圍繞城市。**

這解釋了整條鏈的形狀：`sub_3A766`（§6）檢查那些城市格有沒有被攻方站住
或被逼近，六支行動函式也各自拿這份城市清單去做事。
與省份面板顯示「城市數」、`WARPOS.DAT` 每個鄰省分區 10 格對上 10 個部隊槽
（`docs/re/07`）都對得上——**戰場的目標是城市，不是殲滅**。

### `sub_50151`：地形解碼器 — **confirmed**

它同時證實了 `CLAUDE.md` §3 記的 `30 + 25×圖塊 + 地形` 疊加編碼：

```
if 格 == 0FFh: 回 var_1              ; ⚠️ **未初始化**（見下）
v = word[796h + 格×2] & 0FFFh        ; 戰場地形陣列，取低 12 位
if v ≥ 25:
    v -= 30                          ; ← 先減掉 30 那一層
    while v > 25: v -= 25            ; ← 再一路減 25
回 v                                  ; 1..25 的底層地形編號
```

`& 0FFFh` 取低 12 位——高 4 位就是 `NWMAP.DAT` 那批未解的旗標
（`CONTEXT.md` worklist 1a）。**戰鬥用不到高 4 位。**

⚠️ `arg_0 == 0FFh` 時直接跳到出口，回傳**從未賦值的 `var_1`**——
又一個讀未初始化堆疊值的地方（與 `Strength` 的 `BranchWeight == 0`
同型，`strength.go`）。哨兵值 `0FFh` 正是 `sub_55FBE` 自己補的那個，
所以**呼叫端必須先擋掉哨兵**，不能把整份 10 格清單直接餵進來。

## 8. 這一輪的方法

沒有逐支讀 100 多行組語，而是**先掃形狀**：11 支決策步驟都是同一個模式
（呼叫 `sub_3A320` 比戰力 → 設一個值 → 立旗標），
所以 `tools/battle_ai_chain.py` 一次抽出全部的「常數 + 決策值 + 呼叫」。

> ⚠️ 第一版把 `12h` 讀成十進位 12（正確是 18）——IDA 的 `h` 後綴是可選的，
> 正則寫成 `([0-9A-F]+)h?` 之後沒有記下有沒有真的匹配到 `h`。

## 9. ⭐ 行動 A11 / B1 = **結束戰鬥** — **confirmed**

分派表裡最短的一支：`sub_3B19C` 只有 15 行，轉手呼叫 `sub_3AC7B`：


`sub_54E3B` 就是**九步結算**（`30-combat.md` §3）。第二個參數是**勝方**

所以：

| 分支 | 決策值 | 參數 | 意思 |
|---|---:|---:|---|
| A | 11 | 0 | 結算，**判給 `word_64942`**（攻方）|
| B | 1 | 1 | 結算，**判給 `word_64944`**（守方）|

## 11. 12 支行動函式的**共同形狀** — **confirmed（欄位）**

沒有逐支讀 200–500 行，而是用 `tools/field_writes.py`（過濾器經正對照）
一次掃全部的寫入。結果顯示它們**填同一個結構**。

### ⛔ 訂正：那個「命令結構」**就是單位記錄的 `+9` 起**

`sub_3D0AC` 有一行揭穿了它：

```asm
mov     di, ax
add     di, 7A86h                    ; ← 7A86h = 將領記錄的 +9
mov     word ptr [bp+var_8], di
mov     word ptr [bp+var_8+2], ds    ; var_8 = &將領[u].+9
...
les     di, [bp+var_8]
mov     byte ptr es:[di], 6          ; ← 就是 將領[u].+9 = 6
mov     es:[di+3], al                ; ← 就是 將領[u].+12
```

所以下面那張表的 `es:[di+N]` **要整個平移**：

```
es:[di+0] = +9      es:[di+1] = +10     es:[di+3] = +12
es:[di+9] = +18     es:[di+10] = +19    es:[di+13] = +22
```

**`+9` 就是那個「命令類型」欄位**，值域至少 `{1, 2, 3, 6}`。
`+10`（目標單位）與 `+12`（下一格）在 §12 已經定名——三格是同一組
「單位當前的命令」。

⚠️ `sub_3E691` 用 `es:[di+9]`／`+10`／`+12`／`+13` 那一組，
平移之後是 `+18`／`+19`／`+21`／`+22`——**那是另一組欄位**，不是同一個命令。

### 原始掃描結果（偏移未平移）

| 偏移 | 寬 | 寫入者 | 值 |
|---:|---|---|---|
| +0 | byte | `sub_3CBD9`／`sub_3D57B`／`sub_3DD05`／`sub_3DED9` | **2** |
| +0 | byte | `sub_3D823`／`sub_3E24F` | **3** |
| +1 | word | 六支 | 變數 |
| +3 | byte | 七支 | 變數 |
| +9 | byte | `sub_3E691` | **3** |
| +10 | word | `sub_3DD05`／`sub_3DED9`／`sub_3E691` | 變數 |
| +12 | byte | `sub_3E691` | 變數 |
| +13 | byte | `sub_3DD05`／`sub_3DED9`／`sub_3E691` | 變數 |

**`es:[di+0]` 就是單位記錄的 `+9`＝命令類型**（見上），目前看到 2 與 3，

| 0 劣勢 | **2** |
| 1 優勢 | **1** |
| 2 壓倒 | **0** |

⚠️ 迴圈**倒著掃**，所以先被投入的是 index 大的單位；留下的是 index 小的。
兩個計數迴圈的下界都是 **2**，index 1 完全不碰。

### 後半段：主將要不要親自上

```

```

讀作：**兵少但打得順，或幾乎沒人在找目標了，主將才親自上；劣勢時主將不動。**

⭐ `戰力和` 算完沒有任何地方讀它——原版的死碼，記一筆免得下次又去追它。

⭐⭐ 這一段給了命令 4 最硬的線索：**壓倒性優勢時主將設 3，只是優勢時設 4**
→ **4 比 3 保守**。配上「待命(2) 被啟用會變成 4」，4 像是

## 18. `byte_6AA85` 的 bit 6／7 — 解了一半

§3 記過兩處分派都取 `& 1Fh`，所以 **bit 5–7 另有用途（未解）**。
其中兩位找到來源了：

| 位元 | 設定者 | 條件 |
|---:|---|---|
| **7**（80h）| `sub_3A988` | `word[796h + i×2] & 2000h` |
| **6**（40h）| `sub_3A9C9` | `將領[word_64944].+4 == byte_6FFC4` |

`+4` 是**省份**（`docs/spec/02`），所以 bit 6 是
「第二方的代表單位在 `byte_6FFC4` 這個省」。⚠️ `byte_6FFC4` 的語意未解。

讀取端只有一處，在 `sub_3D57B`（決策值 13 的行動）：

```
if (byte_6AA85 & 80h) != 0 且 byte_64900 ≥ 5:  → loc_3D80E
```

⚠️ **順序上有陷阱**：那一串 `mov byte_6AA85, imm`（0Bh..13h）是**整個覆蓋**，
會把 bit 6／7 清掉；`or al, 80h` 是疊加。誰先誰後決定 bit 7 讀不讀得到，
**未驗**——`sub_3A988`／`sub_3A9C9` 在鏈中的位置要再確認。

bit 5 仍然沒有任何寫入者。


## 19. `sub_3C89A`（198 行）：決策值 B=3，也就是**預設行動**

## 20. `sub_58DF9(side)`：數某一方還有幾個單位

```

else:         複製 word_64916 起 20 bytes
```

`0x64916 = 0x64902 + 20`，兩個 10 格 word 陣列**首尾相接**。

⚠️ 這與 `sub_3A320` 掃的 `0x750`／`0x764`（§4）是**不同的兩組陣列**，
兩組都是「兩方各 10 格」。哪一組是什麼**未解**，別把兩者混為一談。

### 連帶訂正：`word_64902` 不是「主將」

§17 與 `battleforce.go` 把 `word_64902` 稱作「主將」。
從這裡看清楚了：它是**第一方單位陣列的第 1 格**（`word_64916` 是第二方的第 1 格）。

## 21. ⭐⭐ `sub_3B492` + `sub_3B400`：**挑最近的敵方城市**

§19 的評分函式解開了。367 行拆成兩段。

### 第一段：給每個城市打分

```
for i = 1..城市數:
    格 = 城市清單[i]
    u  = word[62A8h + 格×2]                ; 格佔用表（docs/re/07 §已記）

    elif 將領[u].+8 != 0:                   ; ← 攻方

            城市清單[i] = 0FFh              ; ← **整格剔除**
        評分[i] = 0
    else:                                   ; ← 守方
        評分[i] = sub_3B400(狀態, 格)       ; ← 分數
```

⭐⭐ `cmp byte ptr [di+7A86h], 5` 是**整份程式唯一比較命令 5 的地方**。
配上「`+12`（下一跳）正好是這個城市」，語意很清楚：

> **命令 5 = 已經朝這個城市去了。** 有人去了就把城市從候選剔除，別再派人。

§15 記過「沒有任何函式寫立即數 5 進 `+9`」——現在知道**讀的地方也只有一處**。
值從哪裡來仍未解（存檔？某個計算結果？）。

### 第二段：`sub_3B400` 就是**曼哈頓距離**

```
myCell = 將領[word_64902].+5      ; 首位單位所在格
回 |myCell div 14 − 格 div 14| + |myCell mod 14 − 格 mod 14|
```

`cwd / xor ax,dx / sub ax,dx` 是標準的絕對值慣用法，兩次。
14 就是戰場欄數（`docs/re/07` §3，196 = 14×14）。

⚠️ **戰場是六角格，這個距離卻是矩形的曼哈頓距離。** 從頭到尾沒有六角修正。
這是原版的估算方式，照抄——`internal/game/battlecity.go` 標了這一條。

### 第三段：升序排序

雙層迴圈（i = 1..n−1，j = i+1..n），比較 32-bit 評分：

```
if 評分[j] < 評分[i] 且 城市清單[j] != 0FFh: 交換
```

**升序**，小的在前；被剔除的 `0FFh` 不參與交換。

配上 §19 的「取第一個分數 > 0 的城市」，整條鏈合起來就是：

> ⭐⭐ **挑距離最近、由敵方佔據、而且還沒有人去的城市。**
> 距離 0（自己就站在城市上）被 `> 0` 濾掉。

### ⭐ 讀這份程式的一個關鍵：Pascal 巢狀程序

`push bp / call sub_3C0D5` 傳的是**呼叫者的整個 stack frame**，
而 `sub_3C0D5` 用 `ss:[di+4]`／`ss:[di+6]`／`ss:[di+8]` 取回外層的三個參數。
這是 Turbo Pascal 巢狀程序（nested procedure）的標準做法。

> **看到只有一個 `arg_0` 卻在裡面 `ss:[di+n]` 亂取的函式，那是巢狀程序，
> `arg_0` 是外層的 bp。** 不是「參數很少」，是參數在外層。

## 24. `sub_3BF6A`（175 行）：城市空著時改追人

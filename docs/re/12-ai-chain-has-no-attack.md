# 政略決策鏈裡沒有「攻打」——六步全是調動

輸入檔：`WAR.EXE`（375,568 B，未打包）
位址：IDA linear address
日期：2026-08-01

`docs/mechanics/70-ai.md` §6i 曾經下過這個結論：

> **政略階段電腦做的事，主要就是「調動」與「攻打」兩種。**
> 決策鏈的六個步驟裡有五個呼叫 `sub_14F9A`（調動），
> 只有 `sub_15925` 是攻打。

**`sub_15925` 也是調動。** 決策鏈六步全部呼叫 `sub_14F9A`，
一步攻打都沒有。

---

## 1. 怎麼發現的

`cmd/aisim` 接上戰鬥層之後跑 25 回合，有 61 次「攻打」失敗於
**「省 N 沒有可出兵的將領」**——決策層說要打，執行層發現省裡沒人。

這與 `docs/playtest/05` §2 抓到的是同一類毛病（決策與執行條件不一致），
所以回去讀 `sub_15925`，結果讀出的是別的東西。

---

## 2. `sub_15925` 的最後一行 — confirmed

```asm
mov     al, [bp+var_3]          ; 目標省
push    ax
mov     al, 2                   ; ← 調動模式 2
push    ax
push    word ptr ss:[di+4]
call    sub_14F9A               ; ← 調動，不是戰鬥
```

`sub_14F9A` 是調動的入口（`docs/re/10` §4）。攻打會進戰鬥模組
（`docs/re/06` 的三個 gate），這裡完全沒有。

---

## 3. 目標篩選 `sub_1588C` 一個敵省都不收 — confirmed

```
n = sub_5A881(鄰省)                          ; 該省將領數
if 省份[鄰省].+20 == 0:            回 1       ; 無主省：收
if 省份[鄰省].+20 != 我方勢力:      回 0       ; ← 別人的省：不收
if sub_5B7DC(鄰省) != 0 且 n <= 15: 回 1       ; 自己的前線省，人不多
if sub_5B7DC(鄰省) == 0 且 n <=  2: 回 1       ; 自己的後方省，人很少
回 0
```

`sub_5B7DC` 回非 0 表示該省有敵對鄰省（前線）。整段裡**沒有任何分支
會放行敵方的省**——第二條就把它們全擋掉了。

---

## 4. 一道很硬的前置門檻 — confirmed

```asm
cmp     [bp+arg_2], 0
jz      short loc_15943
mov     [bp+var_D], 19h         ; arg_2 = 1（前線）→ 25
jmp     short loc_15947
loc_15943:
mov     [bp+var_D], 5           ; arg_2 = 0（後方）→ 5
...
cmp     ax, ss:[di-22Eh]        ; 門檻 vs 當前省將領數
jle     繼續
jmp     結束
```

| 呼叫端 | 門檻 |
|---|---|
| 前線鏈 `sub_15925(1)` | 當前省將領數 **≥ 25** |
| 後方鏈 `sub_15925(0)` | 當前省將領數 **≥ 5** |

**25 幾乎不可能達到**——`sub_1527A` 增援前線的上限才 15
（`70-ai.md` §6f），而電腦的整體傾向是分散不集中。
所以**前線鏈的這一步實際上等於關閉**。

> 這正是原本誤判的代價之一：規則層把它當成「攻打」又沒有門檻，
> 於是每個前線省每回合都攻打，20 回合跑出 574 次。

## 5. `sub_14EBA`：挑最窮的省 — confirmed

```
複製候選陣列（8 bytes，1-based）
for i = 1 .. n-1:
    for j = i+1 .. n:
        if 省份[候選[j]].+0 < 省份[候選[i]].+0:  swap
回 候選[1]
```

排序鍵是省份記錄的 `+0` = **黃金**（`docs/spec/03` §2），
交換條件 `cmp ax, cx / jbe 不換` 讓小的排前面——**升序**。

所以 `sub_15925` 的語意是：

> **把部隊送去自己最缺錢的鄰省（或無主的鄰省）。**

---

## 6. 電腦在政略階段不會主動攻打 — **強證據**

三條線索指向同一個結論。

### 6a. 只有兩個地方會設「正在打仗」

省份記錄 `+32` 的 bit 6 是交戰旗標（`docs/spec/03`）。全檔只有兩處寫它：

```
sub_2D812   ←  sub_2DEFC  ←  sub_10193（PROGRAM+390）
sub_3964E   （戰鬥模組內部，載入 mem_war.dat 的那一支）
```

### 6b. `sub_10193` 是**玩家**的指令選單

439 行，14 支指令函式一字排開，`sub_2DEFC`（攻打）排第一，
裡面有 `(Y/N)` 確認字串。數量對得上 `docs/playtest/02` §5 實機看到的清單。

### 6c. 玩家路徑與電腦路徑靠 `+32` bit 2 分流

```asm
; PROGRAM+390 附近，進玩家選單之前
mov     al, [di-6215h]          ; 省份 +32
and     al, 4                   ; bit 2
or      al, al
jnz     short loc_10F52         ; ← 立起來就跳過玩家選單
...
call    sub_10193

; PROGRAM+446 附近
call    sub_1ACCC               ; 電腦的一個回合
```

而 `sub_13D23`（`sub_1ACCC` 的第一步）做的正是：

```asm
mov     al, [di-6215h]
or      al, 4                   ; ← 立起 bit 2
mov     [di-6215h], cl
```

**電腦處理過的省，玩家選單就跳過。** 兩條路徑互斥，
而攻打只掛在玩家那一側。

### 6d. 兩條決策鏈都不呼叫攻打

| 鏈 | 呼叫的東西 |
|---|---|
| `sub_15F3C`（已解）| 六步全是 `sub_14F9A`（調動）|
| `sub_17ADA`（667 行）| `sub_174C9` ×4、`sub_16B44` ×4、`sub_14F9A` ×2、`sub_14E85` ×2⋯ |

`sub_17ADA` 底下那批（`sub_174C9`／`sub_1655C`／`sub_16A9E`／`sub_173B5`／
`sub_17437`／`sub_17019`／`sub_16CBB`／`sub_16D98`）**沒有一支碰
`sub_2DEFC` 或 `sub_2D812`**。

### 為什麼標強證據而不是 confirmed

「電腦不會主動打你」與一般的戰棋直覺衝突，所以留餘地：

- `sub_17ADA` 的 667 行只讀了骨架，內部分支還沒逐條對
- ~~`sub_15CE3`（302 行）仍未讀~~ → **已讀完，也是調動**（`docs/re/14` §2）。
  決策鏈**八支步驟函式全部呼叫 `sub_14F9A`，零例外**
- **DOSBox 長期實測沒做**。oracle 本身已經恢復（`docs/playtest/06`），
  但只跑了一個月——要連跑十幾個月看電腦會不會打過來才算數

若成立，它讀起來是合理的設計：**玩家主動制**。
電腦靠調動往無主省擴張、把部隊往前線與窮省送，
玩家發動戰爭，電腦防守。

**在 DOSBox 驗過之前，規則層不假裝電腦會攻打。**
`cmd/aisim` 的 `-fight` 旗標是明確標記的探索工具，不是原版行為。

## 8. 教訓：一支函式的名字要看它**呼叫什麼**，不是它**收集什麼**

`sub_15925` 收集鄰省候選、排序、挑一個——形狀與「選攻打目標」
一模一樣。當初標「收集候選鄰省 = 攻打」時沒有跟到最後那個 `call`。

這與 `docs/playtest/05` §3 的錯誤（讀到 `cmp` 沒跟 `jnz` 跳去哪）
是同一類：**在推論的最後一步停下來**。

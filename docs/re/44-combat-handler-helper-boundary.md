# RE-44：戰鬥 handler 與資源 helper 的證據邊界

日期：2026-08-11  
輸入：`WAR.EXE`  
SHA-256：`11dbfcf24686ab7765f788b38514cefd2039d0f60b6bd517d89fb5a84c068015`  
工具：IDA Pro `9.4.0.260610`；以下位址均為 IDA linear address。

本紀錄把「六種攻擊」的誤稱再拆成可回查的第二層六鍵選單、handler／helper 呼叫鏈。它只保留
能直接由指令與寫入端支持的部分；未解的欄位、動畫、音效與選擇時機不因 remake
已有函式就升格為原版等價。

## 1. 玩家輸入與 handler

`sub_4D585`（`4D585h..4D96Eh`）建立字串 `"0123456"`，接受 `1..6` 方向／目標
輸入，`0` 或 Enter 離開；這六個數字不是六個命名攻擊。`sub_4BF27`
（`4BF27h..4C2EAh`）在目標／狀態檢查後以選單輸入分派：

`sub_4BF27` 在 `4C165h..4C18Ah` 直接建立 `"123456"` 並呼叫 `sub_5544F`，
再依輸入分派。這條輸入與 `sub_4D585` 的六方向 `"0123456"` 不同：

| 按鍵 | 直接 handler | 指令證據 |
|---:|---|---|
| `1` | `sub_4B827` | `cmp al,31h` → `call sub_4B827` |
| `2` | `sub_53111` | `cmp al,32h` → `call sub_53111` |
| `3` | `sub_4B854` | `cmp al,33h` → `call sub_4B854` |
| `4` | `sub_4BA1E` | `cmp al,34h` → `call sub_4BA1E` |
| `5` | `sub_4BCBE` | `cmp al,35h` → `call sub_4BCBE` |
| `6` | 無 handler call | `cmp al,35h` 不相等後落到 `loc_4C2CB`；取消／保留／bug unknown |

第二層六鍵選單的存在已 confirmed，但不等於六個攻擊名稱已解出。

| 原始函式 | 指令中可直接確認的呼叫 | 目前等級 |
|---|---|---|
| `sub_4B827` | `sub_530B4`；設 `byte_6AA8A=1` | confirmed：單次正規 wrapper；helper 副作用未閉合 |
| `sub_53111` | 掃六鄰候選，呼叫 `sub_5301B`；分配主攻／候選支援損失 | strong inference：協同鏈；候選上限與分攤公式未閉合 |
| `sub_4B854` | 目標兵種 4／5 走特殊畫面，其他路徑呼叫 `sub_53428` | confirmed：控制流；特殊分支傷害／時機未知 |
| `sub_53428` | 連續呼叫 `sub_51D68` **五次**，扣雙方 `+7A8E`，收尾呼叫 `sub_517BE`／`sub_52EEA` | confirmed：五次呼叫與寫回；其餘副作用未知 |
| `sub_4BA1E` | 兵種 4 的 `sub_58854`／`sub_57B15` 遠程路徑 | confirmed：遠程控制流；彈藥／動畫／邊界未知 |
| `sub_4BCBE` | 兵種 6 對目標兵種 4／5 的特殊畫面，否則 `sub_58613` | confirmed：分支形狀；傷害與寫回未知 |

因此目前 remake 的 `Engage`、`EngageRanged`、`EngageRepeated` 是窄切片；第二層
六鍵選單的存在已確認，但五個 handler 的命名／完整副作用與第 6 鍵語意尚未閉合，
不應在 UI 或規格中宣稱「六種攻擊」已完成。

## 2. 已閉合的 helper 寫入與尚未閉合的語意

### 2.1 `sub_530B4`／`sub_5301B`

`sub_530B4` 把 `sub_5301B` 的兩個輸出分別扣到雙方執行期記錄 `+7A8E`，再呼叫
`sub_517BE` 與 `sub_52EEA`。`sub_5301B` 的固定參數會呼叫：

1. `sub_528EE`：依兵種選擇畫面／文字資產；
2. `sub_51399`：傳入 `arg_0=0` 的戰損呈現鏈；
3. `sub_5A3B2`：雙方傳入值 5 的效果／資源 helper；
4. `sub_51EC0`：雙方傳入值 1，將執行期 `+7A9A` 扣除並夾在 `0..100`；
5. `sub_51F19`：雙方傳入值 1，將執行期 `+7A9B` 扣除並夾在 `0..10`；
6. `sub_51D68`：以兩方戰力、地形與兵種分支計算輸出。

`+7A9A`、`+7A9B` 的欄位名稱、這些 helper 是否代表彈藥／燃料／士氣，以及
`sub_52D8F`／`sub_524FC` 的完整狀態副作用仍是 unknown。故不能只因看到扣值就
在 Go 中猜成「彈藥消耗」或「協同除法」。

### 2.2 `sub_51D68`

這支先計算兩個方向的 Real／Round 戰力值，再依 `arg_A` 對目標兵種套用加成：

- `sub_5867E` 成功時，第二個輸出加倍；
- `sub_50151` 回傳 2／11 時加倍，回傳 5 時加三倍；
- `arg_C != 0` 且 `arg_8 == 0` 時呼叫 `sub_51844`；
- 任一輸出乘 4 仍不足對方時走 `sub_51972`，否則走 `sub_51B94`。

這些分支證明原版存在地形／兵種／一面倒差異，但 `arg_8`、`arg_A`、`arg_C` 的
所有 callsite 語意及兩個戰損 helper 的完整寫入仍未閉合。現有 Go `Engage` 只
保留已可獨立驗證的戰力／四倍門檻／戰損邊界。

## 3. 交付邊界

- 已可安全交付：六方向目標表、近身單次、兵種 4 遠程三次目標損失、五次正規
  呼叫的 `EngageRepeated`；每支都保留證據等級。
- 不可宣稱完成：協同攻擊的支援分攤、兵種 4／5／6 特殊分支、完整撤退／部署／
  結算副作用、攻擊時機與 AI 選擇、`+7A9A/+7A9B` 的欄位語意。
- 在取得正常玩家傷亡／回合上限 oracle 前，不新增會改寫這些未解欄位的 Go 規則；
  以明確錯誤或 fallback 停止，避免 remake 過頭。

# 徵稅的公式：`sub_303CD`

輸入檔：`WAR.EXE`（375,568 B，未打包）
位址：IDA linear address
日期：2026-08-01

`docs/playtest/12` 量到徵稅帶亂數，結論是「不能寫成確定公式」；
`docs/re/17` 解開 LCG 之後那個門檻消失了。這一輪把公式讀出來。

---

## 1. 徵稅本身沒有 `Random`

`sub_2C6C6`（指令 4，440 行）裡一個 `Random` 都沒有。
亂數在它呼叫的 **`sub_303CD`**（147 行）裡，那支有兩個。

---

## 2. 完整公式 — confirmed

```
人口 = 省份[省].+12（u32）

; 一、黃金
黃金收入 = Random(Round(Sqrt(人口) × 5)) + 300
if 黃金收入 > 6500:  黃金收入 = 6500
if 黃金收入 < 1500:  黃金收入 = 1500
sub_5A467(省份[省].+0, 黃金收入, 60000)

; 二、糧食
糧食收入 = Random(Round(人口 ÷ 10000 × 5)) + 3000
sub_5A467(省份[省].+2, 糧食收入, 60000)

; 三、忠誠度（第一段）
if 省份[省].+19 < 30:  省份[省].+19 = 0
else:                  省份[省].+19 -= 30
```

回到 `sub_2C6C6` 的尾段還有第二段：

```asm
mov  al, [di-6215h]         ; 省份 +32
or   al, 80h                ; ← 設 bit 7「已徵過稅」
mov  [di-6215h], cl
mov  byte_6FE81, 1          ; 標記「這個指令有執行」

mov  al, [di-6222h]         ; 忠誠度（已被扣過 30）
cwd
mov  cx, 5
div  cx                     ; ÷ 5
mov  cl, al
sub  [di-6222h], cl         ; ← 再扣「剩餘 ÷ 5」
```

### 常數出處

| 常數 | 組語 | 值 |
|---|---|---|
| 黃金底 | `add ax, 12Ch` | 300 |
| 糧食底 | `add ax, 0BB8h` | 3,000 |
| 黃金上限 | `cmp [var_8], 1964h` | 6,500 |
| 黃金下限 | `cmp [var_8], 5DCh` | 1,500 |
| 忠誠度代價 | `sub ax, 1Eh` | 30 |
| 資源上限 | `mov ax, 0EA60h` | 60,000 |
| 倍率 | Real `0x83/0/0x2000` | 5 |
| 糧食除數 | Real `0x8E/0/0x1C40` | 10,000 |

`-6222h` = 省份 base（`-6235h`）+ `0x13` = **`+19` 人民忠誠度**，
與 `docs/spec/03` 對上。

## 3b. ✅ 忠誠度是兩段扣的 — **實機零誤差**

`docs/playtest/12` 量到的忠誠度變化，第一段的 `−30` 對不上：

| 省 | 徵稅前 | 徵稅後 | 差 |
|---|---:|---:|---:|
| 河南 | 41 | 9 | **32** |
| 湖北 | 79 | 40 | **39** |

補上第二段（剩餘 ÷ 5）就全對了：

```
河南  41 − 30 = 11  →  11 ÷ 5 = 2  →  11 − 2 = 9    ✓
湖北  79 − 30 = 49  →  49 ÷ 5 = 9  →  49 − 9 = 40   ✓
```

**兩個樣本零誤差。**

## 3c. ✅ `+32` bit 7 = 「已徵過稅」 — confirmed

`CONTEXT.md` §5.16 推翻「bit 2 = 已徵過稅」時留了一句：

> 「已徵過稅」那個詞條仍然存在，只是對應的旗標在別處，還沒找到。

**在 bit 7**（`or al, 80h`）。`4.15` 詞條 42 終於有了歸屬，
而 bit 2 是回合分流開關（`docs/re/14` §1）——兩者各歸各位。

## 3d. `sub_30794` 不是第二筆收入

`sub_2C6C6` 裡 `sub_30794` 被呼叫兩次，一度懷疑是第二筆收入。
看參數是**座標**（`0x145, 0x128` 與 `0x145, 0x13A`）加上收入值，
所以它是**把數字印在畫面上**。

**徵稅只有 `sub_303CD` 那一筆收入**——§4 的三個解釋因此少了一個。

## 3. ✅ 「+1500 出現兩次」的謎解開了

`docs/playtest/12` §3 記過：

> 樣本 2 與 3 是不同的省（人口、地價、忠誠度全不同），
> 黃金收入卻都是**整整 1,500**。這不像連續亂數，
> 比較像幾個離散結果之一。

**那是 clamp 的下限**（`5DCh`）。不是離散結果，是被夾住了。

## 4. ⚠️ 但代入實機樣本，機率對不上

河南人口 27,940,000：

```
Round(Sqrt(27,940,000) × 5) = Round(5285.8 × 5) = 26,429
Random(26429) + 300 → 平均 13,514 → 遠大於上限，**大多數時候應該是 6,500**
打到下限 1,500 需要 Random < 1,200，機率約 4.5%
```

規則層跑 200 個種子驗證：**10 次打到下限（5%）**，與推算吻合。

但實機三個樣本：

| # | 省 | 黃金收入 | 是否下限 |
|---|---|---:|---|
| 1 | 河南 | 4,855 | 否（中段）|
| 2 | 河南 | **1,500** | **是** |
| 3 | 湖北 | **1,500** | **是** |

**三次裡兩次打到 5% 的下限**，而且沒有一次是應該最常見的 6,500。
這與均勻亂數的期望嚴重不符。

### 三個還沒排除的解釋

1. **人口欄位的單位**。若 `+12` 存的不是「人」而是別的刻度，
   `Sqrt` 的結果會小一到兩個數量級，`Random` 的範圍就會小到
   幾乎總是打下限。⚠️ 但 `docs/spec/03` 用湖北 18,250,000 →
   畫面「1825 萬」驗過單位是「人」。
2. ~~那 440 行裡還有第二筆收入~~ → **已排除**（§3d：`sub_30794`
   是印數字不是收入）。仍可能的是 **`sub_2C6C6` 在呼叫 `sub_303CD`
   之前先動過 `Random`**——那會讓實際落點與我們的序列錯開。
3. **`Round` 的行為**：Turbo Pascal 的 `Round` 對 Real 是「.5 取偶」，
   但這裡輸入是連續值，影響應該可以忽略。

**沒有排除之前不宣稱公式對齊原版。** 規則層照反組譯實作
（`internal/game/recruit.go` 的 `Tax`），差異寫在函式註解裡。

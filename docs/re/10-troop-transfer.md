# 調動的執行層：`sub_1408F` / `sub_14F9A`

輸入檔：`WAR.EXE`（375,568 B，未打包）
SHA-256：`workplace/ida/WAR.EXE`（見 `docs/re/01` 的雜湊表）
位址：IDA linear address
日期：2026-08-01

`docs/mechanics/70-ai.md` 解出電腦的決策鏈**決定往哪一省調動**，
但沒解「調動實際做了什麼」。這份補上那一段，順帶推翻一條假說。

---

## 1. ⛔ 推翻：`狀態[-22Eh]` 不是「剩餘命令數」

`70-ai.md` 曾把它標成**強證據**：

> 一個逐格遞減、不同指令要求不同剩餘量的計數器，正是那個機制的形狀。
> **這是社群那條說法的第一個程式碼線索**，但仍未證實——沒有找到它遞減的地方。

**找不到遞減處，是因為它根本不遞減。** `sub_1408F` 把同一格當**陣列長度**用：

```asm
mov     ax, [bp+var_2]          ; i
shl     ax, 1                   ; ×2（word 陣列）
mov     di, [bp+arg_0]
add     di, ax
push    word ptr ss:[di-22Eh]   ; arr[i]  ← 拿來當「將領編號」
call    sub_349C1
```

`arr[0]`（也就是 `狀態[-22Eh]` 本身）是元素數，`arr[1..n]` 是將領編號
——標準的 Pascal 陣列寫法。取出來的值立刻餵給 `sub_349C1`（兵種人力權重）
與 `×33 + 0x7A7D`（將領記錄定址），**只可能是將領編號**。

### 為什麼舊結論看起來成立

四支函式檢查它 `== 1`、`>= 3`、`>= 4`、當分母，全都與「該省有幾個將領」
讀得通，與「還剩幾個命令」也讀得通。**兩個假說在那批證據上完全等價**，
是後來的定址方式把它分開的。

`70-ai.md` §6h 那道沒解的門檻因此也解了：

```
狀態[-236h] ÷ 狀態[-22Eh] ≥ 10000
```

= **平均每個將領兵力 ≥ 10,000**（半個滿員步兵師）。當時就寫了這個假說，
現在分母 confirmed，只剩 `-236h` 待驗。

### 社群那條「每省有命令數上限」怎麼辦

回到**未證實**。`CLAUDE.md` §1.5 的社群說法仍然可能為真，
只是這裡不是它的證據。**不要把它記回去。**

## 2. `sub_1408F(狀態, &旗標, 模式, 目標省)` — confirmed

```
狀態[-22Eh]      將領清單長度（見 §1）
狀態[-22Eh+2i]   第 i 個將領編號
狀態[-2]         我方勢力領袖（將領 ID）
狀態[+0Ah]       出發省
arg_6            模式 0..7
arg_8            目標省
*arg_2           回傳：有沒有調動成功
```

### 調動 = 改寫一個 byte

每個模式最後做的事完全一樣：

```asm
mov     cl, [bp+arg_8]          ; 目標省
mov     ax, 21h                 ; 33 = 將領記錄大小
mul     word ptr ss:[di-22Eh]   ; ×將領編號
mov     di, ax
mov     [di+7A81h], cl          ; [將領×33 + 0x7A7D + 4] = 目標省
les     di, [bp+arg_2]
mov     byte ptr es:[di], 1     ; 旗標
```

`0x7A81 - 0x7A7D = 4` = 將領記錄的**所屬省**欄位（`docs/spec/02`）。

> **兵力不會被拆分。** 原版沒有「分一半兵力過去」那種操作——
> 調動就是整個將領連人帶兵換一個省。這一點對規則層很重要：
> `docs/mechanics/20-military.md` 提過的「整編可在部隊間分配兵力」
> 是**另一個指令**，不是這裡。

### 兵力門檻一律寫成 `兵力 × 人力權重`

```asm
push    word ptr ss:[di-22Eh]   ; 將領
call    sub_349C1               ; → 1 / 人力權重
...
mov     ax, [di+7A8Eh]          ; 將領記錄 +17 = 兵力
call    @Real$q7Longint
call    @$brdiv$q4Realt1        ; 兵力 ÷ (1/權重) = 兵力 × 權重
call    @Round$q4Real
cmp     dx, 0
cmp     ax, 4E20h               ; == 20000
```

`0x7A8E - 0x7A7D = 0x11 = 17` = 兵力，與 `docs/spec/02` 的 `+17` 對上。

**`兵力 × 權重 == 20000` 就是「滿員」**，與兵種無關
——滿員數 = 20000 ÷ 權重（`docs/re/08` §4）。這是那條公式的
**第三個獨立印證**，而且來自完全不同的模組（政略調動，不是戰鬥）。

三道門檻：

| 常數 | 意思 | 用在 |
|---|---|---|
| `4E20h` = 20,000 | 正好滿員 | 模式 1/5/7 |
| `2710h` = 10,000 | 未達半滿 | 模式 2/3 |
| `1388h` = 5,000 | 未達四分之一滿 | 模式 4 |

換算回實際人數：

| 兵種 | 權重 | 滿員 | 半滿 | 四分之一 |
|---|---|---|---|---|
| 步兵 | 1 | 20,000 | 10,000 | 5,000 |
| 騎兵 | 2 | 10,000 | 5,000 | 2,500 |
| 砲兵 | 10 | 2,000 | 1,000 | 500 |
| 裝甲兵 | 100 | 200 | 100 | 50 |

## 3. 八個模式 — confirmed

`arg_6` 是四段互斥的 `cmp al, N`。**差別全在挑誰，動作一模一樣。**

### 3a. 模式 0 與 6：無條件

```
模式 0：count == 1 → 動 arr[1]
        否則        → for i = 1 to count-1
模式 6：            → 動 arr[1]
```

⚠️ **模式 0 的迴圈跑到 `count-1`，最後一個留下。** 這不是我們的選擇，
是原版寫死的。可能是「留一個守家」，也可能是 off-by-one——
沒有證據能分辨，所以**照抄並標記**（`CLAUDE.md` §1）。

### 3b. 模式 1/5/7：只調滿員的

```
進入條件：(count > 1 且 模式 ∈ {1,7}) 或 模式 == 5
         且 sub_5A881(目標省) < 100

i = 0
loop:
  i++
  if 兵力[arr[i]] × 權重 == 20000:
      arr[i].所屬省 = 目標省;  旗標 = 1;  目標省將領數++
  模式 1: if i == count-1: break
          if sub_306CF(目標省) ≥ 400000: break
  模式 5: if i == count: break
  模式 7: if i == count-1: break
  if 目標省將領數 == 100: break
```

**100 是目標省將領數的硬上限**（`cmp [var_6], 64h`）。
模式 1 多一道煞車：目標省兵力總和到 40 萬（`0x61A80`）就不再送。

### 3c. 模式 2/3：只調未達半滿的，從清單尾端往前

```
模式 2：額度 = min(5, count-1)，i 從 count 遞減到 2
模式 3：需 count > 2，i 只跑 count 與 count-1

跳過 arr[i] == 狀態[-2]        ; ← 勢力領袖本人不調動
if 兵力 × 權重 < 10000:  調動；額度--
```

模式 3 沒有額度上限（只有兩格可挑）。

### 3d. 模式 4：清單後半段裡低於四分之一滿的

```
count == 1 → 動 arr[1]
否則        low = Round(count / 2)        ; 48-bit Real 除法 + Turbo Pascal Round
            for i = count downto low:
                if 兵力 × 權重 < 5000:  調動
```

`Round` 是**四捨五入到偶數**（Turbo Pascal 語意），所以
`Round(5/2) = 2` 而不是 3。奇數清單長度上會差一格，
規則層的 `roundHalf` 照這個實作。

## 4. `sub_14F9A(狀態, 模式, 目標省)`：調動成功後做三件事 — confirmed

```asm
call    sub_1408F
cmp     [bp+var_1], 0
jz      短路
mov     cx, ss:[di-2]           ; 我方勢力
mov     dx, 25h                 ; ×37 = 省份記錄
mul     [bp+arg_4]              ; 目標省
mov     [di-6221h], cx          ; 省份[目標].+20 = 我方勢力
...
mov     byte ptr ss:[di-7], 1   ; 「已決定」旗標
```

1. **目標省的司令欄位改成我方勢力** — 這就是佔領無主省的機制。
   調動本身即佔領，不需要另一個指令。
2. 立起 `狀態[-7]`（決策鏈的「已決定」旗標），後面的步驟全部跳過。
3. `sub_34105` 重畫出發省與目標省。

`狀態[-2]` 因此 confirmed 是**我方勢力領袖的將領 ID**
——它被寫進省份記錄的司令欄位（`docs/spec/03` §2 的 `+20`）。

## 5. 「大軍集結」提示：兩道門檻不重疊是刻意的 — 強證據

調動段之後（只在模式 1/5/7 的路徑上）：

```
var_4 = (sub_306CF(目標省) < 250000)        ; ← 調動**前**算
...調動...
var_3 = sub_5B7DC(目標省, 我方勢力)          ; 目標省的第一個敵對鄰省
if sub_306CF(目標省) < 300000:  跳過        ; ← 調動**後**算
if var_3 == 0:                  跳過
if 省份[var_3].司令 != 1:        跳過
if var_4 == 0:                  跳過
→ 畫框 + 印勢力名 + 印省名 + DELAY
```

`< 250,000` 與 `≥ 300,000` 看起來矛盾，其實不是：**中間隔著調動**。
所以條件是

> 目標省原本兵力不到 25 萬，這次調動之後超過 30 萬，
> 而且它旁邊有一個司令為 **1** 的敵省 → 跳提示。

司令 1 在 `TOWN(1).DAT` 是 1926 年的玩家勢力（`docs/spec/03`），
所以這是**給玩家看的情報**：某某軍在某省集結了大軍。

⚠️ 標強證據不是 confirmed：「司令 == 1 就是玩家」在多勢力開局下
不一定成立，要等 DOSBox 實測（`docs/playtest/03` 的輸入問題還沒解）。

## 6. 順帶解出的兩支小函式 — confirmed

### `sub_5A881(省)` = 該省可用將領數

```
for id = 1 .. 將領總數:
    if 將領[id].+4  != 省:                continue
    if !(將領[id].+16 & 1):               continue
    if 將領[id].+14 != 省份[省].+20:      continue
    n++
```

### `sub_306CF(省)` = 該省可用將領的兵力總和（32-bit）

同樣三個條件，累加 `+17`。

**兩支的篩選條件一字不差**，所以「一個省的將領清單」有明確定義：
`+4` 相符、`+16` bit 0 立起、`+14` 等於該省司令。
規則層的 `RosterOf` 照這三條。

`sub_306CF` 開頭還有一段死碼：若 `省份[省].+32 & 0x40`
就把兩個 local 清零，但那兩個 local 之後沒被讀。編譯器沒優化掉，
**不影響行為**，記一筆免得下次又去追。

## 7. 還沒解的

- **清單的順序**。`RosterOf` 目前照將領表序，但原版的 `狀態[-22Eh]`
  陣列是在 `sub_15F3C` 裡填的，還沒讀。**模式 0/2/3/4/6 挑誰完全取決於順序**，
  所以這是宣稱「調動行為對齊原版」之前必須驗的一條。
- `狀態[-236h]`（32-bit，§1 那道門檻的分子）。
- 模式與決策鏈的對應：`70-ai.md` 記了三種調動用 4／1／0，
  但 2/3/5/6/7 是誰在用還沒對完。
- `sub_137AB(狀態, 目標省)`：`byte_6FE83` 立起時才呼叫。

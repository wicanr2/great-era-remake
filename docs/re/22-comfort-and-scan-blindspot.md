# 慰勞軍民全解，以及掃描 pattern 的系統性盲點

輸入檔：`WAR.EXE`（375,568 B，未打包）
日期：2026-08-01

`docs/re/19`／`20`／`21` 連續三輪用「掃欄位寫入點」排除慰勞軍民，
四條路都排掉了（省的民心、將領忠誠度、體力、士氣）。
**四條全錯——因為掃描 pattern 有洞。**

---

## 1. ⛔ 盲點：只掃了絕對定址

先前的 pattern 長這樣：

```
(mov|add|sub|inc|dec)\s+(byte ptr )?\[di\+7A9Ah\],     # 將領 +29 體力
```

`7A9Ah` = 將領陣列基址 `7A7Dh` + `1Dh`。這只涵蓋
**「基址 + 欄位偏移」直接寫死在指令裡**的形式。

`sub_3412B` 用的是另一種：

```asm
mov     ax, 21h
mul     [bp+var_2]              ; id × 33
mov     di, ax
add     di, 7A7Dh               ; ← 先把基址加進 di
mov     word ptr [bp+var_8], di
les     di, [bp+var_8]
add     byte ptr es:[di+1Dh], 0Ah   ; ← 偏移是純粹的 +1Dh
```

**基址先進 `di`，指令裡只剩欄位偏移。** 我的 pattern 一個都抓不到。

### 這與「用不存在的工具去量」是同一類錯

`CONTEXT.md` §5.17 記過：`xmodmap` 不存在，輸出 0 行，
被當成「keymap 是空的」。

這次是**過濾器本身有洞**：pattern 在其他欄位上都命中了
（所以看起來是好的），但它系統性地漏掉一整種定址形式。
`docs/re/20` §4 還拿它下過「城市數零寫入」的結論——
**那條結論現在也要重驗**。

> 「零命中」只有在**過濾器涵蓋所有可能形式**時才是證據。
> 驗證過濾器的方法不是「它在別處有命中」，
> 而是**主動找一個已知該命中的案例試它**。

## 2. 慰勞軍民做四件事 — confirmed

`sub_1C606`（指令 14）本身只畫畫面，實際效果在 `sub_3412B(勢力, 省)`：

```
for id = 1 .. 將領總數:
    if 將領[id].+16 != 1:     continue      ; 可用
    if 將領[id].+4  != 省:    continue
    if 將領[id].+14 != 勢力:  continue

    將領[id].+29 += 10                      ; 體力，夾到 100
    if 將領[id].+30 < 80:                   ; ← 士氣只有未達上限才加
        將領[id].+30 += Round(將領[id].+0 ÷ 5)   ; 帶兵能力 ÷ 5，夾到 80
    將領[id].+1 += 20                       ; 忠誠度，夾到 100

省份[省].+19 += 將領[勢力].+2 ÷ 10           ; 領袖的政治手腕 ÷ 10，夾到 100
```

| 效果 | 量 | 上限 |
|---|---|---|
| 將領體力 | +10 | 100 |
| 將領士氣 | +帶兵能力÷5 | **80** |
| 將領忠誠度 | +20 | 100 |
| 省的人民忠誠度 | +領袖政治手腕÷10 | 100 |

### 士氣上限是 80，不是 100

`cmp byte ptr es:[di+1Eh], 50h` —— `50h` = 80。

**與實機吻合**：`docs/playtest/08` 那五個將領的士氣是
74／67／42／54／30，**全部低於 80**。當時沒注意到這個上限，
現在回頭看是很強的旁證。

### 慰勞是徵稅的解藥

徵稅一次掉 30 + 剩餘÷5 的民心（`docs/re/18`），
慰勞回補 領袖政治手腕÷10。吳佩孚政治手腕 94 → 一次回 9 點。

**回補遠慢於消耗**——徵稅一次掉 32 點，要慰勞三四次才補得回來，
而每次都吃一個指令數。這就是徵稅「不能連著用」的機制根源。

## 4. 改進後的掃描方式

要涵蓋兩種形式：

```sh
# 絕對：[di+7A9Ah]
# 相對：es:[di+1Dh] / [di+1Dh]，配合先前的 add di, 7A7Dh
grep -E '(mov|add|sub|inc|dec)\s+(byte|word) ptr (es:)?\[di\+1Dh\],'
```

相對形式的偏移會與別的結構撞號（`+1Dh` 在省份記錄裡是別的欄位），
所以要**配合基址的來源**一起看，不能只 grep 偏移。

# RE-07 戰場幾何與部署：六角格、格編號、進場區

> 輸入檔：`WAR.EXE`（375,568 B）
> SHA-256：`11dbfcf24686ab7765f788b38514cefd2039d0f60b6bd517d89fb5a84c068015`
> 位址是 IDA database 的 linear address
> 日期：2026-08-01

這一份把四件事一起解開了，因為它們是同一條鏈上的環節：
單位記錄的 `+5` 存什麼、戰場座標怎麼算、地形圖塊怎麼取、部隊從哪裡進場。

---

## 1. 起點：執行期單位記錄的 `+5`

執行期的單位記錄是 33 bytes（`mov ax, 21h` / `mul <索引>`），基址 `0x7A7D`。
`+5`（`[di+7A82h]`）是整份記錄裡最熱的欄位——**423 次存取，其中寫入只有 14 次**。
大量查詢、極少修改，形狀像一個穩定的索引欄位。

那 14 次寫入裡，13 次寫 `cl`，1 次寫 `0FFh`。追 `cl` 的來源就找到答案。

---

## 2. `+5` 是戰場格編號（0..195）— **confirmed**

證據是 `sub_39B6E` 這一段：從部隊清單取出單位，讀它的 `+5`，直接當參數丟給繪圖函式。

```asm
mov     ax, 21h
mul     word ptr [di+750h]      ; 部隊清單（RE-05 的 +0x750，10 個槽）
mov     di, ax
mov     al, [di+7A82h]          ; 單位記錄 +5
push    ax
call    sub_50FF5               ; ← 畫這一格
```

而 `sub_50FF5` 拿到它之後第一件事就是 `mod 14` / `div 14`（見 §3），
第二件事是拿它去索引戰場地圖陣列。**能同時當座標與地圖索引的只有格編號。**

`0xFF` 是「不在場上」的哨兵：全程式 27 次比較 `+5`，**每一次都是與 `0FFh` 比**。

---

## 3. 六角格幾何 — **confirmed**

`sub_50FF5`（linear 0x124683）把格編號換成螢幕座標：

```asm
mov     al, [bp+arg_0]
cwd
mov     cx, 0Eh
div     cx
xchg    ax, dx
mov     [bp+var_2], ax          ; col = cell mod 14
...
div     cx
mov     [bp+var_4], ax          ; row = cell div 14
...
idiv    cx (cx=2)               ; col mod 2
cmp     ax, 1
jnz     短跳（偶數欄）
    mov ax, [bp+var_2]
    mov cl, 5
    shl ax, cl                  ; x = col * 32
    mov ax, 18h
    mul [bp+var_4]
    add ax, 0Ch                 ; y = row * 24 + 12   ← 奇數欄
```

整理成公式：

```
col = cell mod 14
row = cell div 14
x   = col × 32
y   = row × 24 + (col 為奇數 ? 12 : 0)
```

**奇數欄整體下移 12（正好半個格高）= column-staggered 六角格排列。**
`CLAUDE.md` §1.5 記的「戰鬥用六角格」原本只是社群說法，這是它的第一份程式碼證據。

### 尺寸與畫面互相印證

| 量 | 值 |
|---|---:|
| 一格 | 32 × 24 |
| 整張戰場 | 14 欄 × 32 = **448** 寬，13×24 + 12 + 24 = **348** 高 |
| BGI 模式 | 640 × 350 |

**348 差 2 px 就頂到畫面底部**，右邊剩 192 px 給資訊面板。幾何、素材尺寸、
畫面模式三者一致——任何一項解錯都不會這麼剛好。

## 4. 地形圖塊：整條繪製鏈 — **confirmed**

`sub_50FF5` 取圖塊的方式：

```asm
mov     al, [bp+arg_0]
call    near ptr sub_50151      ; 格 → 地形碼
mov     [bp+var_5], al
...
mov     dx, 198h                ; stride = 408
mul     dx
mov     di, ax
add     di, 90Eh                ; 圖塊陣列（1-based，故 base 是「首張 − 408」）
call    @PUTIMAGE$...
```

而 `sub_50151` 是這樣解碼的：

```asm
mov     ax, [di+796h]           ; 戰場地圖陣列，每格 u16
and     ax, 0FFFh               ; 取低 12 bit
cmp     [bp+var_4], 19h
jb      收工                     ; < 25 直接用
sub     [bp+var_4], 1Eh         ; − 30
cmp     [bp+var_4], 19h
jb      收工
loop:   sub [bp+var_4], 19h     ; 反覆 − 25
        cmp [bp+var_4], 19h
        ja  loop
```

**這正是 `docs/spec/04` 那條鐵路編碼 `v = 30 + 25×圖塊 + 地形` 的逆運算。**
那條公式當初是從全 39 省 7,644 格的統計推出來的；現在在程式碼裡找到了原始實作，
從「強證據」升級為 **confirmed**。

### 陣列來源都對上了

| 程式裡的陣列 | linear | 大小 | 來源 |
|---|---|---:|---|
| `[di+796h]` | `byte_64946` | `188h` = **392 B** = 196 × u16 | `nwmap.dat`，`Reset(f, 392)`，Seek 到當前省 |
| `[di+76F4h]` | `byte_6B8A4` | `0C4h` = **196 B** | `warpos.dat`，`Reset(f, 196)`，Seek 到當前省 |
| `[di+62A8h]` | — | 196 × u16 | 執行期的格佔用表 |
| `[di+91Eh]` | `byte_64ACE` | `0C4h` = **196 B** | 執行期，語意未解 |

四張表都是 196 格。**`0C4h = 196` 這個記錄大小直接寫在 `Reset` 的參數裡，不是猜的。**

### `NEWTERR.TPC` 的 stride 408

檔案 8,976 B ÷ 408 = **22 張，零餘數**，正好對上地物編號 1..22。
單張 = 388（BGI 32×24 四平面：`4 + 4×24×4`）+ **20**（`palt` chunk）。

也就是說：`CLAUDE.md` §3.3 記的「差額固定 +20」那一族，`+20` 不是額外資料，
而是每張圖自帶的調色盤；**遊戲把 palt 當成 stride 的一部分**，
putimage 只吃前 388 bytes，那 20 bytes 被整段跳過。

## 5. 部署：`WARPOS.DAT` 是戰場分區圖 — **confirmed**

`sub_41513`（linear 0x93380 起）把一個單位放上戰場：

```asm
記錄[+16] |= 4
記錄[+8]  = 1
var_1 = 0C3h                    ; 195，往下掃
loop:
    if byte[76F4h + var_1] != byte_6AB65:  continue   ; 這格不屬於攻方來源省
    if sub_55CEC(unit, var_1, 1) != 0:     continue   ; 周圍六格有敵人 → 換一格
    if word[62A8h + var_1*2] != 0:         continue   ; 已經有人站
    記錄[+5] = var_1                                   ; 單位 → 格
    word[62A8h + var_1*2] = unit                       ; 格 → 單位
    byte[91Eh + var_1] = 50h
    dec var_1
```

掃完一輪若沒放成功，會再跑一輪**放寬版**（跳過 `sub_55CEC` 那一關），
所以「找不到安全落點就硬塞」是原版行為，不是我們補的。

`sub_55CEC(unit, cell, 1)` 回傳的是**該格周圍六格裡敵方單位的數量**（見 §6），
所以第一輪的規則是「**落點旁邊不能已經站著敵人**」。

### `byte_6AB65` = 攻方的來源省 — 順手解開 RE-05 的最後 1 byte

`byte_6AB65` 就是 `.DT2` 記錄 `+468` 那個未解的位元組。它在 `sub_4F0E2` 被設定：

```asm
mov     ax, 21h
mul     word_64902              ; 攻方參戰單位清單的第一格（RE-05 +28）
mov     di, ax
mov     al, [di+7A86h]          ; 主將記錄 +9
mov     byte_6AB65, al
```

而它唯一的用途就是與 `warpos[格]` 相等比較（全部 9 處都是 `==`）。
`warpos` 的格值是省編號，所以 `byte_6AB65` 也是省編號 —— **攻方從哪一省打過來**。
`+9` 則是「這個單位屬於哪一省」。

### 資料驗證：每個分區恰 10 格，39 省零例外

拿河南（19）的 `WARPOS` 記錄攤成 14×14：

全 39 省掃過：**每一個鄰省的分區都恰好 10 格，零例外。**

湖北打河南時，從 195 往下掃到的第一個 26 是 **cell 186**（col 4, row 13）
→ 螢幕 (128, 312)，戰場的正下緣。攻方確實從自己那一側進場。

### 資料驗證：`+468` 確實是進場區裡的省

拿 `MEM_WAR.DAT` 全 39 筆的 `+468` 去比對該省的 `WARPOS` 分區：

| 結果 | 省數 |
|---|---:|
| 值落在該省的進場區裡 | **31** |
| 值為 0（該省沒有戰事）| 5 |
| 例外 | 3 |

三個例外都有已知來歷：省 15、17 的值是 `255`——那正是 `SPEC-03` 鄰省表的
「海洋／境外」哨兵；省 39（緬甸）的整筆記錄本來就是未初始化殘料
（RE-05 §2 記過，裡面有 8086 機器碼）。**有效樣本零違反。**

而且對得上劇情：河南（19）的 `+468` = 11 = 河北，正是張作霖系的地盤，
與 RE-05 §2 觀察到的「河南正被張作霖系攻打」一致。

### 這不是推翻 SPEC-01，是升級

`docs/spec/01` 原本說「`WARPOS.DAT` 每省一張 14×14，格值 = 省編號，
出現的其他省編號就是鄰省」——那是對的，而且鄰接對稱性 39/39 通過。
現在補上的是**它為什麼長這樣**：它首先是戰場的分區圖，鄰接關係是這張圖的**推論結果**，
不是它的定義。

同時 SPEC-01 標「尚未經反組譯確認」的 row-major 方向（`index = y*14 + x`，
x 由左至右、y 由上至下），現在由 `sub_50FF5` 確認。

## 6. 六角鄰接：位移表與邊界規則 — **confirmed**

`sub_55CEC` 遍歷鄰格的方式是 `cell + word[625Ah + (cell mod 2)×12 + dir×2]`，
`dir` 跑 **1..6**。因為每列 14 格是偶數，`cell mod 2` 恰好等於 `col mod 2`
——原版用了這個捷徑。

位移表由 `sub_4E65C` 在戰鬥開始時填好：

| dir | 方向 | 偶數欄 | 奇數欄 |
|---:|---|---:|---:|
| 1 | 左下 | −1 | +13 |
| 2 | 下 | +14 | +14 |
| 3 | 右下 | +1 | +15 |
| 4 | 左上 | −15 | −1 |
| 5 | 上 | −14 | −14 |
| 6 | 右上 | −13 | +1 |

兩組的**方向語意一致**，差別只來自「奇數欄整體下移半格」。
偶數欄的「左下」是 `−1`（同列左邊那格，但它下移了半格），
奇數欄的「左下」則要跨到下一列才是 `+13`——這正是 staggered 六角格的特徵。

### 邊界：`sub_510E0(a, b)` = a 與 b 是否六角相鄰

```
if b 不在 0..195 或 a 不在 0..195:  →  0
依 b 的欄奇偶與是否在左右緣，列出合法鄰居集合，看 a 在不在裡面
```

| 情況 | 合法鄰居 | 數量 |
|---|---|---:|
| 偶數欄，`col == 0` | `b±14`、`b+1`、`b−13` | 4 |
| 偶數欄，其他 | 六個全有 | 6 |
| 奇數欄，`col == 13` | `b±14`、`b−1`、`b+13` | 4 |
| 奇數欄，其他 | 六個全有 | 6 |

**上下邊界不另外檢查**，靠開頭那道 `0..195` 的範圍測試擋掉；
左右邊界才需要欄位檢查，因為 `col 0 往左`／`col 13 往右` 會跨到別的列去。

而且原版只檢查「偶數欄的左緣」與「奇數欄的右緣」——因為欄號 0..13 裡
偶數欄永遠碰不到右緣 13、奇數欄永遠碰不到左緣 0。**分類是精確的，不是漏寫。**

### `sub_55CEC` 在數什麼

```
自己的陣營 = 單位[arg_4].+14
計數 = 0
for dir = 1..6:
    n = 鄰格(cell, dir)
    if 相鄰 且 佔用表[n] != 0 且 單位[佔用表[n]].+14 != 自己的陣營:
        計數++
```

回傳值就是這個計數——**該格周圍敵方單位的數量**，形狀像 ZOC 或被包圍程度。
`+14` 是 word，用相等比較判「同一方」，**假說是勢力或主將 ID**，未證實。

`arg_0` 決定數到多遠：

| `arg_0` | 掃描範圍 | 位移表 |
|---:|---|---|
| 1 | 距離 1 的 6 格 | `word[625Ah + (cell mod 2)×12 + dir×2]`，dir 1..6 |
| 2 | 距離 1 的 6 格 **＋** 距離 2 的 12 格 | 再加 `word[6272h + (cell mod 2)×24 + dir×2]`，dir 1..12 |

距離 2 的那 12 個位移由 `sub_4E65C` 把距離 1 的位移**兩兩相加**算出來
（`word_6A424 = word_6A40C + word_6A418` 等等），所以它不是另一份手寫表，
是從六鄰位移推導的。射程 2 的東西（砲兵？「協同攻擊」？）大概用得上它，
**呼叫端尚未追**。

## 7. 移動與機動力 — **confirmed（骨架）／未知（成本公式）**

`sub_4A1C0(成本, 單位, 方向)` 是「走一格」：

```asm
sub_50FF5(單位.+5)                    ; 重畫舊格，把單位擦掉
sub_58172(單位)
word[62A8h + 舊格*2] = 0              ; 離開佔用表
byte[91Eh + 舊格] = byte[9E2h + 舊格] ; 還原覆蓋層
單位.+5 += word[625Ah + (舊格 mod 2)×12 + 方向×2]
單位.+7 -= 成本                        ; 扣機動力
word[62A8h + 新格*2] = 單位
```

呼叫端 `sub_4ABFD` 先過三道 gate：

1. `sub_510E0(目標格, ...)` —— 六角相鄰且在界內
2. `sub_4A583(目標格, 單位)` —— 該格可否進入，見下
3. `單位.+7 >= 成本` —— 機動力夠不夠

### `+6`／`+7` 是機動力上限與剩餘 — 這下有證據了

RE-05 只知道「`+7` 每回合回到 `+6`」，是個典型的「當前值 = 最大值」重置，
但不知道是什麼量。現在移動函式直接對 `+7` 做減法、呼叫端拿它跟成本比大小
——**`+7` 就是剩餘機動力，`+6` 是上限**，對上 `3.15` 詞條 51「機動力」。

### 順帶：`byte_91E` 是覆蓋層，`byte_9E2` 是底圖

移動時 `byte_91E[舊格] = byte_9E2[舊格]`——**單位離開就從底圖還原**。
兩個陣列相鄰（`0x91E + 196 = 0x9E2`），各 196 格。
部署時寫進 `byte_91E` 的 `0x50` 是「這格有單位」的標記。

底圖 `byte_9E2` 裝什麼仍未解，但至少知道 `byte_91E` 不是靜態資料，
而是**會被單位進出改寫的即時層**。

### `sub_4A583`：長城會阻隔，某些單位能穿越 — **confirmed**

```
可進入 = true
if 單位.+21 != 1 and sub_5867E(格) != 0:
    可進入 = false
```

而 `sub_5867E(格)` 只有一件事：解出該格的地形碼，回報它是否落在
**12 ≤ 碼 ≤ 21**。

`docs/mechanics/01-vocabulary.md` §1 已經記過：地形碼 1–11 有詞條
（平原、丘陵、河海、森林、城市、高山、沙漠、橋樑×2、高原、關口），
**12–22 沒有詞條，視覺上是長城各段**。現在阻隔範圍正好是 12..21。

資料也對得上：**12..21 只出現在省 7、10、11、12、14、15、16、17、18**
——全部是北方省份，正是長城沿線，總共 89 格。

⚠️ **22 不在阻隔範圍內**，而它只出現 3 格（省 12 一格、省 17 兩格）。
長城上的通行點是最自然的解釋，但沒有證據，**不定名**。

這也讓原版詞表的兩個詞落地了：「**阻隔**」就是這條規則，
「**穿越**」就是 `+21 == 1` 的那條例外（`2.15`，`01-vocabulary.md` §2）。

#### `+21` 是兵種編號 — **強證據**

`+21`（`[di+7A92h]`）是記錄裡第三熱的欄位（134 次存取），
**全程式沒有任何常數寫入**——代表它是隨記錄一起從檔案載入的固有屬性。
比較的常數分佈：

| 值 | 比較次數 |
|---:|---:|
| 4 | 44 |
| 6 | 22 |
| 1 | 22 |
| 5 | 12 |

小整數的列舉、固有不變、而且政略層（`sub_1629E`）也拿它分類計數
——**兵種是最合理的解讀**（詞表列了步兵、砲兵、騎兵、裝甲兵、游擊隊）。
但**哪個號碼對哪個兵種沒有證據**，不定名。

### 成本表未解

呼叫端把成本從一個以**方向**為索引的 word 陣列取出來
（`[bp+di+var_112]`，`di = 方向×2`），那張表在移動前算好。
IDA 把那塊 stack 空間同時當成字串緩衝顯示，沒能乾淨地分離出填表處。
**成本大概與目標格的地形有關，但沒有追到，不寫進規則。**

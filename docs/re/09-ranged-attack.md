# RE-09 遠程攻擊：兵種 4 有射程，而且不吃反擊

> 輸入檔：`WAR.EXE`（375,568 B）
> SHA-256：`11dbfcf24686ab7765f788b38514cefd2039d0f60b6bd517d89fb5a84c068015`
> 位址是 IDA database 的 linear address
> 日期：2026-08-01

`docs/playtest/04` §3 記了一個實跑暴露的疑點：戰損的「任一方是兵種 4 時
F 完全不受損失」讀起來像「兵種 4 打不動人」。

追 `sub_530B4` 的呼叫端解開了——**而且答案完全不是原本猜的方向**。

---

## 1. `sub_42C8F` 的開頭：一段遠程攻擊的守門

```
if 單位[arg_4].+21 == 4:                          ; arg_4 是兵種 4
    if sub_42BC3(arg_2, arg_4):                   ; arg_2 在 arg_4 的攻擊範圍內
        if 地形(arg_4.格) != 4（森林）:
            if 單位[arg_4].+8 == 0 且 word_6493C < 1388h:
                sub_42B56(arg_4)                  ; 顯示訊息後結束
                return
            sub_57B15(arg_2, arg_4)               ; 遠程攻擊
            ...
```

四個條件疊在一起，指向同一件事：**兵種 4 可以攻擊不相鄰的目標**。

### `sub_42BC3(target, unit)` = 目標在不在攻擊範圍內 — **confirmed**

```
sub_58854(&範圍表, 單位[unit].+31, unit)   ; 產生一張最多 10 格的表
for i = 1..10:
    if 單位[target].+5 == 範圍表[i]:  → 命中
```

`sub_58854`（494 行）拿單位所在的格拆成 `col`／`row`，再依 `+31` 填一張
格子清單，空位填 `0FFh`。

⚠️ **`+31` 是「射程」還是「朝向」未定**——`sub_58854` 太長還沒讀完。
兩者都能產生一張格子清單，行為差異在「是一個範圍還是一條射線」。
**不定名。**

## 2. E／F 的對應訂正 — 這推翻了 `docs/playtest/04` §3 的猜測

呼叫鏈是：

```
sub_42C8F(arg_2, arg_4)
  → sub_530B4(結果, arg_2, arg_4)
    → sub_5301B(&損失B, &損失A, arg_2, arg_4)
      → sub_51D68(&損失A, &損失B, 0, 0, 1, arg_2, arg_4)
                                          ↑E     ↑F
```

**發動遠程攻擊的那個兵種 4 單位是 `arg_4`，也就是 F。**

所以：

> **F = 發動攻擊的一方，E = 被攻擊的目標。**

而戰損規則「任一方是兵種 4 時 F 完全不受損失」的意思就變成：

> **遠程攻擊者不吃反擊。**

這讀起來完全合理，而且是戰棋裡砲兵的標準待遇。

### `docs/playtest/04` §3 猜錯了什麼

那份筆記猜「如果 A 其實是守方，特例就變成『兵種 4 防守時攻擊者打不動它』」。
**方向猜反了**：不是守方免疫，是**攻擊方免疫反擊**。

會猜錯是因為把「F 不受損失」直覺讀成「F 是被打的那個」。
實際上兩個參數在原版裡沒有攻守的內建語意，角色**由呼叫端決定**——
`sub_42C8F` 開頭那段還特地檢查 `arg_4.+8 == 0`（arg_4 是守方），
如果 arg_4 永遠是某一方就不必檢查了。

## 3. 兵種 4 是遠程兵種 — **強證據**

四條獨立的線索指向同一個結論：

| 線索 | 出處 |
|---|---|
| 有攻擊範圍檢查（`sub_42BC3`）| 本篇 §1 |
| 攻擊時不吃反擊 | `docs/re/08` §5a |
| **森林不能發動**（`地形 != 4`）| 本篇 §1 |
| 地形表裡兵種 4 在森林的攻擊係數是 **1**（全表最低）| `docs/re/08` §6b |

最後兩條是**兩處獨立的程式碼都說「森林擋遠程」**——一處是明寫的守門條件，
一處是資料表裡的數值。這種跨處一致比任何單一證據都硬。

配上 `docs/re/08` §4c 的戰力權重 10（四個兵種裡第二高）與
`docs/re/08` §6b 的「開闊地攻擊 5（×2.5）」，兵種 4 的形象是
**開闊地上射程內壓制、進了森林就廢掉**。

⚠️ 仍然**不定名為「砲兵」**。原版詞表有「砲兵」（`2.15` 128）也有
「炮擊」「炮轟」，但沒有任何一處把詞條與兵種編號連起來。
`CLAUDE.md` §9：推論標籤要誠實。

## 4. 彈藥門檻 5000 — **confirmed**

```asm
cmp     byte ptr [di+7A85h], 0      ; +8 == 0，這個單位是守方
jnz     short 繼續攻擊
cmp     word_6493C, 1388h           ; 守方彈藥 < 5000
jnb     short 繼續攻擊
push    [bp+arg_4]
call    sub_42B56                   ; 顯示訊息後結束，不攻擊
```

`word_6493C` 是**守方帶的彈藥**——`docs/re/05` §2 解過 `+0..+7` 是
攻守雙方各自的黃金／糧食／彈藥／燃料，兩兩相加寫回省份記錄；
`word_6493A`／`word_6493C` 就是那一對裡的彈藥。

所以：**守方的兵種 4 在彈藥低於 5,000 時放棄遠程攻擊。**
`sub_42B56` 只做繪圖與 `DELAY`，是顯示一則訊息。

⚠️ 這條**只檢查守方**（`+8 == 0`）。攻方的兵種 4 沒有這道彈藥檢查，
或者檢查在別處，**未追**。

## 7. 2026-08-10 追加：範圍幾何與三次戰損呼叫已閉合

### 7.1 `sub_58854`（`58854h`）— 已證實的方向基底與過濾

`sub_58854` 以單位所在格和 `+31` 的方向值建立最多 10 個候選格，輸出空位先填
`0FFh`。六個方向的第一個基底偏移可直接由 `58854h` 內的加減法讀出：

| 方向 | 第一個基底（相對格索引） |
|---:|---:|
| 1 | `+0Ch` |
| 2 | `+1Ch` |
| 3 | `+10h` |
| 4 | `-10h` |
| 5 | `-1Ch` |
| 6 | `-0Ch` |

候選生成會呼叫 `sub_55632`（`55632h`）的 mode 4 鄰格展開，並以 `sub_510E0`
（`510E0h`）做格位合法性檢查；地形 6（高山）在該模式被排除，來源地形 4（森林）
則在 `sub_58854` 入口拒絕。`sub_42BC3`（`42BC3h`）仍逐項比對最多 10 個 u16
候選格，因此「兵種 4 可攻擊非相鄰目標」已不只是方向推論。

**仍未知：** `sub_58854` 的邊界分支如何處理跨列／跨邊界，以及 `+31` 在每個呼叫端
是方向還是更高階射程狀態；本次 remake 只移植已證實的基底、森林／高山 gate 和
最多 10 格上限，邊界遇到無法證實的索引即 fail-closed。

### 7.2 `sub_57B15`（`57B15h`）— 三次 `sub_51D68`，只扣目標

`sub_42C8F`（`42C8Fh`）通過射程與森林 gate 後呼叫 `sub_57B15`。後者的固定流程是：

1. 先做場景／動畫狀態設定（不納入規則層）。
2. 以 `var_1 = 1..3` 呼叫三次 `sub_51D68`（`51D68h`），每次旗標為
   `argA=1`、`argC=1`、`arg8=0`。
3. 將三次累計的損失從目標 `[+7A8Eh]` 扣除，再檢查目標是否潰敗；沒有對
   發動遠程攻擊者做同等兵力扣除。

`sub_51D68` 的 `arg_E` 是目標 E、`arg_10` 是發動者 F；`argA=1` 會對 E→F 的
防守值套用地形倍率（鐵路 2、丘陵／關隘 2、城市 3，其餘 1），`argC=1` 且
`arg8=0` 會先由 `sub_51844`（`51844h`）檢查彈藥 word 是否為零。戰損公式仍沿用
`sub_51972`／`sub_51B94` 的已解出分支；本輪沒有把未知的動畫、寄存器或音效副作用
混進規則層。

`internal/game.BattleSim.EngageRanged` 現在依這條證據執行「單次戰損 × 3、只寫回
目標」；`cmd/dsds` 的攻擊目標表只對兵種 4 追加非相鄰候選，近身目標仍走既有
`Engage`。這是**規則層可驗證切片**，不是完整六種攻擊方式或完整玩家提示的完成宣告。

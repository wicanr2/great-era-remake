## 1. 找法：追誰改動兵力

`MAN(N).DAT` 的 `+17` 是兵力 u16（`docs/spec/02`），執行期記錄同一格是
`[di+7A8Eh]`。全程式對它做 `sub` 的只有 6 處，其中三處在戰鬥段。

`sub_530B4` 是最直接的一支：

```asm
sub_5301B(&損失B, &損失A, A, B)     ; 算出雙方戰損
mov     cx, [bp+var_2]
mul     [bp+arg_6]                  ; 33 × B
sub     [di+7A8Eh], cx              ; 單位[B].兵力 -= 損失B
mov     cx, [bp+var_4]
mul     [bp+arg_4]                  ; 33 × A
sub     [di+7A8Eh], cx              ; 單位[A].兵力 -= 損失A
sub_517BE(A, B)
sub_52EEA(結果, A, B)
```

**一次交戰同時扣雙方的兵力**——不是單向傷害。

---

## 2. `sub_5301B` 是編排，不是公式

它依序呼叫繪圖／動畫／音效，最後才是算式：

```
sub_528EE(2, A, B)
sub_51399(0, A.格, B.格)
sub_5A3B2(5, B) / sub_5A3B2(5, A)
sub_51EC0(1, B) / sub_51EC0(1, A)
sub_51F19(1, B) / sub_51F19(1, A)
sub_51D68(&損失A, &損失B, 0, 0, 1, A, B)     ← 這支才算
```

⚠️ `sub_51F19` **也會扣 `+17`**（linear 0x126699）。所以兵力不只在
`sub_530B4` 那兩行被改，這條鏈上還有別的扣減點，**尚未追**。

## 3. `sub_51D68`：戰力怎麼算 — **confirmed（結構）／未讀（係數）**

```
sub_51D68(&損失A, &損失B, arg_8, arg_A, arg_C, E, F):
    *損失A = 0; *損失B = 0

    var_4 = Round( Real(sub_5A0B9(F)) × sub_50600(F) ÷ sub_50655(E) )
    var_8 = Round( Real(sub_5A0B9(E)) × sub_50600(E) ÷ sub_50655(F) )
```

兩式對稱，E／F 對調。**`sub_5A0B9` 是強度的主項**（337 行，未讀），
另外兩支是修正係數：

| 函式 | 算式 | Real 常數 |
|---|---|---|
| `sub_50655(u)` | `1.0 + 0.25 × (sub_503BB(u, u.格) − 1)` | `0x007F`→0.25、`0x0081`→1.0 |
| `sub_50600(u)` | `0.5 × sub_501A3(u, u.格)` | `0x0080`→0.5 |

三個常數都是 Turbo Pascal 的 48-bit `Real`（exponent bias 129，尾數全 0
所以尾數部分是 1.0）：

```
0x7F = 127 → 2^(127−129) = 0.25
0x80 = 128 → 2^(128−129) = 0.5
0x81 = 129 → 2^(129−129) = 1.0
```

`sub_503BB` 與 `sub_501A3` 都吃「單位 + 它所在的格」，**未讀**。

### 3a. 地形加成 — **confirmed**

`var_8` 算完之後依 **E 所在格**的地形放大：

```asm
if arg_A != 0:
    if 有鐵路(E.格):              var_8 += var_8          ; ×2
    else 依地形:
        2（丘陵）or 0Bh（關口）:   var_8 += var_8          ; ×2
        5（城市）:                var_8 += var_8 × 2      ; ×3
```

| 地形 | 倍率 |
|---|---:|
| 有鐵路（先問，問到就不看地形）| **2** |
| 丘陵、關口 | **2** |
| 城市 | **3** |
| 其餘（含高山、河海）| 1 |

**這是「地形影響防禦」的第一份程式碼證據。** `CLAUDE.md` §1.5 記的是社群
說法（oracle 最低位階），現在有了出處——而且真正的內容比社群說法具體：
只有三種地形有加成，城市最高，而**高山與河海一點加成都沒有**。

⚠️ **加成有開關。** `arg_A` 為 0 時整段跳過，而 `sub_5301B` 那條呼叫路徑
傳的正是 **0**。另一個呼叫端 `sub_483A5+1BC` 還沒讀。
所以「什麼時候算地形加成」**尚未確定**——不要假設它總是生效。

### 3b. 4 倍差距會走不同的路 — **confirmed（分歧）／未讀（兩邊各算什麼）**

```asm
if var_8 × 4 <= var_4:   sub_51972
elif var_4 × 4 > var_8:  sub_51B94
else:                    sub_51972
```

整理：**任一方的戰力 ×4 還追不上對方，就走 `sub_51972`；
雙方都在 4 倍之內才走 `sub_51B94`。**

兩支的戰損算法不同（224 行／184 行），**都還沒讀**。
詞表的「崩潰」「敗逃」「打敗」（`2.15`）很可能對應一面倒那條，
「肉搏戰」（`3.15` 50）對應勢均力敵那條——**但沒有證據，不定名**。

`arg_C != 0 且 arg_8 == 0` 時還會先跑 `sub_51844`（98 行，未讀）。

## 4. `sub_5A0B9`：攻擊力公式 — **confirmed**

這是戰力的主項，337 行，裡面有**七個 Turbo Pascal 48-bit Real 常數**。
全部解出來都是整齊的整數——這本身就是「格式沒解錯」的證明。

### 4a. `20000` 找到了

`CLAUDE.md` §1.5 記過：「`20000`／`10000`／`2000`／`200` 這四個滿員數是
很好的 grep 起點，**但搜不到是正常的**（可能是公式算出來的）。」

它確實搜不到——因為它是編碼成 48-bit `Real` 的：

```asm
mov     cx, 8Fh
xor     si, si
mov     di, 1C40h
call    @$brdiv$q4Realt1
```

6 個 bytes 是 `8F 00 00 00 40 1C`。解碼：

```
exponent 0x8F = 143  →  2^(143−129) = 2^14 = 16384
尾數 0x1C, 0x40 → 1.0011100 0100 0000₂ = 1.220703125
16384 × 1.220703125 = 20000.0
```

**bytes 裡沒有 `20 4E`（20000 的小端），也沒有十進位字串。**
grep `20000` 或 `4E20` 一輩子都不會中。這是 `CLAUDE.md` §7 第 2 條
「掃常數，不要掃結果」最漂亮的一個案例——那條規則原本講的是
「觀察值是公式算出來的」，這裡是更進一步的「常數本身被編碼掉了」。

### 4b. 七個 Real 常數

| 暫存器 `CX:SI:DI` | bytes | 值 | 用在哪 |
|---|---|---:|---|
| `0084 0000 2000` | `84 00 00 00 00 20` | **10** | 第一步的分母 |
| `008F 0000 1C40` | `8F 00 00 00 40 1C` | **20000** | 第一步的總分母 |
| `0084 0000 1000` | `84 00 00 00 00 10` | **9** | sqrt 那一步 |
| `0087 0000 2A00` | `87 00 00 00 00 2A` | **85** | F30 那一步 |
| `0087 0000 2000` | `87 00 00 00 00 20` | **80** | Ability 那一步 |
| `0081 0000 4000` | `81 00 00 00 00 40` | **1.5** | 勢力加成 |
| `0083 0000 2000` | — | **5** | （RE-05 已解，每回合衰減）|

### 4c. 兵種權重 — 順帶確認 `+21` 的值域

```asm
+21 == 1 → w = 1
+21 == 4 → w = 0Ah  (10)
+21 == 5 → w = 64h  (100)
+21 == 6 → w = 4
```

**只認這四個值**，其餘落到未初始化的 stack 值——所以 `+21` 的值域就是
`{1, 4, 5, 6}`，與先前從比較次數統計出來的完全一致（`docs/re/07` §7）。

⚠️ 一個**觀察，不是結論**：權重 1／10／100 與社群傳的滿員數
20000／2000／200 成反比，三項吻合；但權重 4 對應的 5000 與社群說的
「騎兵師 10000」對不上。社群數值不一定出自 1992 原版（`CLAUDE.md` §4），
**不拿來替兵種定名**。

### 4d. 完整公式

```
w = 兵種權重(+21)

S = Round( (F30 + Ability + 3×F19 + 5×F20) / 10 × Force × w / 20000 )
S = Round( S × sqrt(F29) / 9 )
S = Round( S × F30 / 85 )
S = Round( S × Ability / 80 )

; 名將加成（整數運算，不是浮點）
Ability == 100:  S += (S/3)×2      ; ×5/3
Ability >= 98:   S += S >> 1       ; ×1.5
Ability >= 95:   S += S >> 2       ; ×1.25
Ability >= 90:   S += S / 6
Ability >= 85:   S += S >> 3       ; ×1.125

; 後期將領
if byte_6FE88 != 1 and 將領ID >= 6Bh(107):  S += S >> 2

; 勢力／難度加成，見 §4e
; 兵種 5 最後再翻倍
if +21 == 5:  S += S
```

其中 `Ability` = `+0`（`MAN(N).DAT` 的第一個能力值，`docs/spec/02`），
`Force` = `+17`（兵力）。`+19`／`+20`／`+29`／`+30` 的**語意仍未解**
——公式用得到它們，但不知道畫面上叫什麼。

**每一步都有 `Round`，順序不能重排**：中途的截斷會累積。

⚠️ 「後期將領」那條在原版資料上**可能永遠不成立**：第二、三期的名表只有
106 位將領，ID 107 以上不存在。照抄是為了忠實，不是因為它會生效。

### 4e. 勢力／難度加成 — 這是 `byte_6FFCA` 的第一段語意

```asm
if sub_5C7FE(單位.+14):                 ; 效忠的勢力是十大勢力之一
    d = byte_6FFCA & 70h
    if d == 10h:                        S ×= 2
    elif d == 20h:                      S = Round(S × 1.5)
    elif d == 40h and 單位.+14 == 1:     S = Round(S × 1.5)
else:
    if 單位.+14 == 1 and byte_6FE88 == 1:  S = Round(S × 1.5)
```

`byte_6FFCA` 的 **bit 4–6 是一組三選一的加成設定**。CONTEXT worklist #6d
記過「`byte_6FFCA` 各位元語意未知」，現在解出這一段。

`+14 == 1` 是**蔣中正**（`docs/spec/03` §3：`TOWN(1)` 的司令欄位解出來
就是 1926 年的割據圖，ID 1 = 蔣中正）。公式裡有兩處專門為他開的分支。

詳細的 AI 意義記在 `docs/mechanics/70-ai.md` §6c。

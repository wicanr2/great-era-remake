# `+32` bit 2 是回合分流開關；決策鏈最後一步也是調動

輸入檔：`WAR.EXE`（375,568 B，未打包）
位址：IDA linear address
日期：2026-08-01

兩件事：一個被推翻的旗標語意，以及**兩條決策鏈的最後一支未讀函式**。

---

## 1. `+32` bit 2 = 本回合已處理過 — confirmed

`docs/spec/03` §2b 原本標「**假說：本月已徵過稅**」，依據是 `4.15`
詞條 42 有「已徵過稅」，加上徵稅每月限一次正好需要一個旗標。

四處程式碼把它講清楚了：

| 函式 | 動作 | 意思 |
|---|---|---|
| `sub_10193` | `or al, 4` | 玩家在這個省下完命令 |
| `sub_13D23` | `or al, 4` | 電腦開始跑這個省 |
| `sub_10AB5`（主迴圈）| `and al, 4` → 非 0 就跳過 | **立起來就不進玩家選單** |
| `sub_383EF` | `and al, 0FBh`，對全 39 省 | 回合重置 |

```asm
; sub_10AB5，進玩家選單之前
mov     ax, 25h
mul     word_648E2              ; 當前省
mov     di, ax
mov     al, [di-6215h]          ; +32
and     al, 4
or      al, al
jnz     short loc_10F52         ; ← 跳過 sub_10193
```

**它是玩家與電腦的分流開關。**

### 原本的統計觀察在兩種解釋下都成立

`SAVE(1)` 25 省設它、`SAVE(2)` 4 省、無主省一律沒設——

- 讀成「已徵過稅」：徵過稅的省數，無主省沒人徵
- 讀成「已處理過」：存檔當下那一輪已經輪過的省數，
  無主省兩條路徑都不進

**同一批數字，兩種解釋都通。分辨它們的是程式碼，不是統計。**

「已徵過稅」那個詞條仍然存在，只是對應的旗標在別處，還沒找到。

## 2. `sub_15CE3`：決策鏈的最後一步——還是調動 — confirmed

`docs/re/12` 下「決策鏈六步全是調動」的結論時，`sub_15CE3`（302 行，
前線鏈最後一步）**還沒讀**，只知道它呼叫 `sub_14F9A`。現在讀完了。

```
sub_5A907(..., &count, &first, 我方領袖所在省)
if count != 1:            return          ; ← 必須剛好一個
if !sub_5A9F6(first):     return

清單[1] = first
sub_5A907(..., &count2, 清單, first)      ; 取 first 的鄰省清單

依 sub_5B983（戰力總和）排序，另帶一個 var_1B == 1 的條件

if 清單[1] == 當前省:  return
sub_5BF74(0, 我方勢力, 4, 清單[1], 當前省)   ; ← 權重模式 4
if 路徑長 == 1 且 !sub_5B76E(節點[1], 節點[2]):  return
if !sub_5B76E(當前省, 節點[路徑長]):             return
if 省份[節點[路徑長]].+32 & 40h:                 return   ; 交戰中
sub_14F9A(狀態, 1, 節點[路徑長])                 ; ← **調動模式 1**
```

手法與 `sub_14CCF`（`docs/re/11` §5）一模一樣：**尋路取第一步**，
調動只能走一格。

### 新的一個權重模式

`sub_5BF74` 的 `arg_4` 到目前見過三個值：

| 值 | 用在 |
|---|---|
| 4 | `sub_15CE3`（本篇）|
| 10 | `sub_5BA56` 那條分支 |
| 11 | `sub_36BC7`（`70-ai.md` §6l）|

三支權重函式都還沒讀，所以「路徑成本怎麼算」仍是未知。

## 3. 這讓「電腦不主動攻打」的證據補齊了

`docs/re/12` §6 標**強證據**時列了兩個保留：

## 4. 順帶：兩支取清單的函式

| 函式 | 做什麼 |
|---|---|
| `sub_5A907(..., &count, &清單, 省)` | 掃該省鄰省表前 7 格，跳過 `0`／`0FFh`，收集成清單 |
| `sub_5A9F6(省)` | 數該省鄰省表裡有效的格子數，再做進一步判斷（尾段未讀）|

`sub_5A9F6` 的定址基底是 `9DCBh + 省×37 + i + 0x15`，
`0x15` = 21，配上 `i` 從 1 起跳正好落在**鄰省表 `+22`**——
與 `SPEC-03` 一致。

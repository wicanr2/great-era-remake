## 兩點與規格無關、但派工前要知道的事

1. **北伐時期人物與維基〈19XX年中国〉系列是絕配。** 那一系列逐日引郭廷以《中華民國史事日誌》，
   與 gpost 的公報任免令是同一批史料的兩種整理，**因此經常在同一天對上**——本批四篇 `high`
   全部來自這個機制。查 `partial` 的北伐人物時，**先查〈19XX年中国〉再查部隊沿革條目**，
   投報率比反過來高得多。這一點 batch-01 沒撞到（那批橫跨三期，抗戰時期沒有對應的逐日條目）。

2. **一批 10 篇的實際成本（本批實測）**：查證約 65%、成文與回查約 25%、品質閘約 10%。
   工具面：gpost 用 `curl` + 剝標籤直接抓；維基一律走 MediaWiki API 的
   `action=parse&prop=wikitext`（§9.6 的建議正確，`prop=extracts` 對模板多的條目會回空），
   全文檢索用 `list=search` 搭 `insource:"姓名"`——**`insource:` 比普通關鍵字搜尋準得多**，
   `#38 李群`、`#29 張言傳` 這種與常用詞撞名的，普通搜尋回的全是雜訊。
   ⚠ MediaWiki API 連續請求會被限流（回空 JSON 且無錯誤訊息），本批加了重試與間隔才穩定；
   **限流的症狀是「查無此條目」，與真的查無完全一樣**，第一輪因此誤判過一次
   （`#10 馮軼裴` 第一次查 gpost 回空，重跑就有 5 筆）。查到零筆時一律重跑一次再下結論。

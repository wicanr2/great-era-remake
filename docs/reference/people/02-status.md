# 人物自傳資料庫：進度與缺漏

> ## ⛔ 2026-08-02：**§1 的三段統計表整張作廢，不可引用**
>
> 那張表記 `unknown` 91 筆、`partial` 96 筆、`confirmed` 230 筆。
> **三段都不可信，不只 `unknown` 那一段。**
>
> - **`unknown` 91 筆**：全量重跑之後，90 個真人裡**救回 61 個（68%）**，
>   只剩 29 筆是真的查無。
> - **`confirmed` 230 筆**：機械稽核（`04-confirmed-audit.md`）量出
>   **23 筆的維基專條只到 Tier C**，其中 **14 筆該把 `confidence` 封頂在 `medium`**；
>   反過來也有 **78 筆的實際位階比宣稱的高**（另有 gpost 一手佐證）。
>
> ⭐⭐ **兩邊的病因是同一個**：這張表量的不是「這個人查不查得到」，
> 是「**當初那一次查得夠不夠仔細**」。`confirmed` 當初的判準是
> 「維基有沒有個人專條」，不是「那個專條可不可信」。
>
> 原因不是資料稀薄，是**當初的查法有兩個洞**（`docs/design/21` §12.1、§19.2）：
>
> 1. **零命中沒有重跑**——MediaWiki 與 gpost 限流的症狀與「真的查無」完全一樣。
> 2. **沒有換寫法重查**——簡繁與異寫。實測 gpost 與維基 `insource:`
>    的收字習慣**相反**，兩邊都要各查一次。
>
> **往後判一個人查不查得到，只認 `facts-*.json` 的 `verified_by`
> 與 `04-confirmed-audit.md`，不認本檔。**
> 方法見 `docs/design/21-biography-authoring-spec.md` §20 與 §26。
> 本檔以下內容保留作**方法紀錄**。

> 資料抓取日期：**2026-08-01**。主要來源為中文維基百科 MediaWiki API
> （`action=query&prop=extracts&exintro`，`variant=zh-tw`），少數補以全文搜尋與其他中文網站。
> 產出：`people.json`（結構化）、`01-biographies.md`（人類可讀）。

## 2. 異體字／不同寫法對照

名冊姓名是從遊戲點陣字模反查倚天字庫來的，與通行寫法有出入的共 **22 筆**。
`people.json` 的 `name_ingame` 一律保留遊戲寫法，通行寫法放 `name_common`。

✅ **這 22 筆是原版的文本事實，不是反查誤差**——`tools/dup_glyph.py`
證實倚天 `STDFONT.15` 的 13,094 個字形裡**沒有任何兩個碼點共用同一字形**
（非空白重複 0 組），所以 byte-exact 反查取不到錯的碼點。
遊戲寫「閰錫山」就是當年真的打了「閰」。

⚠️ 對 remake 的意義：繁中母本要**保留原版寫法**（這是保存專案），
英文與日文版才用通行寫法。`translations/glossary.md` 兩欄都要留。

值得注意的三點：

1. **同一個人在名冊裡出現兩種寫法**。`#50 龐炳勛`（北伐時期）與 `#289 龐炳勳`（抗戰前期）
   是同一人，遊戲兩期的姓名字模用了不同的「勛／勳」。這暗示三期的姓名資料**不是同一份
   來源**，可能是分期各自輸入的。反過來也提醒：名冊去重時若只做字串比對，會把同一人
   算成兩個。
2. **`#297 李家銓` 是推定，不是確認**。中文維基查無「李家銓」，但 1938 年戰鬥序列裡
   相同序位是第四十七軍軍長**李家鈺**。

   ⛔ **原本研判為「字模反查時鈺誤為銓」，那個解釋已排除**（2026-08-01）：
   `tools/dup_glyph.py` 掃過倚天 `STDFONT.15` 的全部 13,094 個字形，
   **非空白的重複字形是 0 組**——每個字形對應唯一 Big5 碼點，
   byte-exact 反查在原理上不可能取錯字。

   所以遊戲**確實寫的是「銓」**。若對應的是李家鈺，那是 1992 年輸入時的
   錯字，不是我們反查的問題。維持 `partial`，理由改成「原文如此，
   對應人物為推定」。
3. **`#399 陳公俠` 用的是字不是名**。遊戲直接寫「陳公俠」，也就是陳儀。名冊裡可能還有
   其他以字入列的例子，unknown 清單裡的怪名字值得往這個方向再查一次。

### 下一步該去哪查

依情況分四條路，成本由低到高：

1. **先懷疑字模反查出錯**（適用於絕大多數「維基查無同名條目」的人）。
   已知名冊有 22 筆異體字／形近字問題，比例 5.3%；unknown 這 91 人裡合理推測
   還藏著同類錯誤。做法是拿 `docs/formats/01-glyph-text.md` 的反查結果，
   對這些名字的每個字重新檢視候選字模——尤其是筆畫多、字形相近的字
   （勛／勳、渠／榘、鐘／鍾、濬／浚、徵／澂、峙／時、纘／讚、鈺／銓 已各出現過一次）。
   **這條路的投報最高，因為錯的可能是我們的反查，不是資料不存在。**

2. **改查非維基的民國人物資料庫**。維基對北洋中低階將領覆蓋很差，但下列來源覆蓋較廣：
   - 中國文化大學《中華百科全書》民國人物庫（`digroc.pccu.edu.tw`，本次已用於陳瑞河）
   - 劉壽林等編《民國職官年表》——省級以上軍職、鎮守使、督辦的權威名錄
   - 《北洋軍閥史料》《中華民國史資料叢稿》人物傳
   - 各省地方志的「人物志」——旅長／師長級人物通常只在原籍省志留下記載

3. **回遊戲資料本身找旁證**。名冊只有姓名，但將領記錄還有 33 bytes 未解
   （見 `CLAUDE.md` §1.5）。若能解出「所屬勢力」「初始所在省份」欄位，
   就能把「這是誰麾下的人」縮到一個軍系，再拿去比對該軍系的編制表——
   本次 `partial` 有相當比例就是靠這種方式撈出來的
   （周蔭人的福建陸軍一次解掉 5 人、張作霖安國軍的方面軍序列一次解掉十幾人）。

4. **接受部分是遊戲自製或誤植**。1992 年的資料輸入沒有校對機制，名冊裡出現
   打錯字、記錯名、甚至為湊人數編出來的名字都是可能的。真的三條路都走完仍查不到，
   就維持 `unknown`，不要為了讓資料庫看起來完整而編。

### 需要特別處理的幾筆

- **`#274 無省長`**——這不是人名，是**佔位值**。字面就是「無省長」，對應「該省沒有省長」
  的空欄位。它出現在名冊裡代表遊戲的將領表把空欄位也存成一筆記錄，
  **這是解 `WAR.EXE` 將領資料表時要處理的邊界條件**，不是查不到的人。
  建議後續從名冊移出，另記進 `docs/formats/`。
- **`#416 博郎`**——抗日後期 #105，緊鄰 `#414 史迪威`（#103）與 `#415 孫立人`（#104）。
  位置上像是另一位盟軍將領的音譯名。候選方向：美軍在華將領（Brown、Boatner）、
  或中國遠征軍相關的英美軍官。查證方式是先解出該筆記錄的能力值與所屬勢力，
  確認是不是被歸在盟軍那一組。
- **`#227 長興`**——只有兩個字，不像漢人姓名，可能是滿蒙人名的漢字轉寫（奉系常見）。
  下一步查《民國職官年表》的東北軍將領名錄。
- **年代對不上而排除的 7 筆**：`#84 李鵬`（維基條目是 1928 年生的中共前總理，
  北伐時期不可能）、`#104 張中立`、`#225 吳希賢`、`#226 吳泰來`、`#233 劉世安`、
  `#235 趙瀛`、`#376 佟毅`。這幾筆**不是查不到，是查到的人不對**——
  重查時要避開這些同名條目，直接用「姓名 + 軍職 + 北伐」的組合搜尋。

## 4. 已知的資料品質風險

1. **7 筆的來源不是維基百科**，可靠度較低，日後應優先複核：
   - `#353 葉肇`、`#356 劉膺古`（百度百科）
   - `#364 陳瑞河`（中國文化大學民國人物庫，可靠度尚可）
   - `#367 許鴻林`（文學城 BBS 貼文）
   - `#368 于鎮河`（百度百科）
   - `#383 張淦`（factpedia + 網易號文章）
2. **`partial` 的 96 筆多半靠部隊沿革條目拼出來**。這類記載只保證「某年某人任某職」，
   不保證生卒年與籍貫，因此這些欄位常為 `null`／空字串。**不要把 `partial` 的內容
   當成確定事實往下推。**
3. **同名混淆是這批資料最大的風險**。民國人物同名極多（例：楊森有軍閥、藥廠、棒球員
   三個維基條目；李群的維基首選是數學的 Lie group）。本次凡是生卒年或籍貫對不上的
   一律降級或標 unknown，但 `confirmed` 裡仍可能殘留誤配，
   **重要人物在寫進遊戲之前建議人工再核一次**。
4. **名冊本身有一個重複槽位**：`#335 田鎮南` 在抗戰前期同時佔 #81 與 #105 兩個位置。
   這是名冊原始資料的現象（見 `00-roster.md`），不是本次整理的錯誤，
   但代表**「期內序號 → 人」不是一對一**，解將領資料表時要留意。

## 5. 方法紀錄（供重跑）

1. 從 `00-roster.md` 抽出 417 筆（編號、遊戲姓名、出現時期）。
2. 以 MediaWiki API 每批 20 筆抓中文維基導言（`exintro` + `explaintext` + `variant=zh-tw`），
   同時取回重新導向與消歧義旗標。一輪命中 189 筆，其餘 228 筆（188 查無、36 消歧義、
   4 明顯打錯領域）進第二輪。
3. 第二輪用全文搜尋（`list=search`）取候選條目，逐一人工判讀：先試異體字替換，
   再試「姓名 + 軍職 / 部隊」組合，最後才收手標 unknown。
4. 撰寫小傳、填結構化欄位，逐筆標信心度。
5. 機器檢查：編號連續、姓名與名冊逐字一致、`unknown` 的 `bio_zh` 必為空、
   `unknown` 的 `sources` 必為空、生卒年型別與先後順序、
   **346 個維基來源網址全部回打 API 驗證存在**（修掉 3 個失效網址）、簡體字殘留掃描。
6. `periods` 一律由 `00-roster.md` 重新計算覆寫，不採信撰稿階段的填寫。

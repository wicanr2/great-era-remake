## #26 戴岳 — `medium`

戴岳（1888年—1971年），字希鵬，原名哲人，湖南邵陽縣東鄉人。1906年入湖南陸軍小學堂，1912年入保定陸軍軍官學校，1937年入陸軍大學特別班第三期，次年畢業。1924年任湘軍第二軍第二師師長，1926年任國民革命軍第二軍第六師師長，1929年改任陸軍第十八師第五十二旅旅長，1935年敘陸軍中將，1939年派湖南省第四區行政督察專員，次年1月兼該區保安司令，同年4月改派第九區行政督察專員兼保安司令，1943年任湖南省政府委員，1945年免職，1954年任湖南省人民政府參事室參事。1930年12月，江西龍岡一役，第十八師師部與所轄兩旅為中國工農紅軍圍殲，師長張輝瓚被俘，戴自龍岡脫出。1971年逝世。

## 兩個不算缺口、但派工前要知道的事

1. **`highest_post` 與 `faction` 真的會錯，而且錯得不明顯。** `#263 曹萬順` 的 `highest_post`
   是「國民革命軍第三十四軍軍長」，本輪在 gpost 十筆與維基第三十四軍條目全文都查不到；
   `#385 蘇祖馨` 的「中華民國陸軍中將」在 gpost 只查到 1937 年晉少將。
   規格 §8 末段已經說這兩欄要一併重填，**本批的經驗是：重填時要當成「推翻既有結論」處理**
   （`CLAUDE.md` §7 第 5 條），而不是順手改。

2. **一批 10 篇的實際成本**（本批實測）：
   - **查證**佔約 70%：每人 1 次 gpost + 3–8 個維基條目全文（部隊沿革、戰鬥、勳章名單、地方條目）。
     `partial` 的材料**確實散在部隊沿革裡**，規格 §5.2 第 3 步的判斷是對的。
   - **成文 + 回查**佔約 20%，**品質閘 + 修正**佔約 10%（含一次超格、一次不可畫字）。
   - 工具面：gpost 用 `curl` + HTML 剝標籤可直接抓，維基用 MediaWiki API
     （`action=parse&prop=wikitext` 比 `prop=extracts` 可靠，後者對含大量模板的條目會回空）。
     **本批把 WebSearch 額度用完了**（10 篇約需 15–20 次搜尋），後續批次應改以 MediaWiki
     全文搜尋 API 為主，把 WebSearch 留給查不到的人。
   - 若照這個流程，**一批 10 篇是一個 agent 的合理上限**，與規格 §7.1 的估計一致。
     `partial` 剩餘 86 筆約需 **9 批**。

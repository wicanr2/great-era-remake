# 機制：電腦 AI 的判斷邏輯

依 `CLAUDE.md` §6.5，這是機制文件裡優先度最高的一份——
remake 之後要調難度、改進電腦對手、或做強化 AI，全靠這裡。

推論等級的定義見 `00-index.md`。

---

## 1. 勢力輪替：主迴圈逐省處理 — **confirmed**

`WAR.EXE` 的 `PROGRAM`（`docs/re/06`）是一個以 `byte_6FE89` 為迴圈變數的大迴圈，
**變數代表當前處理到第幾個省**。每一輪對該省跑一串 gate，決定要走哪條路。

也就是說，遊戲的推進單位是**省**，不是「勢力」——電腦不是「每個勢力想一次」，
而是「每個省被輪到時判斷一次」。這對 remake 的 AI 設計是關鍵前提：
原版的決策粒度在省，改成勢力層級的全局規劃會是**行為改動，不是還原**。

驗證位址：`PROGRAM` 的 `loc_10C18`（迴圈頭）、`loc_11002`（戰鬥 gate）。

---

## 2. 「這個省要不要進戰鬥」的三個條件 — **confirmed**

```asm
loc_11002:
        mov     al, byte_6FE89      ; 當前省
        mov     dx, 25h             ; ×37 = 省份記錄大小（SPEC-03）
        mul     dx
        mov     di, ax
        push    word ptr [di-6221h] ; 省份記錄裡的一個 word
        call    sub_5C7FE
        or      al, al
        jnz     loc_1102C           ; 1. 成立 → 進戰鬥
        cmp     byte_7003A, 0
        jnz     loc_1102C           ; 2. 成立 → 進戰鬥
        cmp     byte_7003B, 0
        jnz     loc_1102C           ; 3. 成立 → 進戰鬥
        jmp     loc_11143           ; 都不成立 → 這個省跳過
```

三個條件是 **OR**，任一成立就打。

### 條件 1：司令是不是十大勢力之一（`sub_5C7FE`）

```
sub_5C7FE(arg: word) -> boolean
    if byte_7003A != 0:  return false
    if arg == 0:         return false
    for i = 1 to 10:
        if arg == 表[i]: return true
    return false
```

**在一個 10 元素的 word 表裡線性搜尋**。第一期正好有 10 個勢力
（張作霖、孫傳芳、吳佩孚、蔣中正、劉湘、唐繼堯、袁祖銘、趙恆惕、閰錫山、馮玉祥，
見 `docs/spec/03` §3），而傳進去的 word 來自省份記錄，司令欄位存的正是將領 ID。

- 迴圈從 **1** 數到 10，不是 0——與將領 ID 是 1-based 一致（SPEC-03 §3）。
- `arg == 0` 直接回 false，對應「無主的省」。

⚠️ **那張表的內容是執行期填的，靜態看不到**。「表 = 十大勢力領袖」是從
「10 這個數字 + 傳入值來自省份記錄的司令欄位」推的——**強證據，不是 confirmed**。
要確認得動態 dump 或找到填表的程式碼。

### 條件 2、3：`byte_7003A` / `byte_7003B` — **未知**

兩個 byte 旗標。有趣的是**方向相反**：

| 位置 | `byte_7003A != 0` 時 |
|---|---|
| `sub_5C7FE` 開頭 | 直接 return false（不算勢力）|
| 主迴圈 gate | 直接進戰鬥 |

一個合理的解釋是「示範模式／自動戰鬥」——開著的時候略過勢力歸屬判斷，
所有省都打。**但這是假說**，沒有證據。

下一步：找這兩個 byte 的所有寫入點（`grep byte_7003A` 的 XREF）。

## 3. 進戰鬥前會釋放政略階段的記憶體 — **confirmed**

`loc_1102C` 在呼叫戰鬥主函式 `sub_39B6E` 之前，連續七次 `FreeMem`：

```
0xB08, 0x520, 0xA38, 0x520, 0xA98, 0x298, 0x718 bytes
```

政略與戰鬥的狀態是**分開配置**的，不共用緩衝。remake 不需要重現這個
記憶體管理，但它證實了兩個階段的狀態互不干涉——`internal/game` 可以
把政略與戰鬥切成兩組狀態，不必擔心原版有隱藏的共用欄位。

## 4. 還完全沒解的部分 — **未知**

這一份目前只涵蓋「哪個省會進戰鬥」，AI 真正的決策全都還沒挖：

| 問題 | 下一步從哪挖 |
|---|---|
| 電腦選哪個政略指令（15 選 1）| 找政略指令分派器，看電腦走哪條路 |
| 出兵目標怎麼選 | 攻打候選 = 鄰省 − 己方省（SPEC-01 §2 已驗），但**排序規則**未知 |
| 派將怎麼挑 | 將領記錄 33 B 只解出三個能力值與兵力（SPEC-02），選將公式未知 |
| 兵力配置比例 | 未知 |
| 撤退／求和門檻 | 未知 |
| 亂數在哪介入 | `PROGRAM` 開頭有 `Randomize`，但 `Random` 的呼叫點還沒盤 |
| 難度參數 | 不確定原版有沒有難度設定 |

### 建議的挖掘順序

1. **盤 `Random` 的所有呼叫點**——這是最便宜的一步，直接標出所有隨機決策的位置。
2. 找政略指令的分派器（15 個分支的 jump table 或連續 cmp）。
3. 從分派器往回找「電腦走的那一條」——玩家與電腦多半共用同一批動作函式，
   差別在誰來決定參數。

---

## 5. 給 remake 的設計提醒

- **決策粒度在省**（§1）。要做強化 AI 可以另外加一層全局規劃，
  但那必須標記為 remake 差異，不能混進「還原原版」的路徑。
- 條件判斷用的是**線性搜尋十大勢力表**，不是位元遮罩——
  代表勢力數量在原版是硬上限 10。remake 若要支援更多勢力，
  這是第一個要改的地方，也要標為差異。

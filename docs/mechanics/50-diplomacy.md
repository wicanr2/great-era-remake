### 借貸是一整個循環

貸款 → 產生外債 → 償還外債 → 影響信用度 → 可能影響下次貸款。
「各國均拒絕提供貸款」是一條真實的隨機失敗分支；另外，`sub_2164A` 開頭
`cmp byte ptr [di-4225h], 0` 已證實信用度為零時會先顯示「無法貸款」並返回，
不進入額度輸入或核貸亂數。這是**信用度等於零**的 gate，不是信用度小於本次額度
單位的猜測；詳見 `docs/re/34-loan-credit-gate.md`。

貸款的**隨機拒絕會消耗指令**也已由呼叫端資料流確認：`sub_2164A` 在
`Random(10)` 前立 `byte_6FE81=1`，`sub_2296C` 把它帶回 `sub_10193`，主迴圈
在 `loc_103DF` 才遞減命令；信用度零早期分支未立旗標。完整索引見
`docs/re/35-loan-command-cost.md`，remake 接線見 `docs/spec/16-loan-command-cost-m1.md`。

外援給的是**黃金、糧食、彈藥、燃料**四種——與運補能搬的四種完全相同
（`docs/re/27`），煤礦鐵礦都不在內。

### ✅ 外交帳本的位置、初始化與 `.DT1` 持久化 — **confirmed**

這兩張表是 `WAR.EXE` 的執行期全域表，同時也是 `.DT1` 的區塊 8／9。
索引由 `sub_215F0` 以省份司令反查 `word_70026`（1..10）得到；
`sub_391E1` 在劇本初始化時逐格填入初值。

| 表 | 原始運算元 | ds 起點 | IDA linear address（index 1） | 形狀 | 初值 |
|---|---|---:|---:|---|---|
| 信用度 | `[di-4225h]` | `BDDBh` | `6FF8Ch` | 10 × `u8`，索引 1..10 | 100 |
| 外債 | `[di-421Eh]`／`[di-421Ch]` | `BDE2h` | `6FF96h` | 10 × `u32` little-endian，索引 1..10 | 0 |

`sub_2164A` 核准貸款時做三件事：信用度減少 `額度 ÷ 500`、省份黃金增加
額度、外債表以 32-bit `add/adc` 增加同一筆額度。`sub_223ED` 先檢查
輸入額度不超過該索引的外債，再以 32-bit `sub/sbb` 扣外債、扣省份黃金，
最後信用度增加 `額度 ÷ 500` 並夾到 100。規則層的
`internal/game.DiplomacyLedger` 已保留這個 1-based 表與兩個窄接入方法。

`sub_595D4`（IDA `595D4h..598C0h`）把 `byte_6FF96` 的 28 bytes 與
`byte_6FF8C` 的 10 bytes 複製到 `.DT1` 暫存記錄後整筆 `Write`；
`sub_59CBF`（`59CBFh..5A031h`）在載入時以相同大小 `Read` 回來。
`internal/game.ParseDiplomacyLedger`／`WriteDiplomacyLedger` 與
`cmd/dsds` 的 `buildSession`／`autosave` 已接上這條非破壞性存檔鏈。
原始 `.DT1` 區塊 10 的 runtime 快照現在由 `WriteMajorPowerLeaders` 原樣逐欄寫回；
其生成時機仍未閉合，不自行產生名冊。夾在區塊之間的 7 個單 byte runtime 欄位與其他未知 bytes
仍不改寫。玩家介面 M0 的正常路徑與限制
另見 `docs/spec/07-diplomacy-ui.md`、`docs/spec/12-diplomacy-ui-m1.md`、
`docs/playtest/35-diplomacy-ui-m0.md`。

### ✅ 貸款的核貸公式 — **confirmed**

`sub_2164A`（726 行）的判定只有兩行：

```
units = 貸款額 ÷ 500          ; mov cx, 1F4h + @$brdiv
roll  = Random(10)
若 roll + units > 12 → 各國均拒絕提供貸款
否則  信用度 −= units、省份黃金 += 貸款額
```

**借越多越容易被拒**，而且門檻算得出來：

| 額度 | units | 結果 |
|---:|---:|---|
| ≤ 1,999 | ≤ 3 | **必過**（骰最大 9，9+3=12 不超過）|
| 2,000–6,499 | 4–12 | 機率，額度越大越低 |
| 6,000 | 12 | 只有骰到 0 才過（≈10%）|
| ≥ 6,500 | ≥ 13 | **必被拒** |

所以單次貸款的硬上限是 **6,499**。

### ✅ 「信用度」找到位址了

```
sub  [di-4225h], dl      ; dl = 額度 ÷ 500
```

`-4225h` 當 16-bit 是 **`0xBDDB`**——信用度是那裡起的一張 byte 表。
索引來自 `ss:[di-6]`，`sub_215F0` 已證實它是 `word_70026` 的
1-based 十勢力索引。

貸款會**扣**信用度（每 500 黃金扣 1）；償還會按相同單位回補。

### ✅ 償還外債與貸款完全對稱 — **confirmed**

```
額度 ÷ 500 → dl
信用度 += dl
若 信用度 > 100 → 100        ; cmp byte ptr [di-4225h], 64h
```

兩邊用同一個 500 為單位，**借多少還多少就回到原點**。
信用度上限 **100**。

外債餘額是上方已定位的 10 × `u32` 表；`sub_223ED` 的 `sub/sbb` 寫回與
`.DT1` 區塊 8 的存檔同步都已閉合。玩家 UI 現已由 M0/M1 接上選單、貸款、外援與
償債額度頁；信用度零 gate、貸款隨機拒絕成本、外援結果成本均已由呼叫端資料流
閉合。第一期援助國選擇與區塊 10 的同步時機仍未知，而不是這張帳本兩段的格式。

```

Random(10) ≥ 7 → 進入核准／資源寫入   ; 30%
四種資源各 += Random(基準) ÷ 除數
```

```
基準[黃金]   = 60000 - 省份黃金
基準[糧食]   = 60000 - 省份糧食
```

## 1z. ✅ 談判停火的同意判定 — **confirmed**

`sub_211D5` → `sub_20CF0`（148 行）。**這是目前解出來最有設計感的一段 AI 判斷**：

```
roll = Random(10)

; 掃全部將領，用攻擊力公式 sub_5A0B9 分別累加攻守雙方
for 每個將領 g:
    若 g.+4 == 目標省 且 g.+16 bit 2 == 1（已部署）:
        g.+8 == 0 → 守方戰力 += 攻擊力(g)
        否則      → 攻方戰力 += 攻擊力(g)

佔上風 = (請求方是守方 且 守方 ≥ 攻方) 或 (請求方是攻方 且 攻方 ≥ 守方)

佔上風 → roll ≥ 3 才同意    70%
劣勢   → roll ≥ 8 才同意    20%
```

**你強對方才肯停火。** 弱勢方求和只有 1/5 機會。

⭐ 這是「AI 的評估函式就是攻擊力公式」的**第二個獨立例子**
（第一個是調動，`70-ai.md` §6e）。要改 AI 的強弱判斷，改 `sub_5A0B9` 就好。

### 兩張新表的位址

| 表 | 位址 | 形狀 | 已知 |
|---|---|---|---|
| 戰爭記錄 | `ds:B346h` | **60 B/筆**，省編號索引 | `+0`／`+2` 是交戰的兩個勢力 |
| 停火狀態 | `ds:BCA5h` | 每省 1 byte | 值 > 0 = 停火中，同意時 `inc` |

39 省 × 60 = 2,340 B，`B346 + 2340 = BC6A`，正好落在停火表之前——
**兩張表相鄰，佈局自洽**。

⚠️ 停火表是**遞增**而不是設成固定值，形狀像「剩餘停火月數」，但沒有證據。
原版同意分支明確執行 `inc byte`；`internal/game/ceasefire.go` 已保留這個
byte 遞增行為，但不替它命名成「月數」。`WriteCeasefireStates` 只覆蓋這 39 bytes，
其餘 `.DT1` 區域維持原樣。

## 2. 秘密行動的兩個子項 — **confirmed（機率與效果）**

| 項目 | 函式 | 成功／失敗 |
|---|---|---|
| 派遣游擊隊 | `sub_1FC1C`、`sub_20B28` | 「任務圓滿達成」／「遭到游擊隊襲擊，任務失敗」|
| 鼓動學潮 | `sub_20447` | 「發生學潮」／「沒有學潮發生」|

兩者的前置檢查相同：**資金不足**擋一次、**目標省正在戰爭**擋一次，拒絕時
不得扣款。游擊隊成功率 40%，成功後目標黃金／糧食／彈藥以「先除 10、再乘 7」
剩下約 70%，另有 1/5 機率摧毀一座兵工廠。學潮固定花 1,500 黃金、成功率 20%；
成功後目標省將領士氣、將領忠誠與人民忠誠均以 `Round(×0.8)` 衰減。兩者都是
**先扣款再判定**，所以失敗仍付款。完整測試在 `internal/game/covert_test.go`。

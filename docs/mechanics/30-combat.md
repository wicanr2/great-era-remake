# 機制：戰鬥

推論等級的定義見 `00-index.md`。

> **這一份幾乎全是未知。** 戰鬥系統是 M3 最大的一塊，也是目前最沒進展的一塊。
> 不要因為社群資料寫得很具體就當成事實——`CLAUDE.md` §4 的 oracle 優先序裡
> 社群資料是最低位階，而且這款遊戲三十年來有大量修改版流傳。

## 1. 已知的硬事實

### 戰場是每省一張 14×14 格 — **confirmed**

三個檔案各管一件事，見 `docs/spec/01`（地名）與 `docs/spec/04`（地物）：

| 檔案 | 每格存什麼 |
|---|---|
| `WARPOS.DAT` | 屬於哪個鄰省（0 = 本省腹地）|
| `TERNAME.DAT` | 地名索引，指向 `TN15.<省>` |
| `NWMAP.DAT` | 地物編號，決定畫哪張圖塊 |

### 戰鬥狀態記錄 469 bytes — **confirmed（結構）／未知（語意）**

`MEM_WAR.DAT` 與 `SAVE(N).DT2` 同結構，見 `docs/re/05`。
10/10、20/20、200/200 三組成對，**很可能是攻守雙方各一份**。

⚠️ 不能拿 `MEM_WAR.DAT` 當戰前基準去 diff 部隊欄位——**8 個省有未初始化的殘料**，
緬甸那筆裡甚至是 8086 機器碼。

### 戰鬥觸發在主迴圈 — **confirmed**

見 `70-ai.md` §2。三個 OR 條件，任一成立就打。

### 戰鬥模組的位置 — **confirmed**

`sub_39B6E`，主迴圈直接呼叫。生命週期是
載入地圖 → 載入戰鬥狀態 → （主迴圈）→ 寫回戰鬥狀態，見 `docs/re/04`。

`+18F` 到 `+6F4` 之間是戰鬥主迴圈，裡面有 `KEYPRESSED`（輸入）與
`SETACTIVEPAGE`（雙緩衝）。

## 2. 詞表證實的戰鬥組成 — **強證據**

原版 UI 詞表（`01-vocabulary.md` §2）裡有這些詞，證明機制存在：

- **機動力**（`3.15` 51）——**已解**：執行期單位記錄的 `+6`／`+7`，
  移動一格扣掉該步成本（`docs/re/07` §7）。成本公式仍未解
- **肉搏戰**（`3.15` 50）——獨立的一個階段或判定
- **攻擊力**（`3.15` 42）、**單位數**（48）、**士兵數**（49）
- **協同攻擊**與**正規攻擊**（`4.15` 40、41）——**兩種攻擊方式，
  社群資料完全沒提到**
- 移動、撤退、駐軍、炮擊、炮轟、行軍、崩潰、衝鋒、增援、損失、陣亡
- **穿越**、**阻隔**——**已解**：長城段（地物 12–21）阻擋通行，
  單位記錄 `+21 == 1` 的兵種可以穿越（`docs/re/07` §7）
- **強渡**——河海的通行規則，未解
- **地方可退**（`4.15` 44）——撤退需要有可退的格子
- **所在地形**（`4.15` 50）——戰鬥中會顯示格子的地形

「單位數」與「士兵數」是兩個不同的量，呼應戰鬥狀態記錄裡
10 個槽 vs 200 B 單位區的雙層結構（`docs/re/05`）。

**這些都只證明存在，不告訴我們公式。**

## 3. 戰鬥選單有七項，不是六個方向 — **confirmed（程式碼）**

`WAR.EXE` 裡**只有一支函式**比較 `'6'`：`sub_38DFE`（`0x38DFE`，
就在戰鬥主函式 `sub_39B6E` 隔壁，同一個編譯單元）。它處理的是
**`'1'` 到 `'7'` 共七個鍵**，每個分支都做同一件事：

```asm
cmp     al, 31h              ; '1'
jnz     ...
mov     al, byte_6FFCA
... 座標常數 ...
call    sub_5A4BC            ; 畫新位置
call    PUTIMAGE             ; 擦舊位置
```

座標：x 固定 243–258（寬 15），y 在 98／114／163／181／229／244／264
之間跳，每格高 10。**這是選單項目的高亮游標**，不是戰場上的移動。

### 這對「數字鍵 1–6 對應六個方向」的社群說法意味著什麼

`CLAUDE.md` §1.5 記的是社群資料（oracle 最低位階）。

程式碼裡唯一的數字鍵分派是**七項**的選單，而且做的是選單繪圖。
**沒有找到「1–6 = 六個方向」的證據。**

這不等於六角格不存在——`3.15` 的詞表確實有「機動力」，
`NEWICON.TPC` 的飛機有六個朝向（`docs/formats/05` §3）。
但**移動的按鍵不是這一支處理的**，六方向的說法在程式碼裡還沒有對應。

七項是哪七個指令未知。`2.15` 的戰鬥詞裡有移動、撤退、駐軍、炮擊、
行軍、衝鋒等候選。

## 3b. 戰鬥結算是九個步驟 — **confirmed**

戰鬥主迴圈 `sub_39B6E` 逐一處理戰場單位：

```
loc_39E50:  var_2A++                        ; 單位索引
    id = word[0x750 + var_2A*2]             ; 戰場單位清單（將領 ID）
    if id == 0:                    → 下一輪
    if 單位[id].+5 != 0xFF:         → 處理    ; 0xFF = 空槽
    ...
    sub_54E3B(a, b)                          ; 參數順序依 byte_64901
```

`byte_64901` 取 **1 或 2** 決定參數順序——對應詞表的「攻方」(`2.15` 166)
與「守方」(167)，也就是誰先動。

`sub_54E3B` 本身是九個連續呼叫，全部落在 `0x54000` 段，是一場戰鬥的
完整結算流程（**九步全部已解**，對照表見 §3）：

```
sub_540B2  sub_54391  sub_546D1  sub_543C2  sub_54CFD
sub_54826  sub_5446D  sub_545B0  sub_54DAC
```

九步都**沒有 `Random` 呼叫**——戰鬥結算本身不擲骰，隨機性（如果有）
在別處介入。`sub_540B2` 的 56 個加減全是座標運算，是繪圖那一步。

## 3c. 第一條解出來的公式：每回合衰減 20% — **confirmed（程式碼）／未知（欄位語意）**

`sub_54826` 裡有一段完整的算式：

```
for j = 1 to 10:                          ; 每方 10 個單位
    id = 單位清單[j]
    if id == 0: continue
    ptr = 0x7A7D + 33*id                  ; 執行期單位記錄，33 bytes
    if ptr[+30] <= 40: continue           ; 40 以下不衰減
    ptr[+30] -= Round(Real(ptr[+30]) / 5.0)
```

### 那個常數是 5.0

浮點常數存在 `CX:SI:DI = 0x0083, 0x0000, 0x2000`。
Turbo Pascal 的 48-bit `Real`：第一個 byte 是 biased exponent（bias 129），
其餘五個 byte 是尾數（最高位元是符號）。

```
exponent 0x83 = 131  →  2^(131-129) = 4
尾數最高 byte 0x20   →  1.01₂ = 1.25
4 × 1.25 = 5.0
```

除以 5 再四捨五入相減，等於**每回合扣掉當前值的 20%**，
但只在該值大於 40 時才扣。

⚠️ **`+30` 是什麼欄位還不知道。** 候選是「體力」或「士氣」
（`2.15` 詞條 80、81）——衰減型的量都符合，但沒有證據指定哪一個。
「10 個單位」呼應 `docs/re/05` 那份 469 B 戰鬥狀態記錄裡每方 10 個槽。

## 3d. 回合初始化：`sub_5446D` 與 `sub_545B0` — **confirmed**

九步結算裡的第六、七步，都遍歷 `word[0x6742 + i*2]` 的單位清單
（與主迴圈用的 `0x750` 是**兩份不同的清單**，很可能是攻守各一）：

```
sub_5446D 對每個單位：          sub_545B0 對每個單位：
    +16 = 1                        +14 = 參數
    +5  = 0xFF                     +8  = 0
    +7  = +6                       sub_5A031(id)
    +13 = 0                        +16 = 1
    +8  = 0                        if byte_64901 == 2: ...
```

### 兩個可讀的模式

1. **`+7 = +6`** 是典型的「當前值 = 最大值」重置。**已確認是機動力**：
   `sub_4A1C0` 移動一格時做 `+7 -= 成本`，呼叫端先檢查 `+7 >= 成本`
   才准走（`docs/re/07` §7）。對上 `3.15` 詞條 51「機動力」。
2. **`+16 = 1`** 與 `sub_15018` 檢查的 `+16 & 1` 對上：
   那個 bit 是「這個單位在場／可行動」。

### 執行期單位記錄的已知欄位

基址 `0x7A7D`，每筆 33 bytes。與 `MAN(N).DAT` 同大小，
**而且 `+4`（所屬省）是同一個欄位**——不是完全另起爐灶的佈局，
比較像是檔案記錄載入後就地擴充戰鬥用的欄位。

| 偏移 | 用法 | 出處 |
|---:|---|---|
| +4 | **所屬省**，與 `MAN(N).DAT` 的 `+4` 同一個欄位 | `sub_5A881`（`docs/re/07` §9）|
| +5 | **戰場格編號 0..195**，`0xFF` = 不在場上 | `sub_50FF5`、`sub_41513`（`docs/re/07` §2）|
| +6 | **機動力上限** | `sub_5446D`（`+7 = +6` 的來源）|
| +7 | **剩餘機動力**，每回合回到 `+6`；移動一格扣掉該步成本 | `sub_5446D`、`sub_4A1C0`（`docs/re/07` §7）|
| +8 | **攻方 1／守方 0**（強證據）| `sub_41513` 寫 1、`sub_53DA9` 用它選顯示旗標（`docs/re/07` §8）|
| +13 | 每回合歸零；**bit 7 = 本回合已指派目標**（`docs/re/31` §31）| `sub_5446D`／`sub_3E81F` |
| +14 | **效忠的勢力領袖**（將領 ID，u16）。與省份記錄 `+20` 司令直接比較 | `sub_534FF`、`sub_5A881`（`docs/re/07` §9）|
| +9 | **所屬省編號**（部署時決定從哪一側進場）| `sub_4F0E2` 寫進 `byte_6AB65`，`sub_41513` 比對 |
| +21 | **兵種編號**（強證據；值域含 1/4/5/6）。`== 1` 可穿越長城 | `sub_4A583`、`sub_1629E` |
| +16 | bit 0 = 在場／可行動；部署時 `\|= 4` | `sub_15018` 讀、`sub_5446D`／`sub_545B0`／`sub_41513` 寫 |
| +30 | > 40 時每回合減 20% | `sub_54826` |

## 3e. 兩張單位清單 = 攻守雙方 — **confirmed**

執行期有兩張相鄰的單位清單：

```
0x750  第一方的 10 個單位
0x764  第二方的 10 個單位     ; 0x764 - 0x750 = 0x14 = 20 bytes = 10 個 word
```

`sub_543C2` 對**兩張都**做回合初始化（`+16=1`、`+7=+6`、`+13=0`），
`sub_5446D`／`sub_545B0` 則走第三張 `0x6742`。

**每方 10 個單位現在有三處獨立佐證**：469 B 記錄的槽數、
衰減迴圈跑 1..10、以及這兩張表的距離。

## 3f. 佔領：`sub_54DAC` — **confirmed**

九步結算的最後一步：

```
sub_5ADA6(當前省)
byte[當前省 - 0x435B] = 0
記錄[當前省].+32 &= 0xBF              ; 清除 bit 6
if [arg_0+8] == word_64942:
    記錄[當前省].+20 = word_64942      ; **司令改成勝方**
sub_5A541(當前省, [arg_0+8])
```

`+20` 是省份記錄的司令欄位（`docs/spec/03` §2），把它改掉就是**易主**。
`2.15` 的詞條 186「攻克」、219「佔領」對應的就是這一步。

### 這順帶解掉了 `+32` 的 bit 6

先前只知道 `sub_15925` 收集候選鄰省時會跳過設了它的省，語意未解。
現在加上「戰後 `&= 0xBF` 清除」，語意就清楚了：

> **bit 6 = 這個省正在打仗。**

不能挑正在打的省當目標，打完就清掉。這也解釋了為什麼兩份存檔裡
都沒有出現過——存檔時不在戰鬥中（`docs/spec/03` §2b 已更正）。

## 3g. 單位陣亡：`sub_53DA9` — **confirmed**

`sub_54826` 的核心迴圈：

```
for j = 1 to 10:
    id = 單位清單[j]
    if id == 0:                  continue
    if !(單位[id].+16 & 1):       continue   ; 不在場
    sub_53DA9(1, &結果, &var_DF, id)
    if 結果 != 0:  單位清單[j] = 0            ; **清空槽位 = 陣亡**
```

接著對第二張清單 `0x6742` 做同樣的事（`byte_64901 == 2` 時）。
把槽位設 0 就是把單位從戰場移除——對應詞表的「陣亡」(`2.15` 152/177)。

### `sub_53DA9` 的結果套用

```
if 單位[id].+8 != 0 and id == word_64902:
    var_11 = 1
sub_52129(0, id)
ptr = 0x7A7D + 33*id
ptr[+16] = 1                                  ; 標記在場
ptr[+29] = var_12
ptr[+14] = var_14
ptr[+30] -= Round(Real(ptr[+30]) / 10.0)      ; **扣 10%**
if var_11 != 0:
    byte_6A40A = 1
    byte_64901 = 2                            ; 換方
```

## 3h. 同一個欄位有兩條衰減規則 — **confirmed**

`+30` 在戰鬥的不同階段用不同的除數：

| 出處 | 除數 | 門檻 | 效果 |
|---|---:|---|---|
| `sub_54826`（每回合結算）| 5.0 | > 40 才扣 | 扣 20% |
| `sub_53DA9`（戰鬥判定後）| 10.0 | **無門檻** | 扣 10% |

兩個常數都是 Turbo Pascal 的 48-bit Real：

```
0x0083/0x0000/0x2000  →  2^(131-129) × 1.25 = 5.0
0x0084/0x0000/0x2000  →  2^(132-129) × 1.25 = 10.0
```

### ⚠️ 10% 那條的捨入規則未確認

`v / 10` 的小數**會碰到 .5**（v = 5, 15, 25, …），而 `v / 5` 碰不到——
所以 20% 那條怎麼捨入都一樣，10% 這條不行。

Turbo Pascal 的文件說 `Round` 在正好一半時取絕對值較大的那個
（half-away-from-zero），實作照這個寫。但 Delphi 之後改成 banker's
rounding，**而我們沒有實機驗證過這一版 RTL 的行為**。

差異只在 `v ≡ 5 (mod 10)` 的 26 個值上，各差 1。要確認就實機打一場，
記錄該欄位的變化序列。

## 3i. 誰是攻方：`sub_54391` 與 `sub_54CFD` — **confirmed**

`sub_54391` 只有 24 行，但決定了整場戰鬥的視角：

```
if [arg_0+8] == word_64942:  byte_64901 = 1
else:                        byte_64901 = 2
byte_6A40A = 1
byte_6A8F2 = 1
```

`sub_54CFD` 用同一個判斷選資料：

```
if [arg_0+8] == word_64942:  用 word_64902   ; .DT2 的 +28
else:                        用 word_64916   ; .DT2 的 +48
```

而 `word_64902` / `word_64916` 是 `MEM_WAR.DAT`／`.DT2` 記錄的
`+28` 與 `+48`（`docs/re/05` §2），也就是**攻守雙方各 10 個的參戰單位清單**。

`sub_54DAC`（佔領）也用同一個判斷：`[arg_0+8] == word_64942` 時
才把省份的司令改成 `word_64942`——**攻方贏了才易主**。

所以 `word_64942` 是攻方的識別，`byte_64901` 是「當前處理的是攻方(1)
還是守方(2)」。

### 已實作的部分

`internal/game/combat.go` 與 `province.go` 放了已解出的規則：

| 函式 | 對應 |
|---|---|
| `Decay()` | `sub_54826` 的每回合衰減（20%，門檻 40），整數版與浮點算式 0–255 全域等價 |
| `CombatDecay()` | `sub_53DA9` 的戰鬥衰減（10%，無門檻）|
| `CombatUnit.BeginTurn()` | `sub_543C2`／`sub_5446D` 的 `+7 = +6` 重置 |
| `Battle` / `Side` | 兩張 10 格單位清單 |
| `Province.Capture()` | `sub_54DAC` 的佔領結算（清 bit 6、改司令）|
| `BattleState.Attackers()` / `Defenders()` | `.DT2` 的 `+28`／`+48` 參戰單位清單 |

**沒解出來的欄位語意不猜**，結構裡只放已知用途的欄位。

⚠️ **不要把這些偏移套到 `MAN(N).DAT`**。檔案的 `+0/+1/+2` 是能力值、
`+4` 是所屬省、`+17` 是兵力（`docs/spec/02`），與這裡對不上——
執行期結構與檔案結構是兩回事（`70-ai.md` §6 的方法論警示）。

## 3p. 遠程攻擊：兵種 4 有射程且不吃反擊 — **強證據**

完整記錄在 `docs/re/09`。

`sub_42C8F` 開頭是一段遠程攻擊的守門：

```
if 這個單位是兵種 4:
    if 目標在它的攻擊範圍內（sub_42BC3）:
        if 它站的地形 != 森林:
            if 它是守方 且 守方彈藥 < 5000:  放棄，顯示訊息
            else:                            發動遠程攻擊
```

### 兵種 4 是遠程兵種 — 四條獨立線索

| 線索 |
|---|
| 有攻擊範圍檢查（`sub_42BC3`，靠 `+31` 產生格子清單）|
| 攻擊時**不吃反擊**（戰損裡「F 不受損失」，`docs/re/08` §5a）|
| **森林不能發動**（明寫的守門條件）|
| 地形表裡兵種 4 在森林的攻擊係數是 **1**，全表最低 |

最後兩條是**兩處獨立的程式碼都說「森林擋遠程」**——一處是守門條件、
一處是資料表的數值。

⚠️ 仍**不定名為「砲兵」**。詞表有「砲兵」「炮擊」「炮轟」，
但沒有任何一處把詞條與兵種編號連起來。

### 彈藥門檻 5000 — **confirmed**

**守方**的兵種 4 在彈藥低於 5,000 時放棄遠程攻擊。
`word_6493C` 是守方帶的彈藥（`docs/re/05` §2）。

⚠️ 這條只檢查守方。攻方的兵種 4 有沒有彈藥檢查，未追。

### 順帶訂正：`sub_51D68` 的 E／F

**F 是發動攻擊的一方、E 是被攻擊的目標。** 與直覺相反，
但由 `sub_42C8F` 的呼叫確定。這修掉了規則層一個傳反的參數
（`docs/playtest/04` §3）。

## 3o. 地形 × 兵種：兩張表 — **confirmed**

完整表格在 `docs/re/08` §6。這是戰棋規則的核心資料：**每種兵種在每種地形
各有一個攻擊值與一個防禦值**。

```
攻擊值 = 強度(攻) × 0.5×攻擊表[攻方的格][攻方兵種]
                  ÷ (1 + 0.25×(防禦表[守方的格][守方兵種] − 1))
```

**攻守各看自己站的地形**，一個當分子一個當分母。

### 讀得出來的設計

- **兵種 1 是唯一的全地形兵種**：森林、高山、丘陵的防禦都是 4–5，
  而且是唯一在高山有值的
- **兵種 4／5 在開闊地最強**（平原、高原、沙漠的攻擊 5 = ×2.5），
  一進森林就掉到 1（×0.5）
- **長城上除了兵種 1，其他都打不出傷害**（攻擊係數 0），
  但兵種 1 守長城的防禦是 5。**守長城是步兵的事**
- **關口與地物 22 對所有兵種都是防禦 5、攻擊 5**——不分兵種的要塞
- 鐵路覆蓋地形（兩張表都第一件事就問鐵路）

### 高山的「漏寫」是自洽的

高山在兩張表裡只有兵種 1 有值，其餘三個兵種的分支直接跳到 return。
這不是 bug——高山的移動成本 255 等於不可通行，那三個兵種站不上去。

⚠️ **哪個號碼是哪個兵種仍無證據**，所以表用號碼標，不用「步兵」「騎兵」。
但這兩張表本身就是很強的線索：兵種 1 的地形適應最廣、兵種 4／5 偏好開闊地。

## 3n. 戰損：兩條路徑，都沒有隨機數 — **confirmed**

完整算式在 `docs/re/08` §5。

### 勢均力敵（雙方戰力都在 4 倍之內）

```
pct = Round(戰力E / 戰力F × 100)        ; E 是兵種 4 時再除以 2
損失F = 兵力F / 4 × pct/(pct+100)
損失E = 兵力E / 4 × 100/(pct+100)
```

兩個係數相加恆為 1，所以**雙方損失比例合計恆為各自兵力的 1/4**。
戰力相等時各損 1/8；E 是 F 的 3 倍強時，F 損 3/16、E 損 1/16。

### 一面倒（任一方戰力 ×4 還追不上對方）

```
人力值 = 兵種權重 × 兵力
if 對方攻擊值 × 10 >= 人力值:  全滅
else:                         損失 = 對方攻擊值 × 10 / 兵種權重
```

兩條分支自洽，損失永遠不超過兵力——**全滅是設計出來的門檻**。

### 沒有隨機數

兩支都不呼叫 `Random`。這與 §3b 記的「九步結算都沒有 `Random`」一致
——**戰鬥結算是完全決定性的**，隨機性（如果有）在別處介入。

### 兵種 4 的兩條特例

1. 勢均力敵時 `pct` 減半
2. **任一方是兵種 4，F 就完全不受損失**

## 4. 六角格 — **confirmed（排列）／未知（鄰接規則）**

原本記的矛盾點（「戰場資料是 14×14 方格，不是六角」）**解消了**：
資料確實是 14×14，六角是繪製與鄰接的解讀方式，兩者不衝突。

## ⭐ 必勝門檻：戰力差到五倍就跳過過程 — **強證據**

（`WAR.EXE`，`sub_3A817`／`sub_3AA51`／`sub_3B19C`；`docs/re/31` §16）

戰鬥 AI 的決策鏈每一輪都會問一次：

> **有沒有一方的戰力總和不到對方的五分之一？**

有的話就不再逐格打，直接呼叫九步結算（本檔 §3）判勝負，
勝方就是戰力占優的那一方。

```
第二方 × 5 ≤ 第一方  → 決策值 A=11 → sub_3B19C(0) → 第一方勝
第一方 × 5 ≤ 第二方  → 決策值 B=1  → sub_3B19C(1) → 第二方勝
```

「戰力」是雙方各 10 個單位的攻擊力總和（`sub_5A0B9`，本檔 §2）。

⚠️ 標**強證據**不是 confirmed：分派鏈與參數順序都對得起來，
但沒有實機驗過「戰力差五倍時戰鬥確實秒結束」。
驗法：DOSBox 擺一場一面倒的戰鬥，看是否跳過逐格階段。

## ⭐ 預備隊隨優勢反向調整 — **強證據**

（`WAR.EXE`，`sub_3C26A`／`sub_58D4A`；`docs/re/31` §17）

電腦在戰場上不會一次投入全部單位，會留一批待命。留幾個由
**首位單位對敵軍全體的優勢等級**決定：

| 首位單位戰力 vs 敵軍總和 | 優勢等級 | 留幾個待命 |
|---|---:|---:|
| ≥ 兩倍 | 2 | **0**（全部投入）|
| ≥ 一倍 | 1 | **1** |
| 不足 | 0 | **2** |

首位單位是否親自投入也看同一個等級：等級 2 時設命令 3（主動找目標）、
等級 1 時設命令 4（較保守），**等級 0 時不動**。

⚠️ 「首位單位 = 主將」是推論（`docs/re/31` §20），沒有直接證據。

⚠️ 「一個人對全軍」看起來不對等，但攻擊力公式吃能力值與兵力，
首位單位通常是全軍最高的那個。這是原版寫法。

⚠️ 首位單位要不要動還有一道前置：**兵少（≤ 5 個單位）但打得順，或幾乎沒人
在找目標了**（命令 3 的數量 ≤ 1）。也就是說它是**最後才押上去的牌**。


## ⭐⭐ 電腦怎麼挑攻擊目標：最近的敵方城市 — **強證據**

（`WAR.EXE`，`sub_3C89A` → `sub_3B492` → `sub_3B400`；`docs/re/31` §19／§21）

戰鬥 AI 的預設行動每一輪都做同一件事：

1. 掃全場找出所有城市格（最多 10 個）
2. 每個城市算一個分數
3. 照分數**由小到大**排
4. 取第一個正分的當目標

分數就是**首位單位到那個城市的距離**（曼哈頓距離，欄數 14），
而且只有**敵方（守方）佔據的城市**才算分，其餘一律 0。

> **挑距離最近、由敵方佔據、而且還沒有人去的城市。**

「還沒有人去」是一道剔除：某個攻方單位的下一跳正好是那個城市、
而且它的命令是 5，那個城市就從候選清單移除。

⚠️ 兩件事值得記在心上：

- **距離用的是矩形的曼哈頓距離，戰場卻是六角格。** 原版沒有做六角修正，
  所以電腦對「哪個城市比較近」的判斷本身就帶偏差——斜向的城市會被高估距離。
  remake 照抄這個行為。
- **沒有任何「價值」的考量**：城市的守軍多寡、地形、戰略位置都不進分數。
  純粹比距離。這是改進電腦 AI 時最明顯的施力點（`70-ai.md` §未來工作）。

### 選定之後怎麼派人

只有命令 3 與 4 的單位會被派出去（`docs/re/31` §23／§24）：

| 選中的城市 | 目標 | 走法 |
|---|---|---|
| **有守軍** | 那個守軍 | 全員往城市走 |
| **空著** | 附近第一個**走得通**的敵方單位 | 各自往自己的目標走 |

⭐ 城市空著時電腦**不是去佔領，而是改去追人**。
「走得通」是實際跑一次尋路，走不到就換下一個目標。

（`WAR.EXE`，`sub_3F698` 分派表；`docs/re/31` §3／§19／§29）

電腦每一輪在戰場上先跑一條決策鏈，選出四種行動之一：

| 決策值 | 行動 | 做什麼 |
|---:|---|---|
| 1 | `sub_3B19C(1)` | **必勝結算**——戰力差五倍時直接判勝負 |
| 2 | `sub_3B31D` | **佈防**——以主力為中心把周圍三圈的格發給沒去處的單位 |
| 3 | `sub_3C89A` | **打城市**（預設行動）|
| 4 | `sub_3CA09` | **打敵方主力周邊** |

值 3 與值 4 的骨架完全一樣，只差「以什麼為中心找目標」：

- **值 3**：掃全場城市 → 照距離排序 → 挑最近的敵方城市 →
  全員往那裡走（城市有守軍）或改追附近的人（城市空著）
- **值 4**：直接以**敵方主力所在格**為中心，找它周圍兩格內的單位當目標

兩者都只派命令 3 與 4 的單位，都用「逐一試尋路，第一個走得通的就是目標」。

值 2（佈防）的細節：以第一方首位單位所在格為中心，取周圍**三圈共 37 格**
當位置表，依序發給還沒有去處的單位；**已經站在城市上的不動**。
首位單位自己分到第一格（也就是原地）。

⭐ 這是四種行動裡唯一不帶攻擊意圖的一種——電腦在這一輪只是把陣形攤開。

值 1 的觸發條件見本檔「必勝門檻」。**四種行動現在都有語意了。**


## 「做過了」的旗標：兩層同一個手法 — **confirmed**

（`WAR.EXE`，`docs/re/14` + `docs/re/31` §31）

這份程式用同一個手法管兩層的「這一輪處理過了」：

| 層 | 欄位 | 設 | 清 | 讀 |
|---|---|---|---|---|
| 省份 | `+32` bit 2 | 玩家下完命令／電腦開始跑 | 回合重置（全 39 省）| 立起來就不進玩家選單 |
| 戰場單位 | `+13` bit 7 | AI 決定好目標之後 | `sub_3E81F`（連同 `+10`／`+12`）| 立起來就跳過 |

單位那一層的三個欄位是**一組**：`+10` 目標單位、`+12` 下一跳、`+13` bit 7
「已指派」。一起設、一起清——看到其中一個就要想到另外兩個。


## 電腦的斬首戰術 — **強證據**

（`WAR.EXE`，`sub_3D823`；`docs/re/31` §34）

勢均力敵時（雙方戰力比在 0.67 附近），電腦不去打城市，也不挑最近的目標，
而是**全軍撲向敵方主帥**——第一方單位陣列的第一格，通常是全軍最強的那個。

有兩種強度：

| | 留守 | 出擊 |
|---|---|---|
| **積極**（決策值 14）| 只留**一個**在城市駐守 | 其餘全部，包含其他本來要去駐守的 |
| **保守**（決策值 15）| **所有**駐守中的都留下 | 只派沒在駐守的 |

⚠️ 兩者在原版是同一支函式，只差一個參數。**15 比 14 保守**——
這與編號直覺相反，讀原版程式碼時很容易搞反。

⭐ 這是電腦四種攻擊型行動裡唯一不看距離也不看城市的一種。
改進 AI 時值得注意：原版已經有「斬首」的概念，只是觸發條件很窄。


## ⭐ 守方主帥親自坐鎮會改變電腦的打法 — **強證據**

（`WAR.EXE`，`sub_56D49`；`docs/re/31` §44）

電腦在戰場上有一個判斷貫穿四種行動：

> **當前交戰省的司令本人，有沒有在守方的隊伍裡。**

原版的作法是掃守方的十個單位，看有沒有一個就是該省的司令
（省份記錄 `+20`）。四個決策點共用這個判斷：

| 決策值 | 行動 |
|---:|---|
| 4 | 打敵方主力周邊 |
| 16 | 只處理待命與已出發的單位 |
| 17 | 重算全軍的行動 |
| 19 | 全面接戰 |

主帥不在場時，這四種行動都不會被選中，電腦會落到比較保守的選項
（打城市、預設分流）。

⭐ 這條規則有史實味道：那個年代打不打、怎麼打，確實常取決於
對方是誰在指揮（見 `docs/reference/history/40-warlord-politics.md`）。
**改進 AI 時值得保留這個概念**——它比「純比戰力」有意思得多。

## 2. 人口 — **confirmed**

省份記錄 `+12` 的 u32，單位是人；畫面顯示除以 10,000 的「萬」。
湖北 18,250,000 → 畫面「1825 萬」。

數值符合民國初年的實際人口分佈（四川 3,639.8 萬最多、河南 2,794 萬、
山東 2,715 萬、河北 2,410 萬）。

### 每年成長 10%，到 100 萬封頂 — **confirmed**

年度結算 `sub_30003`（`docs/re/25` §2）逐省做：

```
人口 < 1,000,000 時：人口 += Trunc(人口 ÷ 10)
```

- **一年一次，不是每回合。** 這是它一直沒被發現的原因。
- `1,000,000` 是硬門檻（`0x000F4240`）。到頂就完全停住，不是變慢。
- `Trunc` 捨去，所以人口不足 10 的省一個人都不長。
- 交戰中、無主的省照樣成長——這一段不看旗標。

⛔ **`docs/re/21` §3 曾寫「人口只減不增」，那是錯的**，成因是掃描 pattern
漏掉相對定址（`docs/re/22`）。

人口影響什麼——仍**未知**。

## 5b. 資源上限是 60000 — **confirmed**

`sub_5A467(上限, 加數, 目標)` 是全遊戲通用的「累加並夾上限」，
被 **56 處**呼叫，每次都傳 `0xEA60 = 60000`：

```
v = *目標 + 加數        ; 32-bit 運算，不會中途溢位
if v > 上限: v = 上限
*目標 = v
```

資源欄位本身是 u16（能裝到 65535），但實際上限是 60000。
五個資料檔的所有資源值都在其下，最大的是彈藥 **53,692**——逼近但未超過。

### [雷] 中間運算是 32-bit

直接用 u16 相加會先溢位再夾，結果完全不同：
`50000 + 20000` 在 u16 是 4464，夾完還是 4464，但原版給 60000。

## 5c. 戰後的省份資源結算 — **confirmed**

`sub_546D1`（九步結算的第三步）：

```
ptr = 省份記錄
ptr[+0] = 0    ; 黃金
ptr[+2] = 0    ; 糧食
ptr[+4] = 0    ; 彈藥
ptr[+8] = 0    ; 燃料
sub_5A467(ptr+0, 攻方黃金 + 守方黃金, 60000)
sub_5A467(ptr+2, 攻方糧食 + 守方糧食, 60000)
sub_5A467(ptr+4, 攻方彈藥 + 守方彈藥, 60000)
sub_5A467(ptr+8, 攻方燃料 + 守方燃料, 60000)
```

也就是**戰後省份的四種資源 = 雙方各自帶的量相加，夾到 60000**。

### 煤礦與鐵礦不參與

原版只歸零了 `+0`／`+2`／`+4`／`+8`，**沒有碰 `+6`（煤礦）與 `+10`（鐵礦）**。
那兩者是省份的礦藏，不隨部隊移動，戰後維持原值。設計上完全說得通。

### 這解掉了 RE-05 的一個觀察

`docs/re/05` §2 記過「四個 u16 的目標位址間隔 4」而不知為何。
現在清楚了：**每個欄位是一對**（`word_64932`／`word_64934` 是攻守雙方的
黃金），所以間隔是 4 不是 2。

## 6. 「產能」是一組可分配的量 — **confirmed（機制）／假說（欄位對應）**

> 2026-08-01 更新：**指令 8「政策」就是產能分配畫面**（`docs/re/26`）。
> 下面原本的推測基本成立，但欄位位置比推測的更明確。

`sub_23511`（1,147 行）畫的是「本省產能」，五個項目各一個 ％：
**黃金、鐵礦、煤礦、石油、糧食**，加一個「剩餘」。輸入提示是
「司令〈某〉欲調整為多少？」。

省份記錄存四格（`+33`–`+36`，初始全部 25），第五個是算出來的：

```
剩餘 = 100 − (+33 + +34 + +35 + +36)
```

初始 25×4 = 100，所以開局的「剩餘」是 0。

⚠️ **哪一格對應哪一種資源還沒定**——資源名與數值是分兩批呼叫印的，
座標序列還沒對齊。`docs/re/26` §3 記了為什麼不現在猜（`+2` 被誤名為
「開發能力」的教訓）。

以下是解出 `sub_23511` 之前的推論，保留當紀錄：

`4.15` 有「**產能分配**」(27)、「鐵礦產能」(28)、「煤礦產能」(29)、
「石油產能」(30)、「糧食產能」(33)、「**礦藏指數**」(31)。

所以資源不是固定產出，而是**玩家分配產能**的結果。
§1 記的「彈藥 +6,000、煤鐵各 −6,000」很可能就是產能分配造成的，
不是每月固定公式——**那條假說要重新檢視**。

### 兩個待釐清的點

1. **「石油」與「燃料」是兩個不同的詞**（`2.15` 139 石油、26 燃料）。
   省份記錄的資源欄位對應「燃料」，而產能用的是「石油」。
   可能石油是產出、燃料是庫存，未確認。
2. **「礦藏指數」**暗示每省有礦藏上限或品質參數，
   但省份記錄的 37 bytes 裡沒找到對應欄位。

   → **部分有解**：挖金礦 `sub_24535` 讀的正是一張**獨立於省份記錄之外**的
   byte 表（`ds:11h` 起，以省編號為索引，stride 1）。找不到欄位是因為
   它根本不在那 37 bytes 裡。表的語意仍未直接證實，但位置與形狀都對得上
   「礦藏指數」。見下方 §7b。

## 7b. 挖金礦的產出公式 — **confirmed（公式）／假說（礦藏表）**

開發指令的第二項，`sub_24535`（`docs/re/21` 定位、本輪解出常數）：

```
黃金 += Random(礦藏 + 政治手腕 ÷ 10) × 50 + 200      夾到 60000
體力 −= 5
```

| 項目 | 值 | 依據 |
|---|---|---|
| 體力門檻 | 20 | `cmp byte ptr [di+7A9Ah], 14h` |
| 體力消耗 | **5** | `sub byte ptr [di+7A9Ah], 5` |
| 亂數係數 | 50 | `mov dx, 32h / mul dx` |
| 保底 | 200 | `add ax, 0C8h` |
| 上限 | 60000 | `cmp word ptr [di-6235h], 0EA60h` |

[雷] **門檻是 20 但只扣 5**，兩個數字不同，別混用。

`Random(n)` 回 `[0, n)`（`docs/re/17`），所以產出範圍是 `[200, 200 + 50×(n−1)]`
——運氣再差也有 200，不會空手而回。

政治手腕除以 10 的寫法與墾地、慰勞完全一致（`DevelopPoliticsDivisor`），
是這個遊戲裡「將領能力換算成成效」的通用手法。

## 8. 商業活動（指令 12）＝ 買賣資源 — **confirmed**

`docs/re/27` 從畫面文字定位。兩個選單，各自帶一組品項：

| 方向 | 選單 | 品項 | 各自的函式 |
|---|---|---|---|
| **進口（買）** | `sub_1D703` | 糧食、彈藥、燃料 | `sub_1CB96`／`sub_1CF62`／`sub_1D32E` |
| **出口（賣）** | `sub_1ED95` | 糧食、彈藥、煤礦、鐵礦、燃料 | `sub_1DAA8`／`sub_1DE6E`／`sub_1E234`／`sub_1E5FA`／`sub_1E9C0` |

畫面上的話：「司令欲**購買**多少糧食？」「共用〈N〉」／
「司令欲**拋售**多少糧食？」「共得〈N〉」。

### 三件讀得出來的設計

1. **煤礦與鐵礦只能賣不能買。** 兩者是兵工廠的原料（§7），
   賣掉是把原料換現金，但買不回來——**煤鐵只能靠本省產能**。
2. **黃金兩邊都沒有**，它是貨幣不是商品。
3. 進口用「購買／進口」、出口用「拋售／出口」兩組詞，
   失敗訊息也分開（「無法進口彈藥」／「無法出口煤礦」）。

### ✅ 匯率全解 — **confirmed**

八支買賣函式的形狀完全相同，只差匯率與動到哪個欄位：

```
成本（或所得）= 數量 ÷ 匯率      ; Longint 除法，@$brdiv
若結果為 0 → 取 1                ; 保底
資源 ±= 數量
黃金 ∓= 成本
```

匯率＝**多少單位換 1 黃金**，全部出自 `@$brdiv` 前的 `mov cx, N`：

| 資源 | 匯率 | 進口 | 出口 |
|---|---:|:---:|:---:|
| 彈藥 | **10** | ✅ | ✅ |
| 煤礦 | 20 | ❌ | ✅ |
| 鐵礦 | 20 | ❌ | ✅ |
| 糧食 | 30 | ✅ | ✅ |
| 燃料 | 30 | ✅ | ✅ |

三件讀得出來的事：

1. **買賣同價。** 進口與出口用同一個除數，**原版沒有價差**——
   資源可以無損地換來換去，只受上限與保底影響。
2. **彈藥最貴**（10 換 1，是糧食燃料的三倍），煤鐵居中。
   與兵工廠「2000 煤 + 2000 鐵 → 2000 彈藥」對照：
   自產 2000 彈藥的原料值 200 黃金，直接買要 200 黃金——**完全等價**。
3. **保底 1**：買 1 顆糧食也要付 1 塊（`or ax,dx / jnz / mov var,1`）。

步兵徵兵的「10 兵 = 1 金」與彈藥同價；其餘兵種另有匯率：玩家側騎兵
5 人／金、砲兵 1 人／金、裝甲兵 1 人／10 金（四支函式的乘除與扣金資料流
均已證實，見 `docs/playtest/10-recruit-economics.md`）。

實作在 `internal/game/trade.go`。

2026-08-02 已接進 Ebiten 政略介面：指令頁按 `T`，依序選進口／出口、
品項並輸入數量。三層畫面使用原版 `2.15` 的詞條；Docker Xvfb 實測買進
300 糧食後，黃金 4200→4190、糧食 18050→18350、指令數 2→1，規則層回報
「購買糧食 300，共用黃金 10」。《重製版》以 `T` 作為指令 12 的快捷鍵，
屬於現代操作外殼差異；買賣規則仍照原版。

**仍未讀**：黃金不足／資源不足時原版怎麼處理（`sub_1D703` 有
「無法進口彈藥」的訊息，但檢查點還沒對上）。remake 目前直接擋下來並回錯，
已在程式碼標為 remake 行為。

## 9. 運補（指令 3）搬四種資源 — **confirmed**

`sub_3231A` 依序問四次：「司令欲調動多少**黃金**／**糧食**／**彈藥**／**燃料**？」

### 目標省限制 — **confirmed**

`sub_2CB6B+6F..+106` 直接依來源省的八格鄰接表順序掃描，只列出：

1. 有效的鄰省編號；
2. 司令與來源省相同；
3. 省份 `+32` bit 6 未設，也就是未交戰。

因此運補不是任意跨省傳送，也不能送往敵省、無主省或正在作戰的友省。
候選順序不另排序，remake 的 `SupplyTargets` 保留原鄰接表順序。

### ✅ 搬運函式：四支各 100 行，結構完全相同

| 函式 | 資源 | 省份欄位 |
|---|---|---|
| `sub_3083A` | 黃金 | `+0` |
| `sub_30918` | 糧食 | `+2` |
| `sub_309F6` | 彈藥 | `+4` |
| `sub_30AD4` | 燃料 | `+8` |

**煤礦與鐵礦沒有對應的函式**，再一次印證「不可流動的原料」。

簽名是 `f(amount: ^Longint; to, from: byte)`，語意：

```
dst = 目標省的量 + amount        ; 32-bit，不會中途溢位
來源省 −= amount
若 dst > 60000:
    溢出 = dst − 60000
    目標省 = 60000
    來源省 += 溢出               ; ← 退回來源省
否則:
    目標省 = dst
amount^ = 來源省的減少量         ; 回傳實際搬走的量
```

### ⭐ 超過上限的部分**退回來源省**

這是本條最重要的細節：目標省滿了的話，多的資源**不會憑空消失**，
而是留在來源省。**總量守恆。**

⚠️ 這與 `AddResource`（`sub_5A467`）的「直接截斷」是**不同的行為**。
兩者在原版是兩支不同的函式，remake 也不能混用——
`internal/game/supply.go` 已標明「別把這裡換成 AddResource」。

### 🔍 新線索：調動也會搬資源

`sub_1408F`（調動執行層，`docs/re/10`）的 `+631` 也呼叫 `sub_3083A`，
而且傳進去的量是**來源省的黃金全額**：

```
ax = [來源省 +0]            ; 全部黃金
var_A = ax
sub_3083A(&var_A, 目標省, 來源省)
```

形狀像「調動時把資源一起帶過去」，與 `docs/re/10` 記的「調動即佔領」
可以接起來（佔領無主省時把補給帶過去）。

⚠️ **上下文不足以定論**——那一行在哪個分支、四種資源是不是都搬、
是不是只在佔領時發生，都還沒讀。**沒有實作**，記為線索。

**煤礦與鐵礦不能運補**——與 §8 的「不能進口」是不同的限制，但方向一致：
這兩種資源綁在產地，只能就地用掉或賣掉。

外援給的也正好是這四種（`50-diplomacy.md` §1），
所以「黃金／糧食／彈藥／燃料」是這個遊戲裡**可流動的資源**，
煤鐵是**不可流動的原料**。這個二分在三個地方一致，不是巧合。

2026-08-02 已接進 Ebiten 政略介面：指令頁按 `S`，輸入畫面列出的目標省編號，
再依原版順序輸入四項數量。每項輸入上限是來源省當下庫存；全 0 視為取消。
Docker Xvfb 以湖北→河南實測 100／200／300／400，湖北四項資源逐項精確扣減，
指令數 2→1，規則層的目標增加與超額退回測試亦通過。`S` 是 remake 的現代快捷鍵。

# 13 — 開新遊戲的設定畫面：「電腦個性：和平／好戰」

> 環境：`fd2-dosbox-screenshot-local`、DOSBox 0.74-3、Xvfb :99、`play.bat`
> 日期：2026-08-01

先前的實測一律走「載入存檔」（`docs/playtest/02`、`06`）。這次走**開新遊戲**，
拿到三個先前沒見過的畫面，其中一個直接回答了一個標成 confirmed 的錯誤結論。

---

## 1. 進入序列

```
Return → 2 → Return → 1 → Return → 1 → Return    片頭與選單
1                                                 玩家人數（1–9）
Return
2 / 3 / 7                                         屬性三選（見 §3）
Return → Return → Return
1 → Return                                        密碼（三選一任選）+ **確認**
```

到這裡就是政略畫面：**民國 15 年 7 月 秋**，畫面停在玩家的某個省，
底部是「司令，請下命令？(1-15)」與右下的「指令數：1」。

### [雷] 密碼要按 Return 確認，`space` 對它無效

第一次長跑在密碼畫面按了 **40 次 `space` 完全沒推進**——
輸入的數字顯示在畫面上，但沒有送出。`docs/playtest/02`／`06` 記的
「三選一任選都能過」是對的，漏記了**還要 Return**。

症狀很容易誤判成「送鍵失效」（`docs/playtest/03` 那一類環境問題），
但實際上鍵有進去，只是少了確認那一下。**分辨方法：看畫面上數字有沒有出現。**

⚠️ 屬性畫面**每一組要各選一個**，勾選符號 `✓` 會停在選中的那一列。
送鍵太快會被吃掉——第一次跑只勾到「3 高」與「7 進階者等級」，
`2` 那一下沒進去。每個 `key` 之間留 2 秒才穩。

### [雷] 不同次跑的起點省不同，**地圖不可跨 run 比較**

第一次跑進去停在江蘇（第 2 省），第二次停在浙江（第 23 省），
兩張地圖的無主省顏色也不一樣。要看「電腦有沒有擴張」，
**只能在同一次 run 的前後截圖之間比**。

## 3. ⭐ 屬性設定：三組七個選項 — **confirmed**

```
電腦個性        1. 和平    2. 好戰
人工智慧等級    3. 高      4. 低
遊戲難易程度    5. 初學者等級   6. 入門者等級   7. 進階者等級
```

### 「好戰」的存在推翻了「電腦不會攻打」

`docs/re/12` 曾把「**這是玩家主動制的戰棋，戰爭只能由玩家發動**」標成 confirmed。
`docs/re/29` 已用靜態證據推翻（電腦會填參戰部隊表）。

**這個畫面是獨立的第二證據，而且是玩家直接看得到的**：
如果電腦永遠不主動開戰，「和平 vs 好戰」這個設定沒有任何意義。

順帶解掉一個懸案：`docs/re/23` §5 記過 `2.15` 詞 29 是「好戰和平」，
當時不知道用在哪。**就是用在這裡。**

### 三組設定對應 `byte_6FFCA` 的位元 — **confirmed（IDA 2026-08-11）**

`sub_38DFE` 的直接寫入已把三組選項與位元對應閉合；這不等於每個位元在所有
AI 分支的最終語意都已解完，但「設定畫面寫哪一組」不再是假說：

| 畫面 | 選項數 | `byte_6FFCA` 的候選位元 | 依據 |
|---|---:|---|---|
| 遊戲難易程度 | 3 | **bit 4／5／6**（三選一）| `sub_38DFE` `38F53h..3908Dh` |
| 人工智慧等級 | 2 | **bit 2／3**（二選一）| `sub_38DFE` `38EB1h..38F4Ah` |
| 電腦個性 | 2 | **bit 0／1**（二選一）| `sub_38DFE` `38E00h..38EA8h` |

`sub_390B6` 要求三組旗標都已選定並按 Enter 才繼續；每組寫入前會清除同組其餘
位元，再 OR 目標位元。至於 bit 0／1、bit 2／3 在各 AI 使用點的完整行為，仍以
`docs/mechanics/70-ai.md` 的分支證據為準，不能只因畫面名稱就自行命名。

## 4. 政略畫面的地圖是彩色的勢力圖

先前的截圖都在存檔局面下取，這次看到**全彩勢力範圍圖**：
每個勢力一種顏色，省份編號疊在上面（1–36 可見）。

這對驗證「電腦會不會打過來」是理想的觀察量——**顏色分佈變化 = 省份易主**，
不必進去逐省查數值。

## 5. ⛔ `space` 不推進回合——240 次按下去，局面幾乎沒動

這次的目標是驗 `docs/re/29`（電腦會不會出兵），做法是長跑後比對地圖顏色。
**結果是這個方法不成立**，原因在操作而不在結論。

跑了 240 次 `space`（分 8 段截圖），用 `tools/map_diff.py` 逐段比對地圖區：

| 區段 | 地圖區相異 | 判讀 |
|---|---:|---|
| x00→x01 | 1.08% | 一個省的顏色從亮綠換成另一種綠 |
| x01→x02 | **0.00%** | 完全沒動 |
| x02→x03 | 0.22% | 只有游標框（104 px，深藍↔面板色）|
| x03→x04 | 0.22% | 同上，反向 |
| x04→x05 | **0.00%** | 完全沒動 |

而畫面上的日期**全程停在民國 15 年 7 月**。

`docs/playtest/06` §5 早就寫著「`space` = 換到自己的下一個省（**不是換月**）」，
同一份 §171 也記了關鍵機制：

> 切完觀戰之後畫面右上角的省編號從 26 變成 19——**指令數用掉一個**……
> 所以「用指令推進回合」是可行的，不需要另外找「結束回合」的操作。

`sub_10193` 裡的 `cmp byte_6FE81, 0`（「這次指令有沒有**真的執行**」）就是閘門：
**`space` 只換視角，不執行指令，所以指令數不減、回合不推進。**

要推進時間，得反覆下**真的會執行**的指令（徵稅、慰勞、開發…），
把每個省的指令數用完。以孫傳芳五省、每省 1–2 個指令算，一個月要十次左右
的完整操作序列——**用送鍵的方式跑十幾個月成本很高**。

### ⛔ 觀戰模式**不會**讓遊戲自己跑

指令 15「其他選項」的第 7 項是**觀戰**（`docs/playtest/06` §6，
對應 `byte_7003B`）。設定選單長這樣：

```
1.儲存遊戲   2.載入遊戲   3.音效開關 OFF   4.指令圖畫 ON
5.音樂開關 OFF   6.訊息時間 5   7.觀戰 OFF   8.結束遊戲
```

按 `7` → `Return` → `y` 之後**確實切成「觀戰 ON」**，
但關掉選單回到政略畫面後，**遊戲仍然停在「司令，請下命令？」等玩家輸入**。

空等 200 秒（分五段截圖）逐段比對地圖區：

| 區段 | 相異 |
|---|---:|
| o00→o01 | **0.00%** |
| o01→o02 | **0.00%** |
| o02→o03 | **0.00%** |
| o03→o04 | 0.22%（只有游標框 234 px）|
| o04→o05 | **0.00%** |

**所以這個「觀戰」不是自動推進模式。**

這也解釋了一個先前沒注意到的差別：`gameover.go` 用的觀戰旗標是
**`byte_7003A`**（`sub_1060A` 的觀戰路徑，只判天下統一），
而設定選單第 7 項對應的是 **`byte_7003B`**（`70-ai.md` §2）。
**兩個是不同的變數**，先前把它們當成同一件事。
真正的「遊戲自己跑完」應該綁在 `7003A`，入口未找。

⚠️ 輸入要點：指令 15 是 `1` → `5` → **`Return`** 才進子選單。
少了 `Return` 的話後續按鍵會被當成數字接在後面（實測畫面出現 `157`）。
子選單的 `7` 也一樣要 `Return`。

## 5b. 這次沒能回答「電腦會不會攻打」——記下試過什麼

`docs/re/29` 待驗的那條（實跑十幾個月看電腦會不會打過來）**仍未完成**。
照 `CLAUDE.md` §2「卡關就換方法，記錄卡在哪、試過什麼」列出來：

| 路徑 | 結果 |
|---|---|
| 240 次 `space` | ❌ 不消耗指令數，回合不推進（§5）|
| 開觀戰後空等 200 秒 | ❌ 仍等玩家輸入，局面 0.00% 變化 |

### ✅ 找到最短的推進序列：練兵，四個按鍵

指令 **13 是練兵**（不是休息——`docs/re/27` 的 `sub_1C916`，
畫面直接寫「**司令欲練兵嗎？(Y/N)**」）。完整序列只要四個鍵：

```
1 → 3 → Return → y
```

實測**指令數從 2 掉到 1**，確認它走的是「指令真的執行」那條路
（`sub_10193` 的 `byte_6FE81`）。這就是推進回合最便宜的操作。

⚠️ 這裡也再次踩到 §1 的 `Return` 規則：`1` `3` 之後要 `Return` 才觸發，
而 Y/N 提示則是直接按 `y`，**不用再 Return**。
「數字要 Return、Y/N 不用」——兩種確認方式並存。

估算成本：玩家五個省 × 每省 1–2 個指令 ≈ 一個月 10 次序列 × 4 秒 = 40 秒。
跑 12 個月約 8 分鐘，DOSBox 端完全可行。

⚠️ 在這條驗完之前，`docs/re/29` 的結論維持**強證據**不升級。
靜態證據（三方共用參戰部隊表）與實機的「好戰／和平」設定都指向同一個方向，
但「電腦真的會打過來」還沒有人親眼看到。

## 7. 2026-08-09 直接啟動 `WAR.EXE` 的開局按鍵勘誤

本節是對本檔 §1 與 `docs/playtest/16-dt2-live-battle-snapshot.md` 舊時間線的
**追加勘誤**，保留舊證據，不覆寫歷史。測試直接執行 `WAR.EXE`，不是透過
`play.bat` 的外層播放器；環境仍為 `fd2-dosbox-screenshot-local`、DOSBox 0.74-3、
Xvfb `:99`、US keymap，輸入由 `tools/dosbox_runner.sh` 的 `key`／`wait` 送出。

### 7a. `Return` 不是「重新開始」

直接啟動後的第一張畫面明確寫著：

```text
1. 重新開始
2. 載入遊戲
您的選擇（1-2）
```

在這個畫面按 `Return` 會保持原畫面；接著按 `2` 會勾選「載入遊戲」，再按
`Return` 才進入「進度一～十」選單。因此舊時間線開頭的
`Return → 2 → Return` **不能宣稱是新局入口**；在直接 `WAR.EXE` 的條件下，它
實際上是載入流程。這解釋了先前「屬性設定後直接落到政略／調動子選單」的矛盾畫面：
那幾輪是載入既有進度，不是開新局。

### 7b. 可重播的新局時間線

本輪用下面的序列才真正勾選「重新開始」：

```text
1 → Return                         重新開始、進歷史背景
2 → Return                         第二章歷史背景
1 → Return → 1 → Return           片頭後選單
1 → Return                         玩家人數 1
2 → Return                         選擇第 2 位勢力
2 → 3 → 7 → Return ×3             好戰／高 AI／進階者
1 → Return                         密碼選項與確認
```

這條路徑曾在密碼確認後取得真正的戰鬥畫面：「山西省（16）、7 月 1 日、日本攻擊
中國、放置閻錫山的軍隊」。另一次同一序列在約 2 秒顯示「進入戰場中…」，約 4 秒
進入部署畫面；也有輪次在等待期間回到政略畫面。這是**正常玩家路徑中的 AI／亂數
分岔**，不是固定觸發器；因此只把「開局輸入契約」標為 confirmed，不把某一場
戰鬥當成 deterministic gate。

### 7d. 同一路徑連續練兵的指令上限觀察

為確認 runner 不會在動畫期間把按鍵灌入錯誤畫面，另以同一個 `SAVE(1)` 載入路徑

# 政略 AI 第一次連續跑：兩個省互相搬兵二十回合

日期：2026-08-01
工具：`tools/go.sh run ./cmd/aisim -turns 20 -v`
資料：原版 `SAVE(1).DT1`、`MAN(1).DAT`

`docs/playtest/04` 把戰鬥層跑起來，這次輪到政略層。決策鏈
（`docs/mechanics/70-ai.md`）加上剛解出的執行層（`docs/re/10`）
一接起來，就跑出了單元測試看不出來的問題。

**這不是 DOSBox 實測**，是我們自己的規則層在跑。

---

## 1. 第一次跑：局面五回合就凍結

```
開局：      勢力 9／有主省 29／無將領的省 13／最集中：省 19 有 25 人
第  5 回合： 勢力 9／有主省 29／無將領的省 12／最集中：省 23 有 26 人
第 20 回合： 勢力 9／有主省 29／無將領的省 12／最集中：省 23 有 26 人

決策分佈
  sub_150FC 一般調動   60
  sub_1527A 增援前線    1
  sub_1541E 撤回後方  120
  sub_15667 分兵      100
  sub_15925 攻打      160
累計搬動 150 人次
```

220 次調動決策只搬了 150 人次，而且全發生在前五回合。**局面完全不動。**

## 2. 第一個病灶：決策說要調，執行挑不到人

決策層與執行層的條件**不一樣**：

| | 條件 |
|---|---|
| `sub_1541E`（決策）| 省內有**缺員**的部隊 |
| `sub_1408F` 模式 4（執行）| 該部隊**低於四分之一滿** |

缺員但沒那麼缺的時候，決策說要調、執行一個人也搬不動。

原版對這件事有回饋，而我第一版沒有：

```asm
call    sub_1408F
cmp     [bp+var_1], 0
jz      短路                    ; ← 沒搬成就不立「已決定」旗標
...
mov     byte ptr ss:[di-7], 1
```

**旗標沒立，決策鏈就繼續往下走。** 補上這個回饋（`AIWorld.Step`）之後：

```
撤回後方 120 → 10　　分兵 100 → 0　　攻打 160 → 289
```

空轉的決策被吃掉，鏈往下走到攻打。

## 3. 第二個病灶：一般調動的目標條件寫反了

補完回饋之後，`-v` 顯示的是這個：

```
T02 省 27 → 35　sub_150FC 一般調動　模式 4　搬 3 人
T02 省 35 → 27　sub_150FC 一般調動　模式 4　搬 3 人
T03 省 27 → 35　sub_150FC 一般調動　模式 4　搬 3 人
T03 省 35 → 27　sub_150FC 一般調動　模式 4　搬 3 人
...每回合重複到第 20 回合
```

**兩個省每回合互相搬同樣的 3 個人。** 回去讀 `sub_150FC`：

```asm
cmp     word ptr [di-6221h], 0   ; 省份[鄰省].+20（司令）
jnz     short loc_15219          ; ← loc_15219 是 skip
```

`jnz` 跳的是 skip，所以留下來的只有**司令 == 0** 的省
——一般調動**只往無主省**。我的第一版寫成「無主省不調」，正好相反。

配上 `sub_14F9A`「調動成功後把目標省的司令改成我方」，
一般調動的語意其實是**往無人的省份擴張**。

改回來之後一般調動降到 0 次，抖動消失。

### 為什麼單元測試沒抓到

測試驗的是「決策有沒有回傳合法的目標」，而互搬的兩個省在每一步
都完全合法。**要看到問題必須讓它連續跑很多回合並觀察狀態演變**
——`CLAUDE.md` §7 第 7 條講的是畫面 bug，這裡是同一件事的規則層版本。

## 4. 順帶抓到的兩處：`sub_15667` 讀漏了

實跑指向分兵之後，把 `sub_15667` 從頭讀了一次，發現初版：

- 漏了 `sub_13F4E` 那道守門
- 調動模式寫成 4，原版是 **3**（`mov al, 3`）

模式 3 只看清單最後兩個、且要求未達半滿，比模式 4 保守得多。

```
決策分佈

  sub_1541E 撤回後方   10
```

**這讀起來是合理的**：兵調到位就開打。

## 6. 這一輪沒有做到的

- **攻打 330 次，一場戰鬥都沒打。** `aisim` 只執行調動，
  `AIAttack` 沒有接上 `BattleSim`。所以「有主省 29」從頭到尾不變。
  這是下一步。
- **沒有與原版對照。** DOSBox 的輸入問題（`docs/playtest/03`）仍未解。
- **將領清單的順序沒驗。** `RosterOf` 照將領表序排，原版的順序在
  `sub_15F3C` 裡填，還沒讀。模式 0/2/3/4/6 挑到誰完全取決於順序
  （`docs/re/10` §7）。
- `byte_6FFCA` 的難度加成沒有進 `aisim`，跑的是預設難度。

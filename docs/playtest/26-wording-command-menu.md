## 同輪發現的 frame 錯誤路徑

首次 GUI 驗證發現，語意 renderer 成功後若過早 `return nil`，會跳過
`compose()` 尾端的 frame 提交，使畫面停在舊 frame；若首幀還沒建立，更會因
nil frame 二次 panic，遮住真正診斷。現已：

1. 所有新增的白話分支都在當前 switch 結束後繼續執行 frame 提交。
2. `Draw` 在 frame 仍為 nil 時失敗即關閉，不再解參照空指標。
3. 重跑主選單與徵兵深層流程，stderr 無「合成失敗」、panic 或缺字。

## 1. 防拷密碼：過得去

載入存檔後、進政略畫面前會問：

```
輸入密碼   說明書上
第36頁倒數第2行
第2個字
1. 在   2. 有   3. 上
```

**三選一，選 `1` 通過。**

這解除了 `CLAUDE.md` §7 第 11 條的風險（大富翁2 就是卡在密碼畫面，
DOSBox 實測整條線停擺）。這款遊戲的密碼是**三選一**，最差也只要試三次。

⚠️ **只試了 `1` 這一個選項就通過，沒有驗證「是不是隨便選都過」。**
要確認得再跑 `2` 和 `3` 看會不會被擋。在確認之前，不要斷言「密碼形同虛設」。

密碼問的是說明書第 36 頁的內容，我們沒有說明書。若日後要自動化驗收管線，
兩條路：暴力試三次，或從 `WAR.EXE` 找答案表（驗證邏輯一定在執行檔裡）。

## 3. 三件規則層面的硬事實

### 3.1 省編號 = `3.15` 的索引 + 1

畫面顯示「第 **26** 省」，而湖北省在 `3.15` 的 39 個省名裡是第 26 個（0-based index 25）。
**省編號是 1-based，順序就是 `3.15` 的順序。**

這連帶確認 `TN15.N` 的 N 就是省編號（`TN15.26` 應該是湖北的地名表——
實際內容是「漢口 武昌 漢陽 襄陽」，全在湖北 ✓）。

### 3.2 政略指令有 15 個（完整清單見 §5）

```
司令，請下命令？(1-15)
```

`2.15` 的詞表裡有 16 個詞：
`調動 軍事 運補 徵稅 徵兵 查閱 開發 政策 外交 談判 秘密 商業 練兵 休息 特殊 其他`。

已實測的三個都對得上詞表位置（1=調動、2=軍事／攻打、6=查閱），
所以**前 15 個詞很可能就是指令選單，第 16 個「其他」不是**。
但只驗過 3 個，其餘 12 個仍未試，不要全部對號入座。

`CLAUDE.md` §1.5 的社群資料說「命令 5 是徵兵」——詞表第 5 個確實是「徵兵」，
但**還沒實測驗證**。

### 3.3 命令數上限確實存在

```
指令數：2
```

`CLAUDE.md` §1.5 記「每個省份有命令數上限，用完換下一個省份」，
標為社群資料、待驗。**現在確認機制存在**，畫面右下角就顯示剩餘指令數。

上限怎麼算（固定值？依省份？依將領？）**未知**。

### 3.4 兵力超過 u16

`兵力 97500` 超過 65535，所以存檔裡不是單一 u16。
可能是 u32、或是各部隊兵力的加總（顯示時才算）。**未確認。**

## 4. 存檔對照：資源在 `.DT1`

拿畫面上的 7 月數值去搜 `SAVE(1).DT1`，找到**連續排列**的欄位：

| offset | 值 | 欄位 |
|---:|---:|---|
| 929 | 4200 | 黃金 |
| 931 | 18050 | 糧食 |
| 933 | 8787 | 彈藥 |
| 935 | 13000 | **煤礦** |
| 937 | 12048 | **燃料** |
| 939 | 14031 | 鐵礦 |

全部是 u16 little-endian，連續 6 個。

### [雷] 資料順序與畫面顯示順序不同

畫面是「燃料、煤礦」，資料是「煤礦、燃料」——**第 4、5 個欄位對調**。
remake 的 UI 要照畫面順序排，但解碼要照資料順序讀。

### `.DT1` 不是省份陣列——是整塊讀進記憶體的結構

`SAVE(1).DT2` 是乾淨的 39 × 469（`docs/re/03`），但 `.DT1` 的 14,683
不能被 39 整除（而且 14,683 很可能是質數，本來就不該整除）。

**答案在 recsize**：`WAR.EXE` 對 `.dt1` 的 `Reset(f, recsize)` 用的是 **14,683**，
也就是**整個檔案一次讀進記憶體**，不是逐筆讀的定長記錄陣列。

所以 `.DT1` 的內部佈局要從**記憶體結構**（資料被搬到哪些全域變數）反追，
不能靠「檔案大小 ÷ 省數」去切。這也解釋了下面兩次假設為什麼都失敗。

## 5A. 出兵流程（實測到的部分）

### 5A.1 指令 1 = 調動（確定）

輸入 `1` + Enter 後出現子選單：

```
1. 部份調動
2. 全部調動
司令，欲如何調動？  (1-2)
```

`2.15` 詞表第 1 個正是「調動」，子選單的「部份」「全部」也都在詞表裡。

### 5A.2 指令 6 = 查閱（確定）

輸入 `6` 之後畫面切到**河南省（第 19 省）**，正好是 `3.15` 的第 19 個。
`2.15` 詞表第 6 個是「查閱」——**查閱別省就是換省檢視**，對得上。

### 5A.3 輸入確認的規則

`2`–`9` 按下**立即生效**；`1` 會停在 `1_` 等待，因為它是 `1` 與 `10`–`15` 的共同前綴，
要再按 Enter（或第二位數字）才確定。remake 的輸入處理要重現這個差異。

### 5A.4 指令 2 = 軍事／攻打，以及出兵流程（確定）

用「一次 timeline 只測一個指令、從頭跑起」的方法重測，`2` + Enter 之後
直接進入攻打子選單：

```
司令，欲攻打何省？
(18,22,25,27,29)          ← 在湖北省(26) 時
```

`2.15` 詞表第 2 個是「**軍事**」——攻打屬於軍事，語意相符。

這也給了「攻打候選 = 鄰省 − 已控制的省」第二個樣本：湖北的鄰接表是
18,**19**,22,25,27,29，實機少掉 19（河南）——而河南的司令也是吳佩孚，
玩家同時控制這兩省。詳見 `docs/spec/01-map-and-terrain.md` §2。

選定目標省之後進入**派將**：

```
司令，欲派遣何將？
 1. 吳佩孚  20000
 2. …        6000
 …（15 位，與「將領數 15」一致）
```

輸入將領編號後，該將領前面會出現紅色 `*` 標記，而且選單**不會關閉**——
**可以多選**。結束選擇的按鍵未確認。

將領兵力的總和 = 政略畫面的「兵力」欄位，見 `docs/spec/02-generals.md`。

### 5A.5 [方法缺陷] 一次連測多個指令會失敗（已改用單指令測法）

原本想用一次 timeline 連測 `2`–`5`，每個之間用 ESC 退出子選單。**這個做法不成立**：

截圖顯示 `type:2` 之後就進了「欲攻打何省？」的子選單，
而後續的 `3`／`4`／`5` 全部是在**該子選單裡輸入省份編號**，不是主選單的指令編號。
也就是說 **ESC 在這裡不是取消，比較像確認**（語意未確認）。

所以那一輪**不能斷言「指令 2 = 攻打」或「指令 5 = 攻打」**——中間隔著一個語意不明的 ESC。
（後來用單指令測法確認 **2 = 軍事／攻打**，見 §5.4；`5` 仍未測。）

正確的做法是**一次 timeline 只測一個指令**，從頭跑起，不靠 ESC 回主選單。
慢，但結果可信。（`CLAUDE.md` §9 要求 remake 的 ESC 只做取消／退回，
那是 remake 的設計規範，不是原版行為——原版 ESC 做什麼要另外查。）

## 6. 兩次失敗的假設（記帳，避免重蹈）

`CLAUDE.md` §7 第 10 條：猜三次沒中就停手去讀反組譯。這裡猜了兩次就停。

### 假設 A：`.DT1` 的資源表是每省 12 B 的陣列 —— 錯

湖北的 6 個資源在 offset 929–939 連續，所以推測資源表是獨立一段、每省 12 B，
起點 = 929 − 25×12 = 629。

拿河南對照：實機是 5950 / 17955 / 14633 / 6055 / 12037 / 6029，
而 629 + 18×12 算出來是 0 / 25088 / 1024 / 6425 / 6425 / 2415，**完全不吻合**。
其他省的值也多半接近 65535，不像資源。

湖北會吻合只是因為 929 本來就是從湖北找到的——**用同一個資料點驗證自己，永遠會過**。
這是這次最值得記住的教訓。

### 假設 B：`.DT2` 是部隊表，u16 加總 = 兵力 —— 錯

`.DT2` 從 offset 28 起有整齊的 8 B 週期（4 個 u16），推測是部隊列表。
但湖北的 u16[0] 加總是 126（實機兵力 97500）、河南是 542（實機 140500），
四個欄位都試過，沒有一個對得上。

**有一個尚未排除的巧合**：非零組數湖北 3、河南 5，而將領數是 15 與 25，
恰好都是 ×5。樣本只有兩個，**不足以當結論**，記著待驗。

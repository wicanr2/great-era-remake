# 一條自己發明的規則，讓長跑的結果差了兩個勢力

日期：2026-08-01
工具：`tools/go.sh run ./cmd/aisim -turns 200 -fight -recruit -until-unified`

`docs/playtest/09` 的端到端跑暴露「只有消耗沒有補充」。補上徵兵之後
**仍然枯竭**——追下去發現病灶不是缺補充，是一條**我們自己加的規則**。

---

## 1. 三次跑的對照

| 設定 | 最終勢力 | 拿下省 | 無將領的省 |
|---|---:|---:|---:|
| 無徵兵 | 3 | 43 | 20 |
| 徵兵 + **發明的陣亡規則** | 4 | 63 | 25 |
| 徵兵，**移除那條規則** | **2** | **81** | **18** |

補上徵兵讓「拿下省」從 43 升到 63，但**無將領的省反而從 20 變成 25**
——補充管道開了，枯竭卻更嚴重。這個矛盾就是線索。

---

## 2. 病灶：`writeBack` 裡多做的一件事

```go
func (w *AIWorld) writeBack(us []*Combatant, idx []int) {
	for k, u := range us {
		i := idx[k]
		w.Strengths[i].Force = u.Strength.Force
		if u.Strength.Force == 0 {
			w.Units[i].Active = false      // ← 這一行
		}
	}
}
```

當時的註解寫著「原版陣亡的處理還沒解，這裡只確保它不會再被派上場」
——**知道沒解，還是加了規則**。

代價：被標成不可用的將領**再也回不來**。`RosterOf` 只收 `Active` 的，
所以徵兵補不到他們身上。開了補充管道也沒用。

### 原版沒有這條

`sub_28259`（徵兵）掃將領時檢查的是：

```asm
cmp     byte ptr [di+7A8Dh], 1      ; +16 == 1（可用）
cmp     word ptr [di+7A8Eh], 0C8h   ; +17 兵力 vs 滿員
```

**`+16` 與兵力無關。** 兵力 0 的將領照樣通得過第一道檢查，
照樣能被補兵。

移除那一行之後，勢力從 4 收斂到 **2**，拿下 81 省。

---

## 3. 為什麼會犯這個錯

「兵力歸零的部隊不該再上場」聽起來理所當然，而且**不加的話
`BattleSim` 會收到兵力 0 的單位**——當時是為了讓程式跑得下去。

但它違反 `CLAUDE.md` §9：

> **推論標籤要誠實**：confirmed / 強證據 / 假說 / 未知。
> 不准為了讓 worklist 看起來完整而編規則。

當時標了「原版還沒解」，卻沒有意識到**標了未解不等於可以自己補一條**。
正確的做法是：讓兵力 0 的單位照樣進場，或在**呈現層**擋掉，
不要動規則層的狀態。

---

## 4. 仍未解：`+16` 到底是什麼

存檔裡只有 `{0, 1, 32}` 三個值。畫面上「查閱將領」的「狀態」列
顯示「司令」「任用」——所以它至少有「任用／未任用」的語意。

反組譯裡寫 `+16` 的三支都是 `or al, 4`（bit 2）：
`sub_41513`（把攻方部隊放上戰場）、`sub_4166E`、`sub_4E239`。
**bit 2 是戰鬥中才設的**，所以存檔裡看不到——這解釋了為什麼
靜態掃描只看到三個值。

`{0, 1, 32}` 的語意、以及兵力歸零之後 `+16` 會不會變，**都還沒解**。
在解出來之前，規則層**什麼都不做**。

---

## 5. 剩下的凍結

移除規則後仍停在 2 個勢力。這可能是：

- 真的勢均力敵（兩個大勢力對峙）
- 還有別的缺口（徵稅／開發／商業／練兵／慰勞五條補充管道仍未實作）
- 或者根本不該收斂——**原版的勝負判定還沒解**（`CLAUDE.md` §8 M3），
  「跑到統一」是我們定的終點，不是原版的

**不再往下猜。** 下一步是把剩下五條補充管道量出來（`docs/playtest/10` §5），
而不是繼續調整模擬讓它「看起來會結束」。

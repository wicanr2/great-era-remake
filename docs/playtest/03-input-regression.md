## 1. 為什麼想打進戰鬥

`MEM_WAR.DAT` 的 200 B 單位區在**戰前是全 0**，靜態資料看不出欄位切法。
唯一可靠的取證方式是打進一場實際戰鬥、存檔、比對 `.DT2`——
那是 `CLAUDE.md` §4 oracle 優先序的第一位。

而且現在有一條捷徑：`byte_7003B` 是**觀戰開關**（`docs/mechanics/70-ai.md` §2），
打開之後主迴圈對每個省都會進戰鬥。它在設定選單裡，
而政略指令 15「其他選項」很可能就是設定入口。

`MEM_WAR.DAT` 也顯示河南正被張作霖系攻打（`docs/re/05` §2），
載入存檔就有現成的戰鬥。

三種送鍵方式都試過，畫面全部停在主選單（「1. 重新開始 / 2. 載入遊戲」），

### 這是回歸，不是從未成功

`docs/playtest/02` 的整份紀錄（政略畫面 13 個欄位、15 個指令、攻打子選單）
都是靠同一套工具做出來的，截圖還在 `workplace/dosbox/shots/`。
**同樣的路徑現在走不通。**

## 3. 推測與下一步

最可能的原因是 **Xvfb 裡沒有 window manager**，所以視窗拿不到輸入焦點——
XTEST 送出的事件會進到「目前有焦點的視窗」，沒有 WM 時那可能是 root window。
`xdotool windowactivate` 也需要 WM 支援 `_NET_ACTIVE_WINDOW`。

先前能成功可能是環境的偶然（某次剛好有焦點），而不是設計上的保證。

### 候選解法（都還沒試）

1. **在 Xvfb 裡跑一個輕量 WM**（`matchbox-window-manager` 之類），
   讓焦點有人管。這是最正規的修法。
2. **用 DOSBox 自己的機制**：`-c` 參數搭配 autoexec，或 mapper 檔綁定，
   繞過 X 層的輸入。
3. **改資料而不是按鍵**：直接改存檔讓遊戲進入想要的狀態。
   例如設省份記錄 `+32` 的 bit 6（正在打仗）再載入。
   但這條路要先確認遊戲會不會在載入時重算那個旗標。

# 原典／現代白話調動流程等價驗證

日期：2026-08-02  
狀態：**confirmed（指令 1 垂直切片）**

## 目的

驗證 `-wording original` 與 `-wording plain` 只改顯示文字，不改候選、輸入狀態機、
規則結果或存檔。這不是只比較兩張畫面；兩種模式都要走完整玩家路徑並保存結果。

## 同一組操作

第一期 `SAVE(1)`、湖北（26）：

```text
Enter → 1 調動 → 2 全部調動 → 輸入 19 河南 → Enter
→ 15 人維持全選 → Enter
→ 黃金／糧食／彈藥／燃料各輸入 0 → Y 確認
→ F10 → Y 自動存檔離開
```

兩次實跑只改命令列參數：

```text
-wording original
-wording plain
```

## 畫面結果

白話版五階段顯示：

1. 「要怎麼調動？」／「選擇部分將領」／「調動全部可用將領」
2. 「要調往哪個省？」
3. 「哪些將領要留下？」／「確認這份名單」
4. 「要一起運送多少黃金？」（後續依序為糧食、彈藥、燃料）
5. 「確定要執行嗎？」／「Y 確定　N 返回」

原典路徑仍使用原版場景字模；白話路徑使用倚天完整字庫。候選省份、將領姓名、勾選方框、
游標、輸入數值與按鍵完全共用。人工檢查白話畫面不再出現「何將」「何省」等倒裝短語。

## 規則與存檔結果

- 兩次 stderr 都回報：調動 15 位將領至河南省，四種物資均為 0，剩餘指令數 1。
- 原始存檔：湖北 15 人、河南 25 人。
- 兩個輸出存檔：湖北 0 人、河南 40 人。
- 兩個輸出檔 `cmp` 逐位元組相同。
- 兩個輸出檔 SHA-256 均為：
  `32d6dd6f47116af23de9df60eebbedeb8e02e50a23911502d926a11f6109ddb0`。
- 原始輸入 SHA-256 為
  `9ad9359b436ce2450ff3460df4efede478d871dfe234f60299759e781959ad0d`，
  因此不是把未修改的原始狀態另存兩次。

## 失敗樣本與修正

最初以快速 `xdotool key` 注入時，Ebiten 會在同一 frame 收到 key-down／key-up 而漏鍵；
兩份輸出一度都與原始存檔相同。雜湊相等本身不足以證明等價，湖北／河南人數正對照抓到
這個假陽性。正式驗證改用每鍵 150 ms 的 key-down／key-up，並以 stderr、非原始雜湊與
省份人數三項共同守門。

最後離開的 Y 在 key-down 就關閉視窗，因此自動化不再送該鍵的 key-up；否則 xdotool
會對已正常銷毀的視窗回 `BadWindow`，造成假失敗。

## 環境與產物

- `dsds-go:1.25` 建置，`fd2-dosbox-screenshot-local` 執行 Xvfb／xdotool／ImageMagick。
- 兩個一次性容器均 `--rm`、`--network none`，有限 CPU、記憶體與程序數，使用目前 UID/GID。
- 截圖：`workplace/screenshots/wording-ui/wording-{original,plain}-01..06-*.png`。
- 存檔：`workplace/saves/wording-{original,plain}.DT1`。以上均為 ignored 驗證產物。

## 範圍

本驗證只證明人物自傳與指令 1 已接通用語軸；其他十四項指令仍沿用原典字模，不能據此
宣稱全遊戲白話化完成。設定選單與 `prefs.json` 也仍未實作。

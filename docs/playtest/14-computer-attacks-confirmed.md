## 2. 這一張截圖同時驗了三件事

### 2a. 電腦會出兵 — `docs/re/29` **升級為 confirmed**

原本的證據鏈是：`ds:A358h` 參戰部隊表被玩家派將、電腦決策鏈 A、
戰鬥主函式三方共用（靜態），加上開新遊戲有「和平／好戰」設定（實機間接）。

**現在有了直接證據。** `docs/re/12` 的「玩家主動制」與
「規則層不該有『電腦決定攻打』」兩條全部作廢。

### 2b. 戰鬥面板的四種資源 = `sub_174C9` 複製的那四格

畫面上攻守各列**黃金／糧食／彈藥／燃料**——正好是
`sub_174C9` 從省份複製進參戰部隊表的四格（`docs/re/29` §2），
也正好是運補能搬、外援會給的四種（`40-economy.md` §9）。

而且**攻守成對排列**，印證 `docs/re/05` §2 那個「四個 u16 目標位址間隔 4」
的觀察——間隔 4 就是因為每個欄位是攻守一對。

⚠️ 煤礦與鐵礦**沒有出現在戰鬥面板上**，與「不可流動的原料」那條完全一致。

### 2c. 六方向鍵的配置

右下角的方向圖確認 `CLAUDE.md` §1.5 記的「數字鍵 1–6 對應六個方向」：

```
   4   5   6          ← 上排
     [游標]
   1   2   3          ← 下排
```

配合 `docs/re/07` 解出的六鄰位移表（偶數欄 −1/+14/+1/−15/−14/−13、
奇數欄 +13/+14/+15/−1/−14/+1），**方向編號與位移表的對應可以逐一對上**——
但這張截圖只給了鍵位排列，**沒有驗證哪個號碼對哪個位移**，
那要實際按下去看游標往哪走。

## 4. 還沒驗的

- **哪一號方向鍵對應哪個位移**（要按下去看游標走向）。
- 電腦選擇攻打目標的規則——這次只看到「蔣中正打孫傳芳的江西」，
  單一樣本推不出規則。`docs/re/28` 的決策鏈 A 六個步驟裡，
  哪一步導致這次出兵**還沒對上**。
- 戰鬥結算的實機數值（要把部署走完才看得到）。
- `sub_174C9` 那張 60 B/筆表有幾筆（十個部隊槽仍是假說）。

## 5. 給下一輪的操作備忘

```
開新遊戲          Return → 2 → Return → 1 → Return → 1 → Return
玩家人數          1 → Return
屬性（各組一個）   2（好戰）→ 3（高）→ 7（進階者）→ Return ×3
密碼              1 → Return          ← 三選一任選，**要 Return**
推進回合          1 → 3 → Return → y  ← 練兵，四鍵消耗一個指令數
```

⚠️ **數字輸入要 Return，Y/N 提示直接按 y 不用 Return**（`docs/playtest/13` §1）。

⚠️ 進入戰鬥後這套序列就失效了，要另外處理部署與戰鬥的輸入。

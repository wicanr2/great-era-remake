# PLAYTEST-35 指標／觸控 M1：共用數字鍵盤

日期：2026-08-03  
狀態：**PASS（M1 第一批；長清單直接點選仍待完成）**

## 實作契約

- `input.digit.0`..`input.digit.9`、`input.delete`、`input.submit` 是與裝置無關的
  動作；實體鍵盤、滑鼠與 Android Touch adapter 共用原有數值上限與送出流程。
- 鍵盤為 6×2，共十二鍵；每鍵 64×48 邏輯像素。第一列 1..6，第二列
  7、8、9、0、刪除、送出。數字沿用原版字模，刪除與送出以程式圖形繪製，
  不依賴使用者提供的倚天字庫。
- renderer 與命中測試都使用 `internal/ui/layout.NumericKeypadButton`；拖曳取消、
  放開才送出、畫面切換取消等契約沿用 M0 adapter。
- 第一批接到調動目標／四物資、商業數量、運補目標／四物資、徵兵數量、
  整編兵力、秘密行動目標與訊息時間，共九類畫面。
- 39 省、自治省份、整編候選等長清單刻意不顯示鍵盤，避免遮住資料；它們應
  改成直接點列，不可為了形式上「可輸入」犧牲資訊可見性。

## Docker GUI 實跑

建置使用 `dsds-go:1.25`，實跑使用一次性
`fd2-dosbox-screenshot-local:latest` 的 Xvfb／xdotool，全程不用實體鍵盤：

1. 地圖點「指令」→政略第 5 項→「徵兵」→「步兵」。
2. 依序點畫面鍵盤 `1`、`0`、`0`、`0`，輸入欄顯示 1000。
3. 點勾號送出，確認頁顯示需用黃金 100；點確定後回報
   「徵步兵 1000，共用黃金 100（剩 1）」。
4. 點政略第 15 項→其他選項第 1 項→確定，另存
   `keypad-recruit-1000.DT1`。

人工檢查 `workplace/pointer-m1-keypad/01`..`05` 五張畫面：按鍵未遮住提示與
輸入值，刪除／送出圖示清楚，執行後黃金 4,200→4,100、兵力
97,500→98,500、指令數 2→1。

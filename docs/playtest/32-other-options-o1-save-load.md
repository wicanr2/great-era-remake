# PLAYTEST-32 其他選項 O1：儲存與原子載入

日期：2026-08-02  
狀態：**PASS（原典／白話 GUI、存檔位元組與錯誤不破壞舊狀態均驗證）**

## 實作邊界

- `buildSession` 先在純記憶體中解析省份、該期將領、勢力表、勢力領袖、
  將領勢力反查與停火狀態。
- 勢力表、領袖表與反查表必須交叉一致；任一解析或交叉驗證失敗，
  app 的省份表、將領、`AIWorld`、`CommandBudget`、日期與原始存檔指標都不替換。
- 載入成功後會清除舊 session 的調動、運補、徵兵、查閱、政策與戰鬥中間選擇，
  避免舊 UI 指標之後回寫新遊戲。
- 儲存改為同目錄暫存檔、`fsync`、關檔後原子 `rename`；成功後才更新
  session 的原始 bytes。
- `.DT1` 不含可靠的自述期別；期別必須由 `SAVE(N).DT1` 槽位與目前 stage
  配對，不可從 bytes 猜測。

## 機械驗證

Docker Xvfb 內執行 `go test ./...`，涵蓋：

1. 完整 `SAVE(1).DT1` 能建立新快照，並複製輸入 bytes。
2. 目前省不屬玩家司令時，重定位到同司令的第一個合法省份。
3. 過短存檔被拒絕，舊 app 的所有核心指標與日期不變。
4. 只篡改勢力表領袖、造成三表不一致時，載入被拒絕。
5. 無操作儲存逐位元組不變，且不留 `.dsds-save-*` 暫存檔。

`fd2-dosbox-screenshot-local:latest` 的 Xvfb／xdotool／ImageMagick 環境中，
對原典與現代白話各跑一次：

`Enter → O → 1 → Y → 2 → Y → F10 → Y`

- 兩種用語的其他選項均將 1／2 顯示為可用，3–7 維持「尚未完成」。
- 原典確認保留「您確定嗎？」；白話分別說明儲存目前進度，以及載入會丟失
  未儲存變更。
- 載入成功後回到政略指令選單，面板數值未異常殘留或清空。

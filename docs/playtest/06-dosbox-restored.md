`docs/playtest/03` 記的輸入卡點**已經解決**。這一輪用恢復的 oracle
驗掉了兩個結論，並看到一個沒解過的機制。

## 1. ⛔ 訂正：卡點的根因二是誤診

`03` 記了兩個根因：

> **根因一：焦點是 PointerRoot** — 成立，`focus_window()` 已修。
> **根因二：keymap 是空的**（`xmodmap -pk` 輸出 0 行）— **誤診**。

`xmodmap` **在那個 image 裡根本不存在**：

```
setxkbmap    /usr/bin/setxkbmap
xkbcomp      /usr/bin/xkbcomp
xmodmap      MISSING          ← 「0 行」是命令缺失，不是 keymap 空
xdotool      /usr/bin/xdotool
```

`/usr/share/X11/xkb` 的資料（compat／geometry／keycodes／rules／symbols／types）
一應俱全，`setxkbmap us` 也正常回報成功。

**根因只有一個**，而修它的那次改動（`windowraise` + `mousemove --window` +
`windowfocus`）當時就已經寫進 `tools/dosbox_runner.sh`——**只是沒有重測**。

> 這是「查詢回空就下不存在結論」的典型：用一個**不存在的工具**去量，
> 得到 0，然後把 0 當成證據。診斷指令本身要先驗證它會回答問題。

### 端到端驗證

```
tools/dosbox.sh run "WAR.EXE" "wait:10;shot:t0;key:Return;shot:t1;key:2;shot:t2;key:Return;shot:t3"

t0/t1  48d554abd232   ← 標題（Return 是自動跳的，畫面不變）
t2     1fde476057a5   ← 按 2「載入遊戲」，畫面變了
t3     7974cd1fcbc6   ← 按 Return，進到存檔選單
```

畫面隨按鍵改變，輸入完全正常。

## 2. ✅ 命令數 = 將領數 ÷ 8 + 1 — **實機零誤差**

載入進度一、過防拷密碼之後，輪到玩家的湖北：

```
湖北省　正常
司令　吳佩孚      省長　吳佩孚
兵力 97500　將領數 15　人民忠誠度 79

司令，請下命令？(1-15)              指令數：2
```

- **將領數 15** → `15 ÷ 8 + 1 = 2`
- **畫面顯示「指令數：2」**

**第二個樣本**（按空白鍵換到河南）：

```
河南省　司令 吳佩孚　省長 張繼武
兵力 140500　將領數 25　人民忠誠度 41

司令，請下命令？(1-15)              指令數：4
```

`25 ÷ 8 + 1 = 4` ✓

`docs/re/13` §2 從 `sub_13D23` 讀出的公式，兩個樣本都一次命中。
`狀態[-232h]` 是剩餘命令數，**confirmed 升級為實機驗證**。

`CLAUDE.md` §1.5 記的社群說法「每個省份有命令數上限，用完換下一個省份」
到此完全成立。

### 順帶對上的兩件事

- **「(1-15)」= 15 個指令**，對上 `sub_10193` 的 14 支指令函式 + 空白鍵
  （`docs/re/13` §5）
- **「唐繼堯下命令中…」**：電腦逐省下命令，右上角同步顯示省編號
  （34 → 26），對上 `sub_1ACCC` 是「一個省的一個回合」

## 3. 🆕 兵工廠把煤鐵轉成彈藥 — **強證據**

同一個存檔，電腦跑完一輪後湖北的資源變化：

| 資源 | 載入時 | 一個月後 | 差 |
|---|---:|---:|---:|
| 黃金 | 4,200 | 4,150 | **−50** |
| 糧食 | 18,050 | 17,950 | **−100** |
| 彈藥 | 8,787 | 14,787 | **+6,000** |
| 燃料 | 12,048 | 12,048 | 0 |
| 煤礦 | 13,000 | 7,000 | **−6,000** |
| 鐵礦 | 14,031 | 8,031 | **−6,000** |

**煤 −6,000、鐵 −6,000、彈藥 +6,000**，而湖北的**兵工廠數是 3**。

讀作：**每座兵工廠每月吃 2,000 煤 + 2,000 鐵，產 2,000 彈藥。**

⚠️ 這是單一樣本的推論。要確認得換一個兵工廠數不同的省再量一次，
或從反組譯找到那個乘法。**在那之前不寫進規則層。**

黃金 −50、糧食 −100 是另一筆支出（維持費？），比例待查。

## 4. 這一輪沒有做到的

- **「電腦會不會主動攻打」仍未一槌定音。** 這一輪只跑了一個月，
  湖北沒被打，但一個月不構成證據。要連跑十幾個月才有意義。
  卡在「怎麼結束玩家回合」——空白鍵是**換省**不是換月
  （湖北 26 → 河南 19），15 個指令裡也沒有「結束回合」。
  推測要把指令數用完，或是 ESC，都還沒試。
- 兵工廠公式只有一個樣本。
- 沒有進戰鬥，所以 `docs/re/05` §4 那條「取戰鬥中的 `.DT2` 解 200 B
  單位區」還沒做——但**現在路是通的**。

## 6. 指令 15「其他選項」= 設定選單（8 項）— confirmed

按 `15` + `Return`：

```
1. 儲存遊戲              5. 音樂開關   OFF
2. 載入遊戲              6. 訊息時間   1
3. 音效開關   ON         7. 觀戰       OFF
4. 指令圖畫   ON         8. 結束遊戲

司令，您的選擇？(1-8)
```

**第 7 項「觀戰」就是 `byte_7003B`**（`docs/mechanics/70-ai.md` §2 從
反組譯推出的觀戰開關）。`docs/playtest/03` §1 當初的推測
「政略指令 15『其他選項』很可能就是設定入口」**成立**。

切換要按 `Y` 確認（「司令，您確定嗎？(Y/N)」），切完顯示 `觀戰 ON`。

### 這一步會消耗指令數

切完觀戰之後畫面右上角的省編號從 **26 變成 19**——指令數用掉一個，
剩 1 個；再用掉就換下一個省。所以**「用指令推進回合」是可行的**，
不需要另外找「結束回合」的操作。

`sub_10193` 的對應段落：

```asm
cmp     byte_6FE81, 0           ; 這次指令有沒有真的執行
jz      short loc_10428
...
or      al, 4                   ; 標為已處理（bit 2）
dec     [bp+var_6]              ; ← 指令數遞減
...
and     al, 20h                 ; bit 5
cmp     al, 20h
jnz     short loc_10428
xor     ax, ax
mov     [bp+var_6], ax          ; ← bit 5 讓指令數**立刻歸零**
```

`+32` bit 5 只有 `sub_22E25` 會設，用的還是 `xor al, 20h`（切換）。

⛔ 這裡原本寫「掛在指令 7『開發』底下」——**錯了**。逐個 `cmp ax, N`
對出來的分派表（`docs/re/13` §5）顯示 `sub_22E25` 的呼叫者
`sub_23FF6` 是**指令 8「政策」**。開發是 `sub_24D59`。

所以 bit 5 是**政策**設的，讀作「某項政策會佔掉整個月的命令」。

### 順帶：指令數在回合開始時算好，不隨後續變動

回到湖北時：

```
兵力 97,500 → 104,110      將領數 15 → 16
```

將領數變成 16（`16 ÷ 8 + 1 = 3`），但**指令數仍是回合開始算的 2**。
與 `sub_13D23` 一致——它在回合初始化時算一次寫進 `狀態[-232h]`，
之後只遞減。

## 0. 這份文件在解什麼

使用者 2026-08-01 裁決：417 個槽位的人物小傳**全部自撰**，切斷與中文維基百科（CC BY-SA）
及其他來源的衍生關係。`DESIGN-20` §3.6a 定了方向與一版模板初稿，但明白寫著
「上面是初稿，要先在 10 篇上試寫再定」。

這份文件就是試寫之後的定案：**後續幾十個 agent 照著做的作業規格**。

⚠️ 這份規格管的是「怎麼寫」，不管「寫完怎麼進遊戲」。後者見 `DESIGN-20` §3.5 與 §9。

### 為什麼「改寫」不夠

著作權保護**表達**，不保護**事實**。把別人的句子換個說法仍可能構成衍生作品；
真正切斷關係的唯一作法是**只取事實，從事實重新寫**。

本規格把這件事做成可執行的機制：**事實骨架（`facts.json`）與成文（`bio_zh`）分離**，
成文階段**只能看骨架，不能看原文**。骨架是欄位，欄位沒有表達；從欄位長出來的句子是新表達。

## 2. `facts.json` 骨架 schema

### 2.1 設計原則

1. **每一個事實都自帶來源與信心度。** 不存在「全篇一個 confidence」——那會讓
   「生卒年是猜的、任職序列很硬」這種常見情形無法表達。人物層的 `confidence`
   是彙總結果，不是唯一標記。
2. **只放欄位，不放句子。** 骨架裡出現完整敘述句就是流程走歪了。
   例外：`conflicts[].statements[].says` 必須原樣記錄來源的說法，允許是句子。
3. **不確定的東西有位置放。** `conflicts`（來源互相衝突）、`gaps`（查不到什麼）、
   `identity.disambiguation`（同名怎麼排除）三個欄位存在的意義，就是讓
   「不知道」有地方寫，不必為了讓骨架看起來完整而編。

### 2.2 結構

```jsonc

  "generated": "YYYY-MM-DD",

```

### 2.3 欄位級 `conf`

每一筆 `life` / `education` / `posts` / `events` / `ending` 都要標 `conf`：

| 值 | 判準 |
|---|---|
| `high` | ≥2 個獨立來源，且至少一個是 Tier A/B |
| `medium` | 1 個 Tier A/B 來源；或多個 Tier C 但彼此非同源 |
| `low` | 只有 Tier C；或雖有 Tier A/B 但「這筆講的是不是同一個人」需要推定 |
| `unknown` | 查無。此時 `value`/`year` 為 `null`，`src` 為 `[]` |

**空欄位一律留 `null` + `conf: "unknown"`，不得省略欄位、不得填空字串。**
省略欄位會讓「沒查」和「查了沒有」混在一起。

## 3. 來源分級與 `confidence` 判準

### 3.1 來源分級

| Tier | 內容 | 算不算「獨立來源」 |
|---|---|---|
| **A** | 官方檔案與學術工具書：國史館、中研院近史所、**中華民國政府官職資料庫**（`gpost.lib.nccu.edu.tw`）、《民國職官年表》、中華百科全書民國人物庫（`digroc.pccu.edu.tw`）、省市地方志人物志、學術期刊論文 | ✅ |
| **B** | 中文維基百科**有引註的條目**、有署名與出處的專題館藏文章（如南京民間抗日戰爭博物館口述史） | ✅ |
| **C** | 百度百科、求真百科／factpedia、華人百科、百科知識、知乎、搜狐、網易、每日頭條、論壇貼文、自媒體、地方文史整理稿 | ❌ 只當線索 |

三條配套規則：

1. **同源合併。** 兩個網站放的是同一段文字（互相轉載）算**一個**來源。
   中文百科站之間互抄極普遍，預設全部合併成一個 Tier C。
   同理，維基的兩個不同條目算**一個** Tier B 來源。
2. **`gpost.lib.nccu.edu.tw` 是這個專案最被低估的來源。**
   10 篇試寫裡它命中 **8 篇**，其中 `#367 許鴻林`、`#93 王獻臣`
   在維基完全查不到的情況下仍取得帶公報日期的任免令。
   **每一篇都要查它，這是強制步驟**（§5.2 第 2 步）。
   查法：`https://gpost.lib.nccu.edu.tw/view_career.php?name=<URL-encoded 姓名>`。
   ⚠️ 它的年份是**民國紀年**（「022年」= 民國 22 年 = 1933），換算後才寫進骨架。
3. **搜尋引擎摘要不是來源。** 只看到摘要、沒抓到原文的，一律標
   `note: "僅搜尋摘要，未核對全文"` 並降一級。試寫中至少兩次遇到摘要與原文不符
   （`#158 楊森` 被摘要說成「湖南人」、`#368 于鎮河` 的集團軍番號）。

### 3.2 人物層 `confidence`

| 值 | 判準（三條全中才算） |
|---|---|
| **`high`** | ① 生卒年、籍貫、任職序列三者的欄位級 `conf` 都是 `high` 或 `medium`；② 至少一個 Tier A/B 來源；③ 沒有影響主軸的未解 `conflict` |
| **`medium`** | 任職序列站得住（有 Tier A/B 佐證），但生卒年或籍貫只有單一來源／只有 Tier C；或有未解 `conflict` 但不影響主軸 |
| **`low`** | 只有一個可靠來源；或全部只有 Tier C；或查得到的只是零星時間點、串不成序列；或**「這些記載是不是同一個人」需要推定**（§5.3） |
| **`unknown`** | 什麼都查不到。**不寫小傳**，`bio_zh` 留空 |

三個容易搞錯的地方：

- **來源可靠度升級 ≠ 信心度升級。** `#367 許鴻林` 從論壇貼文換成官職資料庫，
  內容具體得多，但**獨立來源數仍是 1**，維持 `low`。這一條寫在這裡就是為了防止
  「我查到好東西了所以升級」的直覺。
- **`low` 不是失敗。** `low` 是「照實說我只有這麼多」。
  硬用模板湊出一篇看起來像樣的傳記，比 `low` 更糟（`CLAUDE.md` §9）。
- **不可外推。** 同一批人裡 A 的來源可靠不代表 B 的可靠，逐人判。

## 4. 敘述模板（定案）

### 4.1 句序

```
S1  身分句   <姓名>（<生年>年—<卒年>年），字<字>，<籍貫>人。
S2  出身句   <年份>年<入／畢業於><學校><科別／期別>。
S3  任職句   <年份>年任<職務全稱>，<年份>年改任<職務全稱>，…
S4  事件句   <年份>年<月>，<地點><事件名>，<角色>，<結果>。
S5  結局句   <年份>年<月><日>於<地點><結局事實>。
S5b 待考句   另據<來源>，…；<相合的點>，是否同一人待考。   ← 僅在 §5.3 觸發時
S6  缺漏句   <欄位>不詳。／ 其餘經歷未查得記載。              ← 僅在核心欄位確實查無時
```

**句序固定，不得重排。缺段直接跳過，不留佔位。**
S3、S4 可各占 1–4 句；其餘每種最多 1 句。

`S6` 的位置有例外：若缺的是生卒與籍貫（S1 的內容），`S6` 上提到 S1 的位置，
寫成「<姓名>，生卒年與籍貫不詳。」——這是 `#93 王獻臣`、`#367 許鴻林` 的形狀。

### 4.2 逐句規則

| 項 | 規則 |
|---|---|
| 生卒 | `（1892年—1953年）`。缺一半寫 `（1892年—卒年不詳）`；兩者全缺則整個括號省略，改用 S6 |
| 主語 | 第一次用全名；其後用姓（葉肇→葉）或省略。**不用「他」「其人」** |
| 職務 | **一律全稱**，且用當時的正式機構名（`DESIGN-20` §6.1 原則 4）。番號用國字（第六十六軍），不用阿拉伯數字 |
| 年份 | 西元 + 「年」。**月／日只在來源有確切日期且該日期本身有意義時才寫**（如簽約日、被俘日）。純敘任令的日期進骨架，正文只寫到月 |
| 敘任 vs 任職 | 授階寫「敘陸軍中將」，職務寫「任…師長」。兩者不可混用 |
| 一句一事 | 一個句子只放一種資訊。不在事件句裡塞評價、推測或背景解釋 |
| 主動語態 | 「率部參加淞滬會戰」不是「被派往參加淞滬會戰」 |
| 引號 | 專有名稱（「和平救國軍」「聯軍辦事處」「和平解放大同協議書」）用「」原樣保留，**不當成敘述用語** |

### 4.3 禁止與限制

**禁止**（`DESIGN-20` §6.1 原則 2 的落實）：

```
英勇 卓越 傑出 出色 著名 名將 一代 傳奇 悲壯 忠貞 氣節 民族大義
賣國 罪魁 叛徒 漢奸 偽軍 偽政權 投敵 無能 腐敗 殘暴 正義 邪惡
起義 投誠 反正 剿匪（作為敘述動詞時）
```

⚠️ **「剿匪」的例外**：`贛粵閩湘鄂剿匪軍`、`剿匪總司令部` 是機構全名，**必須原樣保留**
（`DESIGN-20` §6.2 已預告這個誤報）。判準是：**當它是機構名的一部分就保留，
當它是敘述動詞（「率部剿匪」）就換成中性描述。**

**限制使用（帶歸屬才可寫）** —— 這是試寫新增的一條：

> 他人給的稱呼（綽號、時稱、他稱）可以寫，但必須帶歸屬詞（「時人稱」「一般稱」），
> **不得當主語，不得當定性**，而且和其他事實一樣要過兩來源門檻。

- ✅ 「事後未受追究，時人因此稱其為『東陵大盜』。」
- ❌ 「東陵大盜孫殿英…」
- ❌ 張淦的「羅盤將軍」——流傳最廣，但只有 Tier C，**未達門檻，不寫**。
  流傳廣不等於可查證。

### 4.4 衝突怎麼寫

| 情形 | 處理 |
|---|---|
| 兩個**同級**來源互斥（都 Tier B，或都 Tier C）| 正文並列：「一說<A>，一說<B>」。**不加「應以…為準」，不排序，不暗示** |
| 三說以上 | 前綴「未有定論：」再並列（示範見 `#58 吳佩孚` 死因） |
| **Tier A 與 Tier C 互斥** | **採 A，不並列**，分歧記進骨架 `conflicts`（示範見 `#353 葉肇` 的 1949 年任命日期） |
| 一方有、一方沒有（不是互斥，是覆蓋範圍差） | **不是 conflict**。正文寫有的那一方，骨架記一筆說明（示範見 `#158 楊森` 的第十六師師長） |
| 分歧的其中一方**只看到搜尋摘要、沒核對原文** | **只進骨架不進正文**（示範見 `#368 于鎮河` 的集團軍番號） |
| 同一件事的年份與番號**全都**對不上 | 正文只寫事件本身，**年份與番號都不寫**（示範見 `#204 孫殿英` 改隸直魯聯軍） |

最後一條是這批試寫最重要的發現：**「查不到就不寫」比「挑一個看起來合理的」重要。**

### 4.5 待考句（S5b）

當兩批記載**看起來是同一人但沒有來源這樣說**時，用固定句型：

> 另據<來源名稱>，有一名<姓名>…（列該來源的事實）；<相合的點>，是否同一人待考。

同時把人物層 `confidence` 降為 `low`，並在 `conflicts` 記一筆 `field: "identity"`。

**這個句型是試寫時新增的**（`DESIGN-20` §3.6a 的初稿沒有）。
沒有它，`#93 王獻臣` 只有兩個壞選項：安靜地把兩批記載合併（等於捏造一個接合），
或丟掉官職資料庫那批（等於丟掉真材料）。

### 4.6 長度

**以格數定義，不以字數定義。**

`DESIGN-20` §5.2：全形字元占 1 格、半形（數字、拉丁字母、`·`、`—`）占半格；
§5.1：本文區一頁 13 行 × 28 格 = **364 格**。

| | 值 | 理由 |
|---|---|---|
| 硬上限 | **340 格** | 364 減去約一行（24 格）的斷行浪費。超過就砍，砍法見 §4.7 |
| 目標區間 | 150–300 格 | 現有 326 篇中位 157.5 字；`medium`／`low` 自然落在下半 |
| 下限 | **無** | 查到多少寫多少。`#367 許鴻林` 62.5 格是正常結果，不是缺陷 |

⚠️ **不要用字數估格數。** 民國人物傳記的年份密度極高，半形字元占 12–15%，
「355 字」實際只有 330 格。一律跑 §6 的檢查腳本量。

### 4.7 取捨優先序

`#1 蔣中正` 的可查證事實足夠寫三千字，模板必須給出可執行的砍法。
**取捨軸是遊戲時段**——自傳是給玩家在遊戲裡查將領用的：

```
1. 身分（生卒、籍貫、字）                             永不砍
2. 與該人物所屬遊戲期別直接相關的職務與事件            永不砍
   （北伐時期 1926–28／抗戰前期 1937–41／抗日後期 1941–45，
     取自 people.json 的 periods 欄）
3. 該人物的最高職務一項                               次要
4. 結局一句                                          次要
5. 遊戲時段外的細節、非軍政經歷、學術性爭議            最先砍
```

示範：`#1 蔣中正` 砍掉了援閩粵軍作戰科主任、中國國民黨總裁、中山艦事件、清黨、
中原大戰、第二次國共內戰；日本陸軍士官學校學歷的分歧留在骨架不進正文。
`#204 孫殿英` 在名冊裡只出現於北伐時期，因此 1930 年中原大戰那一句最先被砍。

## 5. 寫作流程

### 5.1 四步（`DESIGN-20` §3.6a，此處補上可操作細節）

```
1. 抽骨架    從既有素材與可靠來源取出結構化事實 → 填 facts.json
             ↓ 產物是欄位，不是句子
2. 交叉查證  ≥2 個獨立來源對得上才標 high。對不上標 conflict，不裁決
             ↓
3. 依模板成文  ⚠️ 關掉原文，只看骨架寫
             ↓
4. 回查      逐句對照骨架，每句都要能追到某一欄。追不到的刪掉
```

**第 3 步的「關掉原文」是整套機制的支點。** 一邊看維基一邊改寫，產出的必然是衍生作品。
實務上：把 `facts.json` 的該筆貼進一個乾淨的上下文，來源網頁一律不再開。

### 5.2 每一篇的強制步驟

1. 讀 `docs/reference/people/people.json` 該筆的**欄位**（`birth`/`death`/`birthplace`/
   `faction`/`highest_post`/`aliases`/`periods`）當**線索**。
   ⚠️ **`bio_zh` 只用來抽事實，不得作為成文參考。** 那是待汰換的衍生文字。
2. **查 `gpost.lib.nccu.edu.tw`**（強制，見 §3.1 第 3 條）。
3. 查中文維基：先查個人專條，查無再查**部隊沿革條目**（「國民革命軍第 N 軍」「第 N 集團軍」）
   與**事件條目**——`partial` 那 96 筆的材料多半在這裡。
4. 同名風險評估：填 `identity.disambiguation`，或確認無風險後填 `null`。
5. 填骨架 → 關原文 → 成文 → 回查。
6. 跑 §6 的品質閘。

### 5.3 同名與 identity 三條硬規則

1. **`name_ingame` 是槽位的鍵，不是人的鍵**（`DESIGN-20` §2.3）。
   已知三組「兩筆同一人」：`4/290`（閰錫山/閻錫山）、`99/399`（陳儀/陳公俠）、
   `50/289`（龐炳勛/龐炳勳）。撞到這些 id 要看另一筆已寫的版本，**不要各寫一篇矛盾的**。
2. **`#274 無省長` 不是人**，是佔位值。跳過，不寫。
3. **推定的接合一律降 `low` 並用待考句**（§4.5）。
   「時間對得上、地點對得上，所以是同一個人」是查證者的推理，不是來源的陳述——
   兩者的證據等級差一級，不能混。

### 5.4 回查檢核表

成文後逐項打勾，**不打勾不算完成**：

- [ ] 每一句都能指到 `facts.json` 的某個欄位路徑（如 `posts[3].title`）
- [ ] 沒有骨架裡沒有的年份、地名、番號、人名
- [ ] 沒有 §4.3 禁止清單的詞
- [ ] 他稱綽號都帶歸屬詞，且過了兩來源門檻
- [ ] 衝突的處理符合 §4.4 的對應列
- [ ] 職務都是全稱、都是當時的正式機構名
- [ ] 格數 ≤ 340（跑腳本量，不目測）
- [ ] 字元可畫性檢查 0 個不可畫
- [ ] `confidence` 依 §3.2 三條逐條核過，不是憑印象填

## 6. 品質閘（機器檢查）

每批交件前跑一次。腳本寫 `/tmp`，用 `tools/py.sh - < /tmp/xxx.py` 送進 docker
（`CLAUDE.md` §9：Python 一律 docker + uv venv）。

```python
import re, sys, unicodedata, json
sys.path.insert(0, 'tools'); import eten

cells = lambda t: sum(1.0 if unicodedata.east_asian_width(c) in 'WF' else 0.5 for c in t)

for text in bios:                       # 每篇正文
    assert cells(text) <= 340, "超過一頁"
    for ch in set(text):
        if ord(ch) < 128:
            continue
        b = ch.encode('big5')           # 編不出 → UnicodeEncodeError
        assert len(b) == 2 and eten.big5_to_font(b[0], b[1]) is not None, f"畫不出：{ch}"
```

四項檢查：

| # | 檢查 | 失敗處理 |
|---:|---|---|
| 1 | 格數 ≤ 340 | 依 §4.7 砍到過為止 |
| 2 | 每個字元都能編 Big5 且倚天有字模 | 換字。**不得引入 `DESIGN-20` §2.4 那 12 個字**（`〇榘衞鲁啓藁献専継荣羣钟`）——尤其 `鲁 献 荣 钟` 四個簡體殘留，既有掃描漏了它們，新文字不准再犯 |
| 3 | `facts.json` 合法且 `id` 對得上 `people.json` | 修 |
| 4 | 禁用詞掃描（§4.3 清單）| 逐篇看，注意「剿匪」的機構名誤報 |

10 篇試寫的實測結果：2,765 字、518 個相異字元，**Big5 編不出 0、倚天無字模 0、
12 個問題字一個都沒出現**。這說明只要照 §4.2 用正式機構名與國字番號寫，
可畫性不會是瓶頸。

## 7. 派工規格

### 7.1 分批建議

剩餘 **395 篇**（416 個槽位 − 已試寫 10 − `unknown` 91 篇不寫傳 … 實際待寫量見下）。

按 `02-status.md` 的分佈重算：

| 類別 | 筆數 | 每篇成本 | 建議批量 |
|---|---:|---|---:|
| `confirmed`（有維基專條）| 230 | 中——資料多，成本在**取捨**與查 gpost | **15 篇／批** |
| `partial`（只有部隊沿革）| 96 | 高——成本在**找材料**，常要翻三四個部隊條目 | **10 篇／批** |
| `unknown`（查不到）| 91 | 低——但**不是零**：仍要跑一次 gpost 與異體字重查 | **25 篇／批** |

- `confirmed` + `partial` 已扣掉試寫的 10 篇 → 316 篇 → 約 **24 批**
- `unknown` 91 篇 → 約 **4 批**（多數會維持 `unknown`，但 `#367 許鴻林` 的經驗說明
  gpost 可能撈出一批人，所以這 91 筆**必須全部重跑一次**，不能直接沿用結論）
- 合計約 **28 批**

**為什麼不是「每批 30–50 篇」**：第 2 步交叉查證需要判斷力，
批量一大就會退化成「照抄第一個搜到的」。10–15 篇是一個 agent 能維持查證品質的上限，
也讓每批的回查（§5.4）還做得完。

**批次順序建議**：先做 `partial` 的 96 篇。理由是這批最可能因 gpost 而**改變結論**，
早點知道 gpost 的命中率有多高，才能決定 `unknown` 那 91 筆要投入多少。

### 7.2 派工 prompt 必含項

`CLAUDE.md` §10：邊界要寫進 prompt，沒寫的等於允許。每批的 prompt 至少要有：

1. **本批的 id 清單**與各自的 `periods`（決定 §4.7 的取捨軸）。
2. **必讀**：本規格 §2–§6 + `DESIGN-20` §6.1。
3. **強制查 gpost**，並附上 URL 格式與民國紀年換算提醒。
4. **產出**：`facts-batch-NN.json` + `bios-batch-NN.md`，格式照 sample 兩檔。
5. **邊界**：只能新增這兩個檔；不准改 `people.json` 與其他既有檔；
   不准 git commit/push/add；不准碰 `workplace/`、`~/.claude/`；
   禁止任何 docker image／volume／system／builder prune 與 `docker rmi`；
   只能清理自己建立的 container。
6. **回報**：每篇的 `confidence` + 格數 + 來源 tier + 品質閘結果 +
   **「哪幾筆查不到、下一步該去哪查」**。

### 7.3 交件驗收

主迴圈收到每批後檢查：

- [ ] 品質閘四項全過（自己重跑一次，不採信回報）
- [ ] `low` 的比例合理——**`low` 太少要懷疑硬湊**。
      以試寫的 10 篇為基準，`partial` 母體的 `low` 比例應該不低於 20%
- [ ] 抽 2 篇做回查抽查：隨機挑句子，要能指回骨架欄位
- [ ] 禁用詞掃描的誤報（機構名）確實是誤報，不是漏網
- [ ] `conflicts` 不是空的——**全批零衝突要懷疑沒真的交叉查證**

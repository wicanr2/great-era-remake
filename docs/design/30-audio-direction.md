## 0. 這份文件要解決什麼

需求是「音效與背景音樂**基於原版**重新調整」。這句話有一個硬前提：
先知道原版是什麼。`docs/formats/06` 把八首曲子從 AdLib 事件串解成可讀的音符，
這份文件接著回答三個問題：

1. **哪一部分是文化資產、不准動**，哪一部分是 1992 年硬體限制的產物、可以換掉。
2. 換掉的部分要往哪個方向走——民國初年到抗戰這段時間的音樂語言是什麼樣子。
3. 怎麼在 Go / Ebiten 上同時保住原版音色與現代編曲，並且支援與視覺同一套的切換。

還有一條貫穿全文的約束：北伐與抗戰是真實戰爭，不是背景板。§4 把編輯方針寫成硬規則。

### 1.1 這批曲子的風格不是「中國風」

音級分佈（只統計旋律聲部 0–5）給出的結論，跟直覺相反：

| 曲名 | 大調七聲吻合度 | 五聲吻合度 | 判讀 |
|---|---:|---:|---|
| `BATTLE1` | 0.94 | **0.90（A 羽）** | 明確的五聲調式，A-C-D-E-G |
| `BT02` | 1.00 | **0.89（C 宮）** | 五聲，C-D-E-G-A |
| `WALL` | 0.99 | 0.82 | 偏七聲，B 音佔 10% |
| `SCENE` | 0.96 | 0.82 | 節奏性素材為主，旋律成分少 |
| `BATTLE2` | **1.00** | 0.82 | 完整 C 大調七聲，F 與 B 各 9% |
| `STRATEGY` | 0.96 | 0.80 | 降 B 大調七聲 |
| `FINAL` | 0.78 | 0.64 | 半音化 |
| `MAINTHEM` | 0.79 | 0.63 | **十二個音級用了十一個**，功能和聲 |

也就是說：**原版的主體是西洋調性語言（進行曲、管樂編制、功能和聲），
五聲調式只在 `BATTLE1` 與 `BT02` 兩首上明確成立。** 主題曲 `MAINTHEM` 是
長號＋雙簧管＋薩克斯＋長笛＋小號＋鐘琴的樂隊編制，半音化，完全是西樂寫法。

這一點直接約束了 §3 的方向：**不能把 remake 一律「國樂化」。** 那不是還原，
是把原作改寫成另一個東西。原版自己的風格分佈是什麼樣，重新編曲就照那個分佈走。

### 1.2 原版已經在用的表情手段

這些是作曲者的意圖，不是硬體殘渣，**必須保留**：

- **速度倍率**（`F0 7F 00 …` SysEx）——落點與曲線見 `docs/formats/06` §4.5：
  - `FINAL` 在**曲子前段（8%–15%）**有一次大幅度漸慢，一路拉到 0.445× 再直接跳回原速，
    21%–27% 還有一次較淺的回落。**這是戲劇性的開場處理，不是結尾收束**
    ——這首以全速直接收尾。
  - `MAINTHEM` 開頭 1% 內從 0.945 漸快到 1.000（**漸快進入**），
    尾段 93%–96% 有一次輕微的彈性速度。
  - `WALL` 在 78%–80% 有一小段半速。
- **聲部音量**（`An`）：`MAINTHEM` 307 次、`BATTLE2` 222 次、`FINAL` 158 次。
  `STRATEGY` 有 0x55→0x56→0x57→0x58 的連續遞增，是寫出來的漸強。
- **弯音**（`En`）：只有 `BT02` 真的用（16 次下彎約 0.9 個半音），是滑音裝飾。

### 1.3 硬體限制的部分（可以換掉）

- **每個聲部只能發一個音**（OPL2 一聲道一音）。`WALL` 的鋼琴和弦被拆成
  聲部 0–3 各持一個音（音域 55-58 / 59-62 / 62-65 / 67-69），這是配置手段不是音樂意圖。
- **打擊只有五種**（大鼓、小鼓、中鼓、銅鈸、腳鈸），而且共用 OPL 的兩個聲道。
- **2-operator FM 音色**，`piano1`、`violin1` 這些名字是標籤不是音色本身。
- **樂曲長度 40–137 秒**後就循環，沒有段落式編排。

## 2. 原版曲目對應的情境

`docs/formats/06` §5 已用反組譯確認索引與檔名的對應，但**「哪支函式對應玩家看到的哪個畫面」
目前是假說**，要靠 DOSBox 實跑定案（該文件 U4）。編曲工作可以先開始，情境判斷要留修正空間。

| 曲名 | 由誰播 | 情境（假說）|
|---|---|---|
| `MAINTHEM` | `GRT.EXE` 硬寫 | 開場動畫與標題 |
| `FINAL` | `GRTE.EXE` 硬寫 | 結局 |
| `SCENE` | `WAR.EXE` 索引 3，程式啟動與多處 | 政略主畫面（曲目最常被切回這一首）|
| `STRATEGY` | `WAR.EXE` 索引 5 | `sub_3752F` 底下兩處 |
| `BT02` | `WAR.EXE` 索引 4 | 戰鬥九步結算第 1 步，同一支函式載入 `warrep.tpc` 戰報圖 → **戰報畫面** |
| `WALL` | `SR.EXE` 索引 6 | 劇情過場 |
| `BATTLE1` / `BATTLE2` | **沒有任何執行檔選得到** | 見下 |

### ⚠️ `BATTLE1` / `BATTLE2` 在這個版本裡取不到

對 `WAR.EXE`、`SR.EXE` 做窮舉式交叉參照的結果：索引變數只被寫入 3、4、5、6，
**從來沒有 1 或 2**。兩首最大的戰鬥曲反而播不到。

這對編曲很重要：`BATTLE1` 是全作五聲調式最明確的一首（A 羽 0.90，用了 sitar1、
tincan1、syn1/2/3 這種特別的音色），`BATTLE2` 是完整的 C 大調七聲樂隊寫法。
**兩首都是完成品，不是草稿。**

處置方式（照 `rulebook/83` 完整性優先）：
- **兩首都要編**，一首都不砍。它們是 1992 年就寫好卻沒被玩家聽到的東西，
  這正是保存專案該補的缺口。
- remake 把它們**接回實際戰鬥場景**（六角格戰鬥中的 BGM），並在 remake 差異表登記
  「原版此二曲無觸發路徑，remake 予以啟用」。
- 若 DOSBox 實測推翻「取不到」這個結論，照 `CLAUDE.md` §10 記進 `CONTEXT.md` 推翻清單，
  並把這條差異登記撤銷。

## 3. 保留什麼、改什麼——那條線畫在哪

### 3.1 不准動（文化資產本體）

| 項目 | 理由 |
|---|---|
| **主旋律的音高序列** | 這是作曲者寫的東西。音符可以換樂器、可以配和聲，不能改音 |
| **和聲走向與低音線** | 功能和聲的進行是作品結構，改了就是另一首曲子 |
| **段落結構與小節數** | 兼作技術約束，見 §5.4（切換要對齊）|
| **速度關係** | `FINAL` 前段的大幅漸慢、`MAINTHEM` 的漸快進入、`WALL` 的半速段都是寫出來的，照做 |
| **曲目到情境的對應** | 除 `BATTLE1`／`BATTLE2` 的啟用之外不重新指派 |

### 3.2 可以改（1992 年的硬體外殼）

| 項目 | 現代化做法 |
|---|---|
| **音色** | 2-op FM → 取樣或現代合成。這是最大的一塊 |
| **聲部數** | 11 → 不設上限。和弦不必再拆成四個單音聲部 |
| **打擊** | 五件 → 完整編制，含中式鑼鼓 |
| **織體** | 允許加入原版沒有的內聲部、對位、延音尾韻 |
| **動態範圍** | OPL 的音量是 6-bit 對數；現代可做真正的漸強漸弱與空間感 |
| **長度與循環** | 40–137 秒硬循環 → 加入導入段、循環段、收束段的分段結構 |
| **混音** | 單聲道 → 立體聲，但**不做過度寬化**（見 §6.3）|

### 3.3 判準

> 把重新編曲的版本用單一鋼琴音色彈出來，應該與原版用單一鋼琴音色彈出來
> **在音高與節奏上逐音相同**。差異只允許出現在配器、織體與音色。

這條可以做成自動檢查：`tools/mus.py` 已能把原版輸出成音符清單；
編曲產物若同時提供 MIDI 母稿，可寫一個比對腳本驗證主旋律聲部逐音一致。
列為 §8 的 P2 驗收條件。

## 4. 史實敏感度與編輯方針（硬規則）

遊戲橫跨北伐（1926–28）與抗戰（1937–45）。這不是奇幻設定，配樂會被讀成對真實事件的表態。

### 4.1 一律不得使用 `[HARD]`

- **任何政黨黨歌、國歌、軍歌的旋律引用**——包含但不限於中國國民黨黨歌／中華民國國歌、
  《義勇軍進行曲》、《國旗歌》。這些旋律帶有明確且現行的政治意涵，
  即使著作權年限已過也不得引用、變奏或「致敬」。
- **日本軍歌與《君之代》**，以及任何足以辨識的日本軍隊象徵旋律。
- **抗戰時期具體歌曲的旋律引用**（《松花江上》《大刀進行曲》《黃河大合唱》等）。
  這些作品與真實傷亡直接綁定，拿來當遊戲 BGM 素材是不恰當的挪用，
  而且部分仍在著作權保護期內。
- **中國風刻板套路**：平行四度＋鑼鈸重擊＋五聲音階的「東方風味」公式化寫法。
  那是外部視角的異國情調符號，不是民國時期的音樂。

### 4.2 戰爭的處理方式

- 戰鬥曲寫**緊張、壓迫、消耗**，不寫**凱旋、狂歡、痛快**。
  勝負音效與結算音樂尤其要克制——玩家剛剛「打贏」的是一場真實戰役的抽象化。
- `FINAL`（結局）在原版是銅管合唱編制、以全速直接收尾，沒有打擊堆疊出來的高潮。
  現代版**不要把它改寫成宏大的勝利終曲**——這是編輯決定，不是從原版速度資料推出來的
  （原版那次大幅漸慢在曲子前段，見 §1.2）。
- 避免以音樂手法把任何一方標記成「邪惡」。玩家可以扮演任何勢力，
  包含各路軍閥；勢力主題若要做，差異只在**地域色彩與編制**，不在道德暗示。
- 日本勢力的音樂**不使用**「尺八＋都節音階」這種簡化標記。

### 4.3 素材來源

- **全部原創。** 不引用任何既有旋律，包含已進入公有領域的傳統曲牌
  （《茉莉花》《春江花月夜》《將軍令》…）。參考的是**語法**，不是**旋律**。
  這樣可以完全避開「引用了什麼、代表什麼」的爭議，也避開著作權灰帶。
- 若日後決定引用傳統曲牌，必須先做一份出處與公有領域狀態的查證表放進
  `docs/reference/`，並在遊戲內致謝頁列出。**不在本文件授權範圍內。**

### 4.4 致謝

原版作曲 **吳宗凱**、**游戲工場** 必須出現在遊戲內致謝與 README。
重新編曲版本要明確標示「編曲：⋯／原曲：吳宗凱・游戲工場（1992）」，
不得讓人誤以為旋律是新寫的。

## 5. 民國時期的音樂語言

這一節是**參考語彙表**，供編曲時取用。每一項都要對照 §4.1 的禁用清單。

### 5.1 那個年代實際存在的四條線

| 音樂類型 | 大致年代 | 特徵 | 可用於 |
|---|---|---|---|
| **學堂樂歌** | 1900s–1920s | 中文詞配西洋或日本曲調；齊唱、方整樂句、簡單和聲 | 歷史敘事的樸素感 |
| **上海時代曲** | 1927–1949 | 五聲旋律配爵士小樂隊（薩克斯、小號、鋼琴、吉他、爵士鼓）；黎錦暉一脈 | 都市、政略、外交場景 |
| **改良國樂** | 1920s–1930s | 劉天華一脈把二胡從伴奏樂器改造成獨奏樂器，引入西洋作曲技法；學院化的國樂合奏開始成形 | 主題、抒情、過場 |
| **西式軍樂隊** | 晚清引入，民國普及 | 銅管＋軍鼓的進行曲；北洋各系與國民革命軍都設軍樂隊 | 進行曲、動員、行軍 |

**關鍵觀察**：這四條線都是「中西混合」的產物。1920–40 年代的中國城市音樂**本來就不純**
——上海的百代錄音棚裡，五聲旋律配的就是西洋和聲與爵士節奏組。
所以原版那種「西樂編制 + 局部五聲」的寫法，**其實比純國樂更貼近史實**。
這是 §3 那條線最有力的支撐：現代化編曲要往「1930 年代上海樂隊」靠，
不是往「當代新國樂」靠。

### 5.2 樂器語彙

| 群 | 樂器 | 語法要點 |
|---|---|---|
| 拉弦 | 二胡、板胡、京胡 | 滑音、揉弦是語法核心；二胡音域約 D4–D6，寫太低會失去特徵 |
| 彈撥 | 琵琶、三弦、中阮、古箏、月琴 | 輪指、掃弦；琵琶的「武曲」語彙適合戰鬥但**別直接引用既有武曲** |
| 吹管 | 曲笛、梆笛、簫、笙、嗩吶 | 嗩吶穿透力極強，用在葬儀與大場面；笙可做持續和聲 |
| 打擊 | 板鼓、大鑼、小鑼、鐃鈸、堂鼓 | 京劇鑼鼓經是最強的文化標記，也最容易變刻板印象——**節制使用** |
| 西樂 | 銅管組、木管組、弦樂組、鋼琴、爵士鼓 | 原版編制的直接對應 |
| 時代質感 | 蟲膠唱片噪聲、AM 廣播頻寬、鋼絲刷 | 只當**效果**，不當主要音色（見 §6.4）|

### 5.3 八首曲子的編曲方針

| 曲名 | 原版性格 | 現代編曲方向 | 主導音色 |
|---|---|---|---|
| `MAINTHEM` | 半音化、樂隊編制、136 秒的長篇，開頭有漸快 | **1930 年代軍樂隊 + 弦樂**。原版的長號主奏保留為銅管主奏；oboe1/sax1 那條線交給雙簧管與中音薩克斯，保留那種「軍樂隊裡混了爵士樂手」的時代感 | 銅管組、弦樂、軍鼓；二胡只在再現段作為一條對位線 |
| `SCENE` | 旋律模式、節奏性素材為主、政略主畫面最常聽到 | **最需要耐聽**。做成低調的循環織體：鋼琴／揚琴分解音型 + 弦樂長音 + 極輕的打擊。原版把 bdrum1/synsnr1 當旋律樂器擺在聲部 1/2，那個「以打擊當音高素材」的想法值得保留成撥弦或木琴 | 揚琴、鋼琴、弦樂低音；避免任何持續刺激的音色 |
| `STRATEGY` | BPM 40（最慢）、七聲、木琴＋鋼琴＋長號＋顫音琴＋巴松＋長笛的室內編制 | **室內樂**。木管五重奏質感，加顫音琴。這是思考型畫面的音樂，寫「留白」 | 長笛、巴松、顫音琴、鋼琴；可加簫 |
| `BATTLE1` | **五聲最明確的一首**（A 羽 0.90），sitar1／tincan1／syn1-3 這種怪音色 | **這首才是該國樂化的那一首**。sitar1 的位置直接換成琵琶或三弦，tincan1 換成小鑼／梆子。原版用合成音色是因為 OPL 沒有彈撥樂器可用，不是因為想要合成器音色 | 琵琶、三弦、板鼓、梆笛；低音用弦樂或低音鼓 |
| `BATTLE2` | 完整 C 大調七聲、小提琴×2 ＋銅管＋鋼琴的樂隊寫法 | **交響性戰鬥曲**。與 `BATTLE1` 形成對比：一首中式彈撥、一首西式管弦。可對應「北伐 vs 抗戰」兩個時期 | 弦樂群、銅管、定音鼓 |
| `BT02` | 40 秒、BPM 120、有下彎滑音、戰報結算畫面 | **短促、功能性**。這是玩家反覆聽到的結算音樂，做成 30–40 秒完整段落而非硬循環。原版的滑音裝飾用二胡或板胡表現最自然 | 二胡、撥弦低音、輕打擊 |
| `WALL` | 旋律模式、BPM 76、鋼琴和弦被拆成四個聲部、豎琴＋法國號，78% 處有一小段半速 | **抒情過場**。硬體限制解除後，四聲部和弦回歸鋼琴本體，豎琴保留。那段半速是原版寫的表情，照做 | 鋼琴、豎琴、法國號、弦樂；可加簫 |
| `FINAL` | 52 秒、銅管合唱編制；**前段 8%–15% 一次拉到 0.445× 的大幅漸慢**，結尾維持全速直接收 | **克制的終曲**。銅管合唱式織體（原版就是 tromb×2 + trumpet×3 + oboe），加人聲哼鳴（無詞）。前段那次漸慢是全作最大的速度手勢，照原版曲線做。**結尾不要加勝利感的打擊高潮**——§4.2 | 銅管、弦樂、無詞人聲 |

### 5.4 兩條技術性的編曲約束

1. **小節對齊。** 現代編曲版的每一小節必須與原版同一小節對應（原版是 240 tick/拍、
   4 拍/小節）。這樣切換主題時可以在同一個音樂位置無縫換源（§6.2）。
   段落可以加導入與收束，但**循環段本體的小節數不得改變**。
2. **循環點必須乾淨。** 提供 `LOOPSTART` / `LOOPLENGTH`（取樣數）中繼資料，
   循環接點做過零與尾韻重疊處理。原版是硬接，remake 不必沿用這個缺點。

## 6. 技術落地（Go / Ebiten）

### 6.1 兩條音訊路徑，對應同一套主題模型

`docs/design/10-visual-modernization.md` §2.1 定義的 Preset／Axis 模型直接沿用，
**新增第四根軸**：

| 軸 | 值 | 影響 |
|---|---|---|
| `audio` | `retro` / `modern` | BGM 音源與音效層 |

- `audio=retro`：**軟體 OPL2 合成**，直接播放原版 `.MUS` / `.TIM`。
  逐暫存器重現 1992 年的聲音。
- `audio=modern`：播放重新編曲的串流音檔。

`prefs.json` 沿用同一個檔案（視覺文件 §2.3）：

```json
{ "theme": "retro", "audio": "", "volumeMusic": 0.7, "volumeSfx": 0.7, "audioDevice": "auto" }
```

空字串 = 沿用 preset。優先序：命令列旗標 > 設定檔 > 內建預設（`retro`）。

⚠️ 與視覺的 `retro` 一樣：**`audio=retro` 需要玩家自備原版檔案**
（`CLAUDE.md` §9 禁止散布 `.MUS` / `.TIM`）。玩家沒有原版時，設定選單要把
`audio=retro` 標成不可用**並說明原因**，不是靜默隱藏。

### 6.2 切換的時機與行為

音訊不能像重畫一張畫面那樣瞬間換掉，要定義行為：

| 情況 | 行為 |
|---|---|
| 遊戲中切換 `audio` 軸 | **交叉淡入淡出 300 ms**，新音源從**相同的音樂位置**（小節：拍）接續。§5.4 的小節對齊就是為了這件事 |
| 切換曲目（進戰鬥、看戰報）| 淡出 200 ms → 新曲從頭。原版是硬切，remake 這裡允許差異，登記進差異表 |
| 熱鍵 | 視覺用 F2；音訊建議 **F3**，同樣避開 ESC／F10 的既定語意（`CLAUDE.md` §9）|
| 無音訊裝置 / CI | `-audio=off` 完全跳過音訊初始化 |

**`-audio=off` 是硬需求，不是選配。** Ebiten 的 audio context 在無音效裝置的環境會失敗，
而截圖回歸測試與 CI 都跑在那種環境。音訊子系統必須能整個不啟動而不影響其他部分。

### 6.3 復古路徑：內嵌 OPL2 合成器

```
.MUS ──► 事件排程器（tick → 事件）──► OPL2 暫存器寫入 ──► 軟體合成 ──► 48 kHz PCM
.TIM ──► 音色 → 暫存器對應 ───────────┘
```

- **合成器選型**：兩個候選。`Nuked-OPL3`（週期精確，音質基準）與 DOSBox 的 `dbopl`
  （較快，音質已足夠）。兩者都是 C，需要移植成純 Go——**不要用 cgo**，
  跨平台建置（`CLAUDE.md` §8 M7）會變複雜。建議先移植 `dbopl`，
  用 `Nuked` 當離線比對基準。**未決，見 §9 A1。**
- **排程**：事件排程器的時間基準用取樣數，不用 wall clock。
  tick 速率 = `tempo / 60 × 240` Hz（`docs/formats/06` §4.1）。
  每產生 `sampleRate / tickRate` 個取樣就推進一個 tick。這樣暫停、變速、
  無頭離線算繪都一致。
- **`An`（聲部音量）到 OPL total level 的對應目前未知**（`docs/formats/06` U1）。
  解不出來就先用對數對應並標為 remake 差異；解開驅動後改回原樣。
- **驗收**：把原版在 DOSBox 裡的 OPL 暫存器串流錄下來，與 Go 版產生的串流逐筆比對。
  這是唯一可信的驗收標準——「聽起來很像」不算（`CLAUDE.md` §5 第 3 條的音訊版）。

### 6.4 現代路徑：串流音檔

| 決定 | 選擇 | 理由 |
|---|---|---|
| 格式 | **Ogg Vorbis**，48 kHz 立體聲，約 160 kbps | Ebiten 內建解碼；無授權疑慮；檔案小 |
| 即時合成 | **不做** | 要內嵌音色庫與合成引擎，體積與複雜度都比串流高，換不到相應的好處 |
| 循環 | `LOOPSTART` / `LOOPLENGTH` Vorbis comment（取樣數）| 業界慣例，解析簡單 |
| 分軌 | **第一版不做** | 動態混音（例如戰況吃緊時加入打擊聲部）很誘人，但那是**新玩法回饋**，會踩到 §4.2 與 remake 差異的界線。列為 §9 A3 |
| 時代質感 | 蟲膠噪聲／AM 頻寬只用在 `MAINTHEM` 開頭與 `FINAL` 結尾，且**可關閉** | 用整首會犧牲可聽性；而且「老唱片」是一種外部懷舊視角，不是 1930 年代的人聽到的聲音 |

**混音準則**：立體聲寬度保守（原版是單聲道，過寬會失去年代感）；
主要動態範圍留給音樂本身，不做現代流行樂的重壓縮。

### 6.5 分層與相依

```
internal/audio/          純解碼與合成，不認識 Ebiten
    mus/                 .MUS / .TIM 解析（對應 tools/mus.py）
    opl/                 OPL2 軟體合成器
    stream/              Ogg 解碼與循環點
internal/ui/audio.go     Ebiten 播放器、混音、主題切換
internal/game/           只發「播第 N 首 / 停」的訊號，不碰音訊
```

理由與 `internal/ui/textlayout` 相同（`CLAUDE.md` §11）：
**解析與合成必須能在無頭環境測試**。Ebiten 在 init 期就要求顯示器與音效裝置，
把合成器綁進去就等於放棄自動化驗收。

## 7. 音效

### 7.1 原版有什麼（confirmed）

`docs/formats/06` §6 的結論：

- **`WAR.EXE` 與 `SR.EXE` 完全沒有音效。** 政略與戰鬥全程只有 BGM。
- **`GRT.EXE` / `GRTE.EXE`（開場與結局動畫）有 PC 喇叭掃頻音**，四個呼叫點，
  參數是起頻、迄頻、步進與延遲圈數。頻率上限 4660 Hz。延遲用空迴圈，
  **速度隨 CPU 漂**——這是缺陷不是特徵。

### 7.2 remake 的處理

| `audio` 軸 | 音效層 |
|---|---|
| `retro` | 完全照原版：主遊戲**無音效**；開場與結局重現 PC 喇叭掃頻（方波，由 8253 除數還原頻率）|
| `modern` | 新增一層節制的音效 |

`retro` 的掃頻音有一個問題：原版時長取決於 CPU 速度，沒有正確答案。
處理方式是**在 DOSBox 用固定 cycles 量一次**，把量到的時長寫成常數並在差異表登記
（`CLAUDE.md` §9「截圖驗收要帶固定亂數種子」的同一種紀律）。列為 §9 A2。

### 7.3 `modern` 音效清單（提案）

原則：**只做「確認動作」與「狀態變化」的回饋，不做擬真戰爭音**。
理由是 §4.2——槍砲聲、慘叫、爆炸會把抽象的回合制戰棋推向擬真戰爭再現。

| 類別 | 項目 | 質感 |
|---|---|---|
| 介面 | 游標移動、選項確認、取消／返回、非法操作 | 木質、短促、低音量；取材自算盤、木魚、紙張 |
| 政略 | 指令發布、指令數用盡、季節推進、年度結算 | 印章、鑼一聲（極輕）、翻頁 |
| 軍事 | 部隊移動、部隊交戰、部隊潰散、攻城 | **抽象化**：鼓點、金屬摩擦；不做槍聲爆炸 |
| 事件 | 事件發生、將領死亡、勢力滅亡 | 將領死亡與勢力滅亡用**靜默 + 單一低音**，不用音效堆疊 |
| 存檔 | 存檔成功、存檔失敗 | 存檔失敗必須有明確可辨的回饋（`CLAUDE.md` §9：存檔失敗就不離開）|

硬規則：
- **音效不得攜帶原版只用視覺呈現的資訊**，也不得成為理解遊戲的必要條件。
  關掉音效要能完整遊玩。
- **音效不改任何規則**（`docs/design/10` §6.2 的紅旗清單同樣適用）。
- 每一個新增音效都要登記進 remake 差異表。

## 8. 落地路徑

每一階段可獨立驗收，前一階段沒過不進下一階段。

### P0 — 解碼層與離線驗證（不出聲）
- `internal/audio/mus` 移植 `tools/mus.py` 的解析器，附 8 首曲子的 golden test：
  事件數對 `nrCommand`、資料長度對 `dataSize`、音色索引全部落在範圍內。
- **驗收**：8/8 解析結果與 `tools/mus.py` 逐事件相同。無頭可跑。

### P1 — 復古音源（`audio=retro`）
- 移植 OPL2 合成器，接上排程器，輸出 PCM。
- **驗收**：與 DOSBox 錄下的 OPL 暫存器串流逐筆比對（§6.3）。
  這一步同時把 `docs/formats/06` 的 U1／U2／U5 三個未決項推向定案。

### P2 — 一首試作編曲
- 先做 **`BT02`**（40 秒、9 聲部、最短），走完整條流程：
  MIDI 母稿 → 混音 → Ogg + 循環點 → 遊戲內播放 → 與 `retro` 交叉切換。
- **驗收**：§3.3 的逐音一致檢查通過；F3 切換聽不到接縫。

### P3 — 其餘七首
- 依序：`WALL`（63 s，抒情）→ `STRATEGY`（97 s，室內樂）→ `BATTLE1`（國樂化的那一首）
  → `BATTLE2` → `FINAL` → `SCENE`（最耐聽的那一首放後面，需要最多修訂）
  → `MAINTHEM`（最長、最複雜，放最後）。
- `BATTLE1` / `BATTLE2` 同時把觸發路徑接上（§2）。

### P4 — 音效層（`audio=modern`）
- 依 §7.3 清單製作；`retro` 的 PC 喇叭掃頻還原。

### P5 — 混音與發行
- 全曲響度統一；`-audio=off` 路徑驗證；deny-list 掃描確認沒有原版 `.MUS`／`.TIM`
  或轉出的中介檔進入發行包。

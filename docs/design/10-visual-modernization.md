## 0. 這份文件要解決什麼

`CLAUDE.md` §1 把 remake 的定位寫成「還原 + 現代化外殼」：核心規則對齊原版，
外殼允許現代化，但每一項改動都要標記成 remake 差異。這句話目前沒有落地的做法
——現有的 `internal/ui/render` 只有一套實作，而且刻意做成逐像素還原原版
（`glyph.go` 的加粗與 20 px 字距、`battlepanel.go` 六個標籤零差異）。

要在同一個執行檔裡同時做到「保存原版畫面」與「現代化呈現」，就必須把
「畫什麼」與「怎麼畫」拆開。這份文件定義那條界線、兩套資產怎麼並存、
切換的粒度與時機，以及分階段的落地路徑。

**沒有涵蓋的**：音樂與音效（`.MUS`／`.TIM` 格式未解，見 §10 未決 9）、
開場動畫的重製（§10 未決 5）、多語系的字串內容（`translations/glossary.md` 的職責）。

## 1. 原版視覺清單與分類

先把「現在畫面上有什麼」列全，再逐項判斷該不該動。分類只有三種：

| 標記 | 意義 |
|---|---|
| **保存** | 這是還原的一部分。復古模式必須逐像素等同原版，現代模式**也不得改語意**，只能改呈現媒介 |
| **可換** | 純呈現，現代模式可以整個換掉，換掉不影響任何規則或資訊量 |
| **改了會碰玩法** | 換掉會改變玩家拿到的資訊或操作能力。要動必須先進 §7 的紅旗流程 |

### 1.1 顯示模式與畫布

| 項目 | 事實 | 分類 |
|---|---|---|

## 2. 主題模型

### 2.1 切換的粒度

三個層級，由粗到細：

```
Preset（玩家看到的那個開關）
  └─ Axis（三根獨立的軸，進階設定才展開）
       └─ Asset / Metric（實作單位，玩家不直接碰）
```

**Preset** 只有兩個具名值：`retro`、`modern`。這是玩家在設定選單看到的唯一選項，
預設 `retro`（保存專案的預設值應該是原版樣貌）。

**Axis** 三根，各自可獨立覆寫 preset 的值：

| 軸 | 值 | 影響 |
|---|---|---|
| `icons` | `retro` / `modern` | 地形圖塊、部隊圖示、資源與 UI 圖示 |
| `typography` | `bitmap` / `vector` | 字模 vs 向量字，連帶影響字距與行高 |
| `layout` | `original` / `wide` | 640×350 固定版面 vs 現代基準畫布（§6）|

**為什麼是三根而不是一個總開關**：這三者的相依性不對稱。
`typography=vector` 幾乎一定要 `layout=wide`（點陣版面是照 16 px 全形格排的，
向量字塞不進去）；但 `icons=modern` 配 `typography=bitmap` 是完全合理的組合
——想看高解析地形圖塊、又要原版字。反過來 `icons=retro` + `layout=wide`
也成立（原版圖塊整數放大 2× 放在寬版面裡）。硬綁成一個開關會擋掉這些組合。

**非法組合的處理**：`typography=vector` + `layout=original` 判定為非法，
載入時降級成 `layout=wide` 並在 stderr 留一行說明。不做靜默修正
——靜默修正就是下一輪除錯的假訊號。

### 2.2 切換時機

| 時機 | 是否支援 | 理由 |
|---|---|---|
| 命令列旗標 `-theme retro\|modern` | ✅ | 無頭截圖與 CI 比對要用，這是最重要的一個 |
| 設定選單（指令 15「其他選項」底下）| ✅ | 原版就有這個入口，不必自己發明選單 |
| 遊戲中即時熱鍵 | ✅ | 主題只影響呈現層，切換不碰任何狀態。建議 **F2**（避開 ESC／F10 的既定語意）|
| 戰鬥中切換 | ✅ | 同上。戰鬥狀態在 `internal/game`，重畫一張畫面就好 |

**即時切換能成立的前提**：呈現層對規則層是唯讀的。這一條要當硬規則寫進 §7（R7）。

### ⭐ 使用者確認（2026-08-01）：是**切換**不是替換

「icon 允許多種模式切換（不是替換喔，是可以在遊戲中設定切換）」

也就是說三套圖示**同時存在於發行包裡**，玩家隨時改隨時生效：

- **F2** 在 `retro` → `modern` → `symbol` 之間循環，立即重繪，不重啟、不回主選單
- **設定選單**也要有同一個選項（熱鍵是捷徑不是唯一入口，玩家不一定知道 F2）
- 選擇存進 `prefs.json`，下次啟動沿用（但**不進遊戲存檔**，見 §2.3）

架構上的要求：**資產不能在 init 期綁死成單一套**。
三套圖示各自解碼後常駐（總量不大：`NEWICON` 那批 + 兩套 SVG 出圖的 PNG），
切換只是換一個查表的索引，不重新載入檔案——否則切換會卡頓。

⚠️ `retro` 那一套的來源是玩家自備的原版檔案。**玩家沒有原版時 `retro` 不可選**，
設定選單要把它標成不可用並說明原因，不是靜默隱藏。

### 2.3 持久化

**主題偏好不進存檔。** `CLAUDE.md` §9 要求存檔寫回是「改寫不是重建」、
驗收標準是 byte-for-byte round-trip；多塞一個欄位就把這條破壞掉了，
而且原版存檔根本沒有這個欄位可以放。

偏好存在獨立的設定檔：

```
$XDG_CONFIG_HOME/dsds/prefs.json     （沒設就用 ~/.config/dsds/prefs.json）
{ "theme": "retro", "icons": "", "typography": "", "layout": "", "scale": 2 }
```

空字串 = 沿用 preset。優先序：命令列旗標 > 設定檔 > 內建預設（`retro`）。
設定檔讀不到或壞掉一律回退到內建預設，不當錯誤處理。

## 3. 資產組織

### 3.1 兩套並存的方式

```
（版控內）
assets/themes/modern/
  theme.json            主題描述：資產清單、度量、色票
  terrain/*.png         現代地形圖塊
  units/*.png           現代部隊圖示
  ui/*.png              資源與狀態圖示
  fonts/*.woff2 或 .ttf 向量字（授權見 §10 未決 3）
  src/*.svg             作者原始檔（出圖用，不進執行期）

（不進版控，執行期從玩家的原版目錄讀）
workplace/orig/game/    NEWTERR.TPC、NEWICON.TPC、*.15、*.RGB …
```

**復古主題沒有自己的資產目錄。** 它的「資產」就是原版檔案，
由 `-game` 指到的那個唯讀目錄提供。這樣的好處是污染不可能發生：
現代資產永遠不會覆蓋原版檔案（不同目錄、不同解碼路徑），
原版資產也永遠不會被誤 commit（`deny_scan.sh` 擋副檔名 + `workplace/` 整個目錄）。

### 3.2 主題介面

放在 `internal/ui/theme`（新 package，**不依賴 Ebiten**，理由同 `render`：
無頭要能測）。介面刻意做窄——呼叫端只需要知道三個概念：

```
type Theme interface {
    Tile(kind assets.TileKind) Bitmap        // 地形圖塊
    Rail(idx int) Bitmap                     // 鐵路圖塊
    Unit(branch uint8, faction int, facing uint8) Bitmap  // 部隊圖示
    Icon(id IconID) Bitmap                   // 資源／狀態／指令圖示
    Metrics() Metrics                        // 度量：格子尺寸、行高、字距、面板寬
    Text() textlayout.Face                   // 字型（點陣或向量）
}
```

`Bitmap` 是一張已經解好的 RGBA（不是 `*ebiten.Image`）。
兩個實作：`retroTheme`（包住現有的 `TileSet` / `LoadIcons` / `PanelFonts`）
與 `modernTheme`（讀 `theme.json` + PNG）。

**`render` 層的改動方向**：現在 `DrawTiledBattlefield` 直接吃 `*TileSet`，
改成吃 `theme.Theme`。這是唯一必要的簽章改動，其餘畫圖函式不動。

⚠️ **`Unit` 的參數多了 `faction`。** 原版只有綠／紅兩色（`BranchIcon` 的 `red bool`），
但十大勢力編號 0–9（`docs/playtest/13`）——原版在戰場上顯示的是「攻方／守方」
不是「哪一個勢力」。現代主題可以做十色，**但復古主題必須維持兩色**，
否則就是在復古模式下增加資訊（§7 R2）。`retroTheme` 的實作把 `faction`
折成攻守二值，這個折疊要寫在程式碼註解裡。

### 3.3 deny-list 的影響（落地時要處理）

`tools/deny_scan.sh` 現在**只放行 `docs/images/*.png`**，其他位置的 PNG 一律報錯
（第 40 行）。現代主題的 PNG 放在 `assets/themes/modern/` 會被擋下。

落地時要在 `deny_scan.sh` 加第二條白名單：`^assets/themes/modern/.*\.(png|svg)$`。
**這條白名單有風險**：它是「自製美術」的通道，也可能被拿來偷渡原版衍生物。
配套是加一個檢查——現代主題的 PNG 尺寸不得等於原版圖塊尺寸的整數倍
且色數不得 ≤ 16？這條規則太脆弱，不建議。改用可稽核的做法：
**每個現代資產都要有對應的 `src/*.svg` 原始檔**，沒有原始檔的 PNG 不放行。
原版資產不可能有 SVG 原始檔，這個檢查是可信的。

（本文件不修改 `deny_scan.sh`，只登記需求。）

## 4. 現代視覺語言

### 4.1 色彩：從原版量到的顏色長出來，不是憑空選

現有程式碼裡有三個從實機截圖量到的顏色（`internal/ui/render/panel.go` §配色）：

| 用途 | 原版值 | 語意 |
|---|---|---|
| 面板底 | `#FFFFA2` | 紙 |
| 標籤與數值 | `#AE0000` | 朱（墨的暖色版）|
| 省名／標題 | `#0000AA` | 靛 |

現代色票由這三個推出來，讓兩套主題在視覺上仍是同一款遊戲：

| 名稱 | Hex | 用途 |
|---|---|---|
| `paper` | `#F2EAD3` | 面板底、對話框底（原版米黃降飽和，長時間閱讀不刺眼）|
| `paper-deep` | `#E3D7B8` | 面板分區、表頭 |
| `ink` | `#2B2118` | 主文字 |
| `ink-mute` | `#6B5E4E` | 次要文字、單位 |
| `vermilion` | `#A3161A` | 數值、警示、我方強調（原版 `#AE0000` 降一階明度）|
| `indigo` | `#1F3A8A` | 標題、可選項、連結（原版 `#0000AA` 降飽和）|
| `jade` | `#2E6B4F` | 正面狀態（補給充足、忠誠高）|
| `amber` | `#B8860B` | 注意狀態（缺糧、忠誠低）|

**對比度要求**：主文字對 `paper` ≥ 7:1（WCAG AA 內文級），
次要文字與圖示線條 ≥ 4.5:1。這是硬性驗收項，不是建議。

### 4.2 勢力色（十色 + 中立）

原版戰場只分綠／紅，但政略地圖上是分勢力上色的（實機畫面可見）。
**現代主題的十色配盤尚未決定要沿用原版還是重配**（未決 6）——
下表是「重配」情況下的規範，不是最終值：

| 勢力 | Hex | | 勢力 | Hex |
|---:|---|---|---:|---|
| 0 | `#C0392B` 朱 | | 5 | `#7B4BA0` 紫 |
| 1 | `#2C5AA0` 藍 | | 6 | `#1F8A8A` 青 |
| 2 | `#4A7C3F` 綠 | | 7 | `#C2185B` 洋紅 |
| 3 | `#C08A2E` 赭 | | 8 | `#8B5A2B` 棕 |
| 4 | `#5A6B7C` 鋼灰 | | 9 | `#7A8B2E` 橄欖 |
| 中立 | `#9E9E9E` | | | |

三條配套規則：

1. **顏色不得是唯一的識別方式。** 十色裡必然有色覺障礙者分不開的組合
   （2 綠 / 3 赭、0 朱 / 7 洋紅）。部隊圖示要同時帶勢力的**番號數字**
   （原版本來就有番號系統，`docs/spec/02` §`+25..+28`），地圖上的省份
   要能開「顯示勢力代號」。
2. **每個部隊圖示外加 1 px `ink` 描邊 + 內側 1 px `paper` 描邊。**
   戰場底色從深綠（森林）到白（雪山）都有，沒有描邊的圖示在某些地形上會消失。
3. 勢力色只用在「歸屬」，不用在「狀態」。狀態一律用 §4.1 的 `jade`／`amber`／`vermilion`。

### 4.3 圖示風格：兩個方案，未決

題材是民國初年的北伐與抗戰。兩個方向都成立，**需要使用者裁決**（未決 1）：

**方案 A — 軍事地圖符號**
把部隊畫成制式標記（步兵斜十字、騎兵斜線、砲兵實心圓、裝甲橢圓），
外框是勢力色的盾形或矩形。

- 優點：六角格上辨識度最高，遠看也分得出來；跟民初到二戰的作戰地圖有史料相合性；
  出圖成本低，可以整組用同一套幾何規則生成，風格不會漂。
- 缺點：跟原版差距最大。原版的鋼盔／馬頭／戰車／大砲是寫實側視圖，
  換成抽象符號會流失「這是一款 1992 年台灣戰棋」的味道。

**方案 B — 高解析寫實重繪**
沿用原版的構圖（鋼盔、馬頭、戰車、側視野戰砲），重畫成 3× 解析度、
仿民初石印畫報／木刻的線條與網點。

- 優點：與原版連續，復古／現代切換時玩家認得出是同一個東西；
  對保存專案的定位更一致。
- 缺點：美術工作量高一個量級（每個圖示都是獨立作品，不能生成）；
  風格一致性靠人維持；六角格 32×24 的空間裡寫實圖的辨識度不如符號。

✅ **已裁決（使用者，2026-08-01）：兩套都做，但分階段。**

`icons` 軸從兩個值擴充為三個：

| 值 | 內容 | 階段 |
|---|---|---|
| `retro` | 原版 `NEWICON.TPC` | P0（本來就有）|
| `modern` | 方案 B 寫實重繪 3× | **P1** |
| `symbol` | 方案 A 軍事地圖符號 | **P4 之後** |

⚠️ 這個裁決把美術工作量變成兩套，而且**兩種風格都要長期維護**。
配套要求：

- `symbol` 這一套必須**用同一組幾何規則生成**（見 §4.3 方案 A 的優點），
  不要變成第二批手繪資產——否則維護成本會失控
- 三個值的**資訊量必須相同**。`symbol` 不能因為好畫就多顯示東西，
  也不能因為抽象就少顯示朝向（砲兵六朝向是資訊，見紅旗 R3）
- 切換 `icons` 不得影響任何規則層行為，三個值的截圖驗收各跑一份

## 5. 解析度與版面

### 5.1 兩個基準畫布

| 模式 | 邏輯畫布 | 縮放 |
|---|---|---|
| `layout=original` | 640×350 | 整數倍放大（1×/2×/3×），最鄰近取樣。**不做非整數倍**——點陣字模非整數放大會糊 |
| `layout=wide` | **1280×720**（暫定，見未決 2）| 依視窗大小等比縮放，保留黑邊 |

640×350 的長寬比是 1.829，不是 16:9（1.778）。`layout=original` 在 16:9 螢幕上
左右留黑邊；要不要提供「拉伸填滿」的選項是玩家偏好問題，
但**預設不拉伸**——拉伸會改變原版的像素比例，對保存專案是錯的預設值。

### 5.2 戰場在 `wide` 下的排法

原版戰場的幾何是規則不是排版（`docs/re/07` §3）：

```
x = col × 32
y = row × 24 + (col 為奇數 ? 12 : 0)
整場 = 14 欄 × 32 = 448 寬，13 × 24 + 12 + 24 = 348 高
```

現代模式**只放大格子尺寸，不改幾何公式**。兩個候選：

| 格子 | 戰場尺寸 | 1280×720 的剩餘寬 |
|---|---|---:|
| 48×36（1.5×）| 14×48 = **672**，13×36 + 18 + 36 = **522** | 608 |
| 64×48（2×）| 14×64 = **896**，13×48 + 24 + 48 = **696** | 384 |

2× 的高度 696 幾乎頂滿 720，面板只剩 384 寬——夠放 13 個欄位，但放不下
「面板 + 指令選單」同時顯示。1.5× 留 608 寬，可以做成「面板 + 指令選單並排」，
少一次開關選單的操作。**建議 1.5×**，但這取決於未決 2 的畫布尺寸。

### 5.3 排版層抽離：`internal/ui/textlayout`

`CLAUDE.md` §11 已經預告了這個 package（「排版邏輯不能依賴 Ebiten」），
但目前還不存在。現代化與多語系**指向同一個抽離**，不必做兩次：

- 英文版：640×350 的版面是照全形點陣格排的，換成比例字後字寬、行高、
  對話框全要重算（`CLAUDE.md` §6）。
- 現代模式：向量字的 advance 不是固定 20 px。

介面同樣做窄：

```
type Face interface {
    Advance(r rune) int        // 這個字佔多寬
    LineHeight() int
    Draw(dst Bitmap, s string, x, y int, col RGB)
}

type Box struct { ... }        // 語意化的欄位框：label 靠左、value 靠右、對齊到 slot
func Layout(boxes []Box, f Face, m Metrics) []Placement
```

兩個 `Face` 實作：`bitmapFace`（advance 恆 20、行高 18、加粗開關）
與 `vectorFace`（走字型檔的 metrics）。

**現有 `panel.go` 的硬座標要改成語意化的 Box。** 現在的 `panelLabel = panelX + 8`、
`panelValue = panelX + 182`、`lineH = 18` 是 remake 的排版選擇（註解已標明），
搬進 `Metrics` 之後兩套主題各給一組值，`panel.go` 只描述「有哪些欄位、誰對齊誰」。

⚠️ **戰鬥面板不能這樣搬。** `battlepanel.go` 的座標是量自實機的
（三字標籤 520 起字距 18、二字標籤 530 起字距 20，「黃　金」是分散排版不是置中），
而且有逐像素零差異的測試護著。復古模式**必須繼續用寫死的實機座標**，
現代模式才走 `textlayout`。這是兩條路徑，不是一條路徑兩組參數
——`CLAUDE.md` §7 第 4 條說「一條規則只留一份實作」，這裡的做法是
把復古座標當成「原版事實的記錄」（等同資料），現代座標才是「規則」。

## 6. 與規則層的邊界

### 6.1 純呈現（不碰玩法，可放心做）

- 換地形圖塊、部隊圖示、鐵路圖塊的畫法
- 換字型與字距、行高
- 版面重排（面板位置、選單排法、視窗縮放）
- 色彩、描邊、陰影、過場動畫的時長
- 加入不改變資訊量的視覺回饋（選中格子的高亮、hover 效果）

### 6.2 紅旗：碰到玩法的改動

每一條都要在動手前單獨評估，並且**登記進 §7 的差異表**。

| # | 改動 | 為什麼是紅旗 | 處置建議 |
|---|---|---|---|
| **R1** | 改六角格幾何或格子鄰接關係 | `x/y` 公式與六鄰位移表出自 `sub_50FF5`，是規則不是排版。改了就改了移動與射程 | **不准改。** 只放大不改公式 |
| **R2** | 現代模式新增狀態圖示（缺糧、被包圍、已行動…）| 原版沒有這些提示，玩家要自己判讀數字。加上去等於降低難度 | 做成可關的「輔助顯示」，**預設關**；差異表登記 |
| **R3** | 砲兵圖示不畫朝向 | `+31` 疑似是朝向（1..6），六張預繪圖示配六角格六方向是強證據（`docs/formats/05` §3.3）。不畫朝向 = 隱藏資訊 | 現代圖示**必須**表示朝向。若後續證實 `+31` 是射程不是朝向，這條再訂正 |
| **R4** | 現代模式顯示敵方部隊的兵力數值 | 原版顯示到什麼程度尚未逐項確認 | 先確認原版行為再決定；未確認前**照原版**（`docs/playtest` 有截圖可查）|
| **R5** | 加入滑鼠操作 | 原版是純鍵盤（數字鍵 1–6 六方向）。滑鼠點選會讓「選到不合法的目標」變成可能的輸入 | 可以做，但**滑鼠必須走與鍵盤同一條規則 API**，不得直接寫規則層狀態 |
| **R6** | 加入移動範圍／攻擊範圍高亮 | 原版要玩家自己算機動力與地形成本 | 同 R2：可關的輔助顯示，預設關 |
| **R7** | 呈現層呼叫 `game.Rand` | 原版的 LCG 序列是可重現的（`docs/re/17`），呈現層抽一次亂數就把序列污染了，固定種子的截圖驗收會失效 | **硬規則：`internal/ui/**` 不得 import 或呼叫 `game.Rand`。** 動畫需要隨機就自己開一個獨立的 `math/rand` |
| **R8** | 現代模式「修正」原版的顯示怪癖（欄位順序、疑似 bug 的畫面）| `CLAUDE.md` §1「不得默默改動遊戲規則」，術語表「原版 bug 照抄並標記」 | 不修。要修是 remake 差異，由使用者決定 |

`CLAUDE.md` §1 要求「每一項改動都要在文件裡標記為 remake 差異」。
格式固定成一行，欄位如下，新增差異就往下加：

| ID | 差異 | 類別 | 主題 | 依據／理由 | 可關 |
|---|---|---|---|---|---|
| VD-01 | 視窗放大 2×，邏輯解析度仍 640×350 | 純呈現 | 兩者 | `cmd/dsds` 既有行為 | 是（`-scale`）|
| VD-02 | 現代模式邏輯畫布 1280×720，面板與戰場重排 | 純呈現 | modern | §5 | 是（切回 retro）|
| VD-03 | 現代模式用向量字取代 16×15 點陣字模 | 純呈現 | modern | `CLAUDE.md` §6「原版的字模索引機制到 remake 就結束」| 是 |
| VD-04 | 現代模式部隊圖示用十色勢力區分，原版只有攻守兩色 | **資訊量增加** | modern | §3.2 | 是 |
| VD-05 | 現代模式狀態圖示（缺糧／被包圍／已行動）| **資訊量增加** | modern | §6.2 R2 | 是，**預設關** |
| VD-06 | 現代模式移動／攻擊範圍高亮 | **資訊量增加** | modern | §6.2 R6 | 是，**預設關** |
| VD-07 | 面板欄位改用語意化 Box 排版（座標不再寫死）| 純呈現 | modern | §5.3 | 不適用 |

**類別只有兩種**：`純呈現`、`資訊量增加`。第二種一律要有「可關」欄且預設關。
沒有第三種——若某個改動既不是純呈現也不只是資訊量增加，那它就是改規則，
不屬於這份文件的範圍。

## 8. 落地路徑

每一階段獨立可驗收，前一階段沒綠就不做下一階段。
**這份文件是 DRAFT，所有階段都要等它轉 READY 才能動手。**

### P0 — 主題介面（不換任何一張圖）

- 新增 `internal/ui/theme`，`Theme` 介面 + `retroTheme` 實作（包住現行程式碼）
- `render` 層的 `DrawTiledBattlefield` 等函式改吃 `theme.Theme`
- `cmd/dsds`、`cmd/screenshot` 加 `-theme` 旗標（此時只有 `retro` 一個合法值）

**驗收**：`internal/ui/render` 現有測試全綠且**逐像素零差異**；
`cmd/screenshot` 產出的 `menu-26.png`／`province-26.png` 與重構前 byte-identical。
這一階段的價值就是「什麼都沒變」——有一個像素變了就是重構出錯。

### P1 — 現代地形圖塊（22 + 21 張）

- 建 `assets/themes/modern/`、`theme.json`、SVG 原始檔與出圖流程（chrome-headless）
- `modernTheme` 實作，但**只實作 `Tile` 與 `Rail`**，其餘 fallback 回 retro
- `deny_scan.sh` 加白名單 + 「PNG 必須有對應 SVG」的檢查

**驗收**：`-theme modern` 能畫出全 39 省的戰場，22 種地形與 21 種鐵路各出現至少一次
且無縫平鋪；混用（現代地形 + 原版部隊圖示）畫面不破。
無頭截圖存進 `workplace/shots/`（不進版控）。

### P2 — 現代部隊圖示與勢力色

- 4 個 base 圖示 + 執行期上色 + 砲兵旋轉
- `Unit(branch, faction, facing)` 的 retro 折疊（十勢力 → 攻守兩色）

**驗收**：六個朝向的砲兵圖示與六角格六方向逐一對上（做一張對照圖）；
retro 模式下 `faction` 參數不影響輸出（回歸測試）；
十色 + 描邊在 22 種地形底上的對比度全部達標（自動量測，不靠肉眼）。

### P3 — `textlayout` 與向量字

- `internal/ui/textlayout`，`bitmapFace` + `vectorFace`
- `panel.go` 改成語意化 Box
- **`battlepanel.go` 的復古路徑不動**（§5.3）

**驗收**：`bitmapFace` 走 `textlayout` 之後，政略面板仍與原版逐像素零差異
（現有測試就是這個保險）；`vectorFace` 在 1280×720 下 13 個欄位不溢出、不重疊；
把最長的省名與將領名塞進去測邊界。

### P4 — 現代版面與 HUD

- 1280×720 版面：面板 + 指令選單並排
- 可關的輔助顯示（VD-05／VD-06），預設關

**驗收**：15 項指令全部可達；ESC／F10 語意在兩套主題下一致（`CLAUDE.md` §9）；
遊戲中 F2 即時切換主題，切換前後規則層狀態 byte-identical（這是 R7 的實證）。

### P5 — 開場與過場（範圍待定）

320×200 256 色的開場、`AC.TPC` 的 17 張戰鬥插圖、`NEWSDATA.DAT` 的 17 條新聞。
**三者都有前置未解項**（未決 4、5、7），現在排不進去。

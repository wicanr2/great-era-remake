# 指標與觸控輸入設計

狀態：DRAFT（桌面 Modern 高解析 H1/H2 與 M0 行動 viewport 已實作；Android binding／
真機與完整發行驗收尚未完成；M3 的可實作契約見 `docs/spec/05`）

## 目標

讓鍵盤、滑鼠與 Android 單指觸控共用同一套遊戲動作與規則。輸入裝置只負責
把座標或按鍵轉成穩定的動作識別碼，不得直接修改省份、人物、資源或戰鬥狀態。
原版鍵盤操作必須完整保留，觸控也不得成為另一套結果不同的規則入口。

2026-08-02 使用者已確認 Android 移植與點擊操作為正式路線，不再是
「是否要做」的未決項。尚待決定的只是封裝技術、Android 最低版本與
第一批實作範圍。

## 架構契約

1. 畫面狀態公布可執行的動作與命中區域，例如 `command.develop`、
   `common.confirm`、`common.back`；鍵盤與指標輸入都只派送這些動作。
2. 命中區域由實際版面配置產生，不另外維護一份容易漂移的座標表。
3. retro 將視窗座標反算至 640×350；Modern high／Android 則反算至 1280×720
   design surface；兩者都先扣除黑邊與安全區，黑邊點擊一律忽略。
4. 一次按下／抬起只觸發一次動作。拖曳超過容許距離時取消點擊，避免捲動或
   手指移動造成誤觸；不以懸停承載必要資訊。
5. Android 系統返回鍵與畫面上的返回按鈕都派送 `common.back`；其結果須與
   `Esc` 相同。存檔等高風險確認仍需明確的確認／取消動作。
6. 觸控目標至少 48×48 Android 密度獨立像素；若原味版面的文字較小，允許
   擴大不可見命中範圍，但不得改變相鄰項目的選擇優先順序。
7. 返回與翻頁箭頭以程式圖形繪製，不依賴使用者提供的倚天字庫。箭頭位置必須
   為原版欄頭、頁碼與資料保留空間；不得以「能點」為由遮住既有資訊。

## 分期

- M0：🟡 共用動作派送器、座標換算、地圖右上「指令」可見入口、政略主選單、
  發展、調動方式、商業、徵兵／整編、秘密行動、查閱、政策、其他選項、
  顯示設定、新聞／史事（`N`／滑鼠／觸控）與確認／取消已接；子畫面已有 48×48 可見返回，省名與自傳已有翻頁
  動作，將領清單可直接點選。尚需補其他長清單與數字鍵盤；證據見
  `docs/playtest/34-pointer-m0-options.md`。
- M1：🟡 將領、省份、自治、調動、整編與產能欄位已可直接點選；調動多選有
  條件式勾號送出。九類短目標／數量畫面與產能比例共用 6×2 觸控數字鍵盤，
  並保留實體鍵盤。桌面事件路由已閉合；密集清單 48dp 仍待 Android 實機或
  modern UI 放大驗證。證據見 `docs/playtest/35`、`36`、`37`。
- M2：🟡 戰場六角格座標反算與相鄰格點擊已接。點相鄰空格等同方向鍵 1–6，
  點鍵盤 Enter 原本會選到的第一個相鄰敵軍等同攻擊。原版圖塊是 32×24 矩形
  精靈，採奇數欄下移 12 像素排列；命中契約依已證實的 `sub_50FF5` 幾何，
  不另發明外觀六角多邊形。主畫面顯示的是單省 14×14 戰場，不是 39 省戰略
  地圖，因此保持只讀；證據見 `docs/playtest/38-pointer-m2-battlefield.md`。
- M3：戰鬥的可見「換部隊／攻擊／結束回合」按鈕與多目標選取。原版戰鬥
  七項選單尚未解完，新增控制必須標示重製差異，避免固化成原版結論。
- M4：Android 封裝、旋轉／背景恢復、不同密度與安全區驗證；觸控中斷不得
  重複送出動作。

Android 版預設以橫向遊玩作為規劃基準，但在技術驗證前不鎖定旋轉策略；
無論採用哪種封裝，鍵盤、滑鼠與觸控必須共用同一個動作識別碼。
Modern high 的地圖／戰鬥／流程卡與 3×4 keypad 由同一份 1280×720 layout 產生；
`internal/ui/mobile/viewport.go` 會依實際 density 擴大不可見命中區至至少 48 dp。
Android binding、背景恢復與實機量測仍不得由桌面測試代替。

## 驗收

- 每個動作都要有鍵盤與滑鼠／觸控兩條輸入測試，並比較遊戲狀態與存檔位元組。
- 測試命中區中央、四邊、四角、相鄰項目間隙、黑邊及縮放後座標。
- GUI 實機驗收至少涵蓋桌面滑鼠與 Android 觸控模擬；不得只靠單元測試宣稱完成。
- 原典用語／現代白話及原味／現代圖形切換後，動作識別碼與結果保持不變。
- 鍵盤焦點必須可見，且全流程不使用滑鼠或觸控仍可完成。

## 尚待決定

- Android 最低版本、封裝方式及橫向畫面策略。
- 長按是否僅作人物說明，或完全不使用長按。
- M0 是否與第一個 Android 技術驗證版同批交付。

## 高解析度 Modern 的座標前置條件（2026-08-11）

本文件的 640×350 座標契約仍是 retro 與目前 Modern shell 的基準；高解析度 Android
不直接把它乘上倍率。依 [`docs/design/33-high-resolution-modern-android.md`](33-high-resolution-modern-android.md)
已確認的 1280×720 設計畫布，`SurfaceToLogical` 目前先以 H0 橋接泛化為 design-surface
座標，並由同一份
Modern layout 產生繪製矩形與觸控命中矩形。48 dp、安全區、旋轉、背景恢復與官方
Android binding 的 cgo／NDK 邊界仍是 H2/H3 技術驗證項目；桌面單元測試不能替代實機
驗收。

2026-08-11 畫布 A 已確認為 1280×720。桌面 `F3` 是原版 640×350／高解析畫布的
快捷切換；沒有實體鍵盤的裝置可從「其他選項 → 解析度切換」選擇同一偏好。H0 目前
把既有 frame 安全等比放進高解析 Surface，並將點擊反算回 640×350；正式 Modern
高解析 layout／字型仍是 H1，不能把橋接畫面當成完成宣告。

H1-a 已先收斂地圖頁：`internal/ui/layout.ModernMapLayout` 同時提供 1280×720
地圖／資訊卡／「指令」／「新聞」矩形，`cmd/dsds` 在 Modern 高解析地圖頁直接以
設計座標命中；其他頁面仍使用 H0 的 Surface→640×350 反算。這是刻意的分頁式
fallback，不宣稱整個高解析輸入鏈已完成。
